# QLGL 开发规划

> 定位：**CSS+HTML 的"GTK"** —— 界面用 HTML/CSS 写，构建期编译成 C；绘制层 CPU/GPU 双后端；
> PC / 移动是第一平台，MCU 是第二平台；性能对标 LVGL，在小屏 CPU 光栅场景结构性轻于 GTK。
>
> 本文是**排期与验收依据**。每完成一个里程碑，必须同时更新 [bench.md](./bench.md) 与相关手册。

## 4. 里程碑

> 排序原则：**先让"能看见、能点、能写中文"，再谈性能极限，最后铺平台。**
> 每个里程碑独立可演示、可验收，不做"半年后再看效果"的大爆炸式交付。

### M1 · 交互闭环（约 2 周）—— **已完成（2026-11-08）**

**目标**：界面能点、能悬停、能响应键盘。

| 任务 | 说明 | 状态 |
|---|---|---|
| 输入抽象 | `QLInputEvent`（pointer down/up/move/wheel/leave、key down/up、字符输入）+ 64 深度静态环形队列 | ✅ |
| 后端对接 | X11（显示 + GL 共用 `qlinput_x11.h`）、Wayland（`wl_pointer`/`wl_keyboard`）、GL 窗口 | ✅ |
| 事件路由 | 命中测试 → 目标控件 → 冒泡到根；`stop_propagation` 有效 | ✅ |
| 回调 API | 用既有的 `ql_connect(obj, QL_WIDGET_EVENT_*, cb, user)`；12 个控件事件 | ✅ |
| 状态样式 | `:hover` / `:active` / `:focus` 在**构建期**编译成状态变体样式表 + 控件级 `state_bg` | ✅ |
| 验收 | `test/input/test_input.c`（130 项断言）、`example_input`（窗口 + `--demo` 自检）、`test_web_ui` 增补 13 项 | ✅ |

**实现要点**

- 输入层不认识控件树：后端只 `push`，主循环 `ql_input_dispatch()` 统一派发，
  因此**无窗口也能自动化测试**（`example_input --demo` 注入事件跑完整链路）；
- 状态位沿**父链**设置，和 CSS 的 `:hover` 作用到祖先一致；
- 按住拖动时事件仍发给按下目标（等价 DOM 隐式指针捕获），拖出控件再松手不会漏 UP；
- 点击合成：同目标 + 位移 ≤ 4px；
- 后端**不再**把 Esc 当关闭键，示例用 `ql_win_bind_esc()` 自己挂处理器。

**顺带修掉的真 bug**

1. `ql_object_set_parent` 头插 + 渲染正序遍历 → **最后挂上的控件画在最下面**，
   与 `qlwidget.h` 的承诺相反。改为追加到链尾（链表顺序 == 绘制顺序）。
2. `ql_ui_build` 用 `node_count` 给**样式下标**做越界检查，
   样式数一旦超过节点数就静默回落到 `styles[0]`。`QLUIDoc` 增加 `style_count`。

**未纳入 M1（已登记）**：Tab 遍历焦点、双击/长按、触摸、IME、DPR。

### M2 · 文本质量（约 3 周）—— **已完成（2026-11-08）**

**目标**：中文能看、任意字号、文本不再是 CPU 瓶颈。

| 任务 | 说明 | 状态 |
|---|---|---|
| 字体后端抽象 | `QLFontBackend` + 可选的 `glyph_bitmaps`，静态位图字体与动态字体共用读取接口 | ✅ |
| FreeType 接入 | `ql_font_ft_load(path, face, px)`；8bpp 灰度；TTC 自动挑简体字面 | ✅ |
| 字形缓存 | 有序数组 + 每字形独立位图；上限 2048，满则拒绝新字形并告警 | ✅ |
| 动态图集 | GPU 侧 1024² R8 货架分配 + `glTexSubImage2D` 增量上传 + `(字体,codepoint)` 哈希 | ✅ |
| 任意字号 | `ql_font_default(N)` + `font-size: Npx` 全部走字号表 | ✅ |
| 验收 | `test_font_ft`（40 项）、中文示例页（CPU 与 GPU 输出一致）、`example_gl_window` 中文渲染 | ✅ |

**实现要点**

- 三条绘制路径（画布 / QLDraw2D / GPU 图集）**都不区分字体类型**，
  只通过 `ql_font_glyph_row()` / `ql_font_glyph_alpha()` 取像素；
- 内置位图字体仍在启动时一次性拼进图集（一次 `glTexImage2D`），
  动态字形才走增量上传 —— 首帧耗时反而从 1230µs 降到 1065µs；
- MCU 可以直接关掉 `QLGL_BUILD_FREETYPE`，位图字体路径零依赖不变。

**顺带修掉的真 bug**

1. GPU 字形 UV 缓存用**字形数组下标**做键，而动态字体的缓存表插入后要保持
   按 codepoint 有序 —— 插入新字会把后面所有字形挪位，下标不稳定，
   症状是"部分文字被画成别的字"。改成按 `(字体, codepoint)` 做键。
2. 往 8bpp 图集搬 4bpp 位图时按 `box_w` 直接 memcpy，奇数宽度时
   `stride < box_w` 会读越界（ASan 报 global-buffer-overflow）。
   统一走 `fetch_glyph_row()`，非 8bpp 逐像素展开。
3. 生成器把字体字节写成数字数组 `{ 228, 184, 173 }`，`-Wconversion` 下报错；
   改成带八进制转义的字符串字面量。

**未纳入 M2（已登记）**：自动折行、字距/行高精调、HarfBuzz 整形、
字重/斜体合成、字形 LRU 淘汰。

### M3 · 布局表达力（约 4 周）—— **已完成（2026-11-08）**

**目标**：能表达真实页面，不再"只能堆 div + margin"。

| 任务 | 说明 | 状态 |
|---|---|---|
| flexbox | `display:flex`、`flex-direction`（含 reverse）、`justify-content`（6 值）、`align-items`、`flex-grow/shrink/basis`、`gap`、`flex-wrap` | ✅ |
| 定位 | `position: relative/absolute/fixed`、`top/right/bottom/left`、`z-index` | ✅ |
| 裁剪 | `overflow: hidden/auto`（裁剪 + 命中测试同步裁剪） | ✅ |
| 混合内容 | `<p>文字<b>粗</b>…</p>` —— **生成期**展开成匿名 inline 节点，运行期零改动 | ✅ |
| 验收 | `test_flex`（84 项几何断言，12 个用例页）；示例页改为真实 flex 布局；CPU/GPU 均验证 | ✅ |

**实现要点**

- flex 是"**测量 → 分配 → 定位**"三步；测量直接复用 `layout_node`（哑位置跑一遍），
  保证与 block/inline 路径的尺寸算法完全一致；
- 全程**零分配**：信息暂存在子节点的 `border_box` 里，需要汇总时再遍历链表；
- 最终尺寸写进 `style_copy`，复用既有的"运行期改写样式"机制；
- `z-index` 在布局末尾对子链表做**稳定排序**，之后绘制与命中测试自动一致；
- 混合内容在**生成期**消解成匿名 `<span>`，运行期数据模型不变。

**顺带修掉的真 bug**

1. `box-sizing: border-box` 时**显式高度**被当成内容高使用，导致所有这类元素
   被撑大一整个 `padding + border`（卡片高度 68 → 86）。宽度路径一直是对的，
   高度路径漏了换算。
2. `style_copy` 从不清除：flex 分配与绝对定位写进去的强制尺寸会**带到下一帧**，
   视口变窄时表现为"尺寸不更新"。改为每次 `ql_ui_layout` 开头重置。
3. `QLUILength.value` 是 `uint16_t`，`top: -6px` 变成 65530（badge 飞到 y=65741）。
   改成 `int16_t`。
4. 同一节点在一次布局里被 `layout_node` 调用两次（相对定位那段重复调用），
   已合并成一次。
5. 命中测试原来按"数组下标倒序"扫，`z-index` 排序后与绘制顺序脱节。
   改为与绘制同源的树遍历（子节点优先 + 后者覆盖 + overflow 裁剪）。

**未纳入 M3（已登记）**：滚动容器与滚动条、自动折行、`align-self`/`align-content`、
绝对定位的 "static position" 与完整 shrink-to-fit。

**第 0/1 步的验收（已全部通过）**

- `test_ui_blob`（63 项）：编码/解码往返、字段逐项相等、**重新编码的 blob 与原文逐字节相同**、
  加载后的 doc 渲染与静态 doc **逐像素相同**（差异 0/102400）、7 类损坏输入全部明确拒绝、
  与 `qlblob` 产物逐字节一致；
- 热重载实测：改 CSS → 重新生成 `.qlui` → 窗口更新，**应用二进制未重新编译**；
  新 blob 损坏时**保留旧界面**并打印原因。

**第 3 步的完成判据（先写下来，防止"差不多就行"）**

1. 同一份 HTML/CSS，构建期产物与提交的基准 blob **逐字节相同**；
2. **拒绝的输入集合相同**（含错误信息里的行列号），不只比成功的；
3. 解析器是全库唯一吃外部文本的地方，必须有界：嵌套深度、节点/样式/文本/字号上限
   全部进 `qlconfig.h`；
4. 可摘：不编译该编译单元则零字节成本，core 里零静态引用指向它。

**明确不做**：元素级 doc 混用（跨 doc 的 `uint16` 下标无法引用）；
混用单位锁死在**面板**（一个 `QLUIRoot` ↔ 一份 doc）。

**`--platform` 降级报告（与 M5.5 能力矩阵配套）**

同一份 HTML/CSS，两个目标各生成一份产物；MCU 侧不支持的效果**明确报告降级去往何处**，
而不是静默忽略（沿用"不静默降级"红线）：

```
$ qltext cc --html app.html --css app.css --platform mcu --out build/mcu
⚠ app.css:42   backdrop-filter: blur(8px)
               MCU 不支持 → 降级为 background-color: #ffffffcc（无模糊）
⚠ app.css:88   transform: rotateY(45deg)
               MCU 不支持 → 降级为 scaleX 假翻转
❌ app.css:120  filter: blur(4px)
               无等效替代 → 建议改用 9-slice 预烘焙阴影
qlui: 21 处降级，1 处无法降级
```

这样**一份源文件、两个平台**，能力差异由工具表达，不需要 `#ifdef` 满天飞。
（MCU 为第二平台，此任务在 PC 主线走通后再做。）

**实现过程中真正花时间的五个细节**（都写进《QLUIText阅读指南》）：

1. **样式表身份 = 排序后的 `(属性, 值)` 字符串集合**，不是编译后的结构体。
   否则"两个声明不同但编出来一样"的节点会被合并，样式表条数就不同了。
2. **简写必须在单条规则内展开**（`animation` / `transition` / `flex` / `gap` /
   `background` / `border`）——级联合并后再展开会覆盖后出现的长写。
3. **空文本池也要占一条**：构建期工具用 `text_ofs[] = { 0 }` 占位，于是
   `text_count == 1` 且池里是空串。
4. **Unicode 空白**：Python 的 `\s` 认 U+3000 等；示例文本里就有一个全角空格，
   漏掉它 blob 差 2 字节。
5. **`box-shadow` 的颜色提取顺序**必须是 `rgba()` → `#hex` → 第一段字母，
   顺序错了会把 `1px` 里的 `px` 当颜色。

顺带修掉一个真泄漏：`pnode_free` 只遍历 `items`，而 flatten 之后子节点在

### M5 · 逻辑坐标 / 高 DPI / 亚像素 —— **已完成（2026-11-08）**

**目标**：同一份 CSS 在 1x/1.25x/1.5x/2x/3x 屏上视觉一致；动画在 CPU 上也是连续的。

| 步骤 | 任务 | 状态 |
|---|---|---|
| M5.1 | **布局精度**：消灭"各自取整"导致的空隙 | ✅ 见下 |
| M5.2 | **DPR**：布局在 CSS px、光栅在设备 px；缩放只在后端入口乘一次 | ✅ 见下 |
| M5.3 | **绘制期亚像素**：`QLRectFx` + 面积覆盖率抗锯齿；`QLDraw2D` 绘制期偏移（GPU 顶点本来就是浮点，天然免费） | ✅ 见下 |
| 验收 | DPR=2 与 DPR=1 的截图缩放到同尺寸后像素差 < 3% | ✅ **0.57%** |

> **M5 结论**：DPR 与亚像素都只影响**绘制入口**，布局始终是 CSS px 整数运算，
> 所以上层代码一行没改。三条安全阀（M5.1 累计分配、M5.2 按边缩放、M5.3 对齐时逐字节不变）
> 保证了这些改动不会悄悄改变已有像素。

#### M5.1 的过程与结论（重要，改了这一节的原始设计）

原计划是"`ql_coord_t` 语义整体改成 26.6"。开工前先量了真实缺陷，结论是**要分两步走**：

1. **先修真正的病根**：flex / justify 的每一项都是"各自整除"，
   余数被直接丢掉。实测 `100px` 分三个 `flex:1` 得到 `33+33+33 = 99`，
   右边留 1px 空隙。这**不需要定点**，只要把分配改成**累计推进**：
   ```
   num += 总额 × 权重;   份额 = num / 权重和;   num %= 权重和;
   ```
   这样份额之和恒等于总额。改完实测 `33+34+33 = 100`，space-between 也精确落到行尾。
2. **再决定要不要 26.6**：查下来，"整数输入 + 整数输出"的布局里，
   26.6 的额外精度**只来自除法**，而除法已被第 1 步解决。
   其余精度损失来自**样式表本身的表示**（`QLUILength.value` 是 `int16` 整数 px / 整数百分比），
   要让 `33.33%` 或 `margin: 5.5px` 可表达就必须改 `QLUIStyle` → **改 blob 格式**，
   那是另一件事。
   而 `border_box` 是 `QLRect`（设备像素整数），
   光栅化的落点本来就是整像素——**26.6 在这里体现不出任何视觉差别**。

**所以 `ql_coord_t` 全局改 26.6 撤出 M5.1**，改到 M5.3 与"边缘覆盖率 AA"一起做：
只有光栅化肯吃小数，定点才有意义。这样也避开了 424 处调用点的无收益风险。

> 剩下真正受益于 26.6 的地方只有两处，都记在 M5.3：
> ① 光栅化落点（边缘覆盖率）；② 字形前进宽（FreeType 给的就是 26.6，
> 现在被 `adv_w = (slot->advance.x + 32) >> 6` 取整，长行会累计漂移，
> 居中/右对齐会偏几个像素）。

**M5.1 的验收**：`test_flex` 新增第 12 组用例（`test/web/flex/frac.*`）：
100px÷3 的边界、space-between 的末项贴边、shrink 后无空隙，共 14 项断言。
原有 84 项全部保持通过（说明累计分配只改"除不尽"的情形）。

#### M5.2 的设计：缩放只在一处发生

**单位三层，各管一段**：

| 层 | 单位 | 谁负责换算 |
|---|---|---|
| 布局 / qlui / 控件 / 自定义绘制 | **CSS px** | 不换算，始终是 CSS px |
| `QLDraw2D` 后端入口（CPU 与 GL） | 设备像素 | **唯一**的换算点 |
| 驱动 `flush(area)` / 清屏 | 设备像素 | `ql_render()` 各自换一次 |

缩放系数是 26.6 定点（`QL_SCALE_ONE` = 1.0，96 = 1.5），挂在"表面"上：
`QLDispDriver.scale_fx` → `QLCanvas.scale_fx` → `QLDraw2D.scale_fx`，
GL 侧是 `QLGfxGL.scale_fx`。上层代码**一行都不用改**——这就是选这个设计的原因。

两条容易写错的地方：

1. **矩形必须按"边"缩放**（`ql_scale_rect` 用 `ql_rect_right` 算同一条边界），
   不能 `x*scale + w*scale`：相邻矩形各自算宽度会在接缝处裂开或重叠 1px。
   （和 M5.1 的累计分配是同一个道理。）
2. **文本要按设备字号重新取字体**（`ql_draw2d_device_font`）：DPR>1 时
   `ql_font_default(css_px * scale)`，否则字形会被拉伸糊掉。只有动态字体能真正
   重取；位图字体在 MCU 上不缩放（固有限制）。

**顺手修掉一个 GPU 的真 bug（重要）**

写 DPR 测试时发现 GPU 后端和 CPU 差 28%，查下来是：本后端是**单批次**
（整帧一次 `glDrawArrays`），注释里写着"顶点已按最终 clip 画好"，
但 `emit_quad` / `emit_quad_gradient` / `emit_shadow` **从来没做这个裁剪**，
`g->clip` 只是存着。结果是 **`overflow:hidden` 在 GPU 上完全没生效**——
测试页里那个 120×70 的子节点整块画了出来，正好多出 5422 像素。

修法：发顶点前把四边形范围与 `g->clip` 求交（`clip_quad`），
但**形状参数（`hx/hy`、radius、border、渐变跨度）必须继续用未裁剪的矩形**，
否则片元里的 SDF 会算错——被裁掉的只是光栅化范围。
纹理四边形（字形）裁剪后按顶点位置线性插值重算 UV（图集 UV 是轴对齐的，插值精确）。

结果：CPU vs GL 从 **28.24% → 0.77%**（scale=1）/ **27.87% → 0.40%**（scale=2），
仍是**单 draw call**。

**M5.2 的验收**：`test/web/test_dpr.c`（22 项）：
1. 布局与 DPR 无关（两种 DPR 下 `border_box` 逐字段相同）；
2. `scale=2` 渲染后 2×2 盒式降采样 vs `scale=1`：**0.57%** 像素超差（门槛 3%）；
3. GPU 与 CPU 在 `scale=2` 下：**0.40%**；
4. `ql_scale_rect` 按边缩放：1.5× 下相邻矩形边界相接、设备→CSS 往返不丢像素。

#### M5.3 的设计：先把"能画在半个像素上"做出来

动画的"顺滑"本质是**矩形边落在非整像素上也能画**，所以这一步只加光栅化原语：

```c
typedef struct { ql_coord_t x, y, w, h; } QLRectFx;   /* 设备像素 26.6 */

void ql_canvas_fill_rect_fx(...);        /* 面积覆盖率 AA */
void ql_canvas_fill_round_rect_fx(...);
void ql_canvas_stroke_rect_fx(...);
```

配一个**绘制期平移**，这就是动画的落点：

```c
ql_draw2d_set_offset(d2d, x_css_26_6, y_css_26_6);   /* translate(0.5px) → 32 */
```

- CPU：把矩形转成 `QLRectFx` 走覆盖率填充；
- GPU：**直接加进顶点浮点**（本来就免费，且是精确的，比 CPU 更准）；
- **不影响布局**（与 CSS `transform` 语义一致）→ 滑动/缩放动画零重排；
- 文本与阴影只吃偏移的整数部分（亚像素会让字形糊；阴影本来就软）。

三个关键实现选择，都是为了"不引入跳变"：

1. **圆角跨度复用整数版 `round_row_span`**，再把整像素跨度平移亚像素余量。
   一开始用中心采样（直接算 SDF），结果圆角比整数版**大将近 2px**——
   动画跨过 0 时拐角会"突然胀一圈"。改用整数跨度后，对齐时**逐字节相同**。
2. **整数矩形 = 低 6 位全 0 的 fx 矩形**，覆盖率恰好全满 → 与整数路径**逐像素相同**。
   这就是本次改造的安全阀（`test_subpx` 用 5 种矩形 × 4 种半径 × 3 种 alpha 对照）。
3. **每行只在两端各多一次 `put_px`**，中间整像素仍走 `fill_row` 的 SIMD 快路径，
   所以亚像素不是"全逐像素"的代价。

**缓动曲线能看到几个台阶**（12px 的矩形从 0 移到 1px）：

| 实现 | 一个像素内的不同落点 |
|---|---|
| 整像素 | 1 个（直接跳过去） |
| 26.6 亚像素 | **64 个**（`test_subpx` 抽查 6 个偏移得到 6 个不同边缘值） |

#### M5.3 的验收：`test/draw/test_subpx.c`（23 项）

1. **对齐时逐字节不变**：5 种矩形 × 4 种半径 × 3 种 alpha 的填充与描边，
   fx 版与整数版**逐像素相同**；
2. **覆盖率按面积**：0.5px 偏移的首尾像素各 50%，一行内覆盖率之和 = 真实宽度
   （10px → 2550 ± 6）；
3. **1px 偏移退化成纯平移**：整幅图与"矩形右移 1px"逐像素相同；
4. **一个像素内有多个台阶**：6 个不同偏移得到 ≥5 个不同边缘值；
5. **GPU 吃同一个偏移**：亚像素偏移下 CPU vs GPU **1.62%**（门槛 2%，差异全在圆角 AA）。

##### ③ `@keyframes` —— **已完成**

关键帧在**构建期编译成静态表**，运行期零解析、零分配：

   不需要为每个元素生成一份帧表。

##### ④ transform —— **`translate` 已完成；`scale`/`rotate` 待做**

`transform` 是**绘制期属性**（与 CSS 一致），所以移动元素**零重排**：

| 关注点 | 做法 |
|---|---|
| 绘制 | `render_node` 把 `transform` 加到 `QLDraw2D` 的偏移上，**逐层累加**（子树跟着走，等价于 CSS 的"transform 建立包含块"）；GPU 侧同一个字段直接进顶点，零额外成本 |
| 布局 | 完全不参与。`border_box` / flex 计算里没有它的影子 |
| 命中测试 | `hit_walk_ui` 逐层累加平移，把屏幕坐标映射回节点的布局空间；用**生效样式**（动画中的值），所以移动中的元素也点得中 |
| 脏区 | 这是唯一需要小心的地方：`paint_box` 必须覆盖"旧位置 ∪ 新位置"。布局末尾自上而下算出每个节点的**绝对平移**（`tf_abs_*`）与**动画位移区间**（`tf_dev_*`），`paint_box` 取 Minkowski 包围盒——只膨胀不收缩，所以脏区偏大一点但绝不漏画 |

支持范围（**明确报错**而非降级）：

```css
.card { transform: translate(-40px, 0); }   /* ✅ */
.card { transform: translateX(8px); }       /* ✅ */
.card { transform: none; }                  /* ✅ */
.card { transform: scale(1.2); }            /* ❌ 报错：非轴对齐光栅化，M5.5 ④ 后续 */
.card { transform: rotate(30deg); }         /* ❌ 报错 */
```

`@keyframes` 里也能写 `transform: translate(...)`（通道位 `QL_UI_KF_MOVE`），
于是"滑入/滑出"这类最常见的入场动效已经能做了。
`transition-property: transform` 当时还报错（过渡的 4 个 float 通道已排满，扩通道要改 `qlanim`），
后来在 ⑧ 之后补上了——过渡槽改成"三份样式 + 一个进度"后，通道数不再受 `QLAnimValue` 限制。

**另一处顺手修掉的坑**：关键帧只写 `background-color` 时，alpha 原来取自**基础样式**
（透明元素永远动不出一块底色）。CSS 里 `background-color` 是**带 alpha 的颜色**，
所以现在 alpha 跟着背景色通道一起插值（显式写了 `opacity` 时才由它说了算）。

**验收**：`test_keyframes` 扩到 118 项，新增静态 `transform`、动画平移的逐帧值、
命中测试在平移前后都正确、`paint_box` 覆盖滑入起点、**像素级**断言
"平移后的位置有内容、原位只剩父背景"。

##### ⑦ 完成：`clip-path: circle()` 子树圆形遮罩 —— **已完成**

语义：`clip-path: circle(<百分比>)`，圆心固定在元素中心，百分比是**最远角距离的千分比**
（0% = 全裁，100% = 完全覆盖）。用千分比而不是 px 是因为揭示动画要走完整个过程——
px 半径会在动画早期就把元素盖满，剩下 90% 的时长"看起来没动"。

**关键设计：在像素汇点上做遮罩，而不是为每个原语各写一遍。**

| 后端 | 做法 | 为什么这样最省 |
|---|---|---|
| CPU | `fill_row` 把每行跨度与圆的水平范围求交（每行一次 `sqrt`），内层仍走 SIMD 快路径，两端各留一个像素给覆盖率；单像素走 `put_px`，alpha 乘圆覆盖率 | `fill_row` / `put_px` 是全部图元（填充/圆角/渐变/阴影/字形）的**共同汇点**，只改 2 个函数就自动全覆盖 |
| GPU | 新增顶点属性 `a_mask`（设备像素的 cx, cy, r），在 `emit_vertex`（唯一出口）统一填；片元里 `cov *= 1 - smoothstep(-0.5,0.5,length(gl_FragCoord-中心)-r)` | 所有 `emit_*` 都从 `emit_vertex` 出去，同样一处改动全覆盖；`gl_FragCoord` 要按 `u_viewport.y` 翻一次（GL 原点在左下） |

顶点因此从 64 B 涨到 **80 B**（65536 顶点 ≈ 5.2 MB 静态），换来"遮罩对任何图元成立"。

**约定："关闭"必须是 -1，不能是 0。** 0 的语义是"遮罩存在但半径 0 = 全裁掉"，
这正是揭示动画的第一帧。这条约定踩了三次坑：
1. `memset` 出来的 `QLCanvas`/`QLDraw2D` 是 0 → 默认变成"全裁" → 整屏全黑；
2. GPU 侧只重置了 `g->mask_r` 没重置 `g->draw.mask_r`，`render_node` 收尾恢复时
   用 0 又把遮罩打开了 → 除第一个节点外全部消失；
3. 顶点属性 `a_mask` 只写了 `glDisableVertexAttribArray(6)` 却忘了
   `glVertexAttribPointer(6, ...)`，未绑定的属性默认值是 `(0,0,0,1)` → `mr=0` → 全黑。

**已知限制（刻意保留并告警）**：只支持一层遮罩。嵌套 `clip-path` 的 CSS 语义是
"取交集"，而两个圆盘的交集不是圆盘，所以运行期保留外层并 `QL_LOGW`。

**验收**：`test_clip` 30 项——0% 零墨迹、100% 完全恢复、50% 圆内/圆外分明、
**子元素伸出父盒子的部分被一起裁掉**（这是"子树遮罩"与"只裁自己背景"的关键区别）、
遮罩 50% 时 CPU vs GPU 差 **0.26%**。

##### ④ 完成：`transform: scale()` —— **已完成**

只做**等比**缩放（绕元素中心）。非等比会让圆角/描边/字形的语义变得没有定义，
`rotate`/`skew`/`matrix`/3d 需要非轴对齐光栅化，全部构建期报错。

**关键洞察：等比缩放一个轴对齐矩形，还是轴对齐矩形。** 于是 CPU 侧完全不用碰光栅化本身——
两个入口助手 `sx()`（矩形）与 `sl()`（长度）把元素缩放折进去就行，所有图元自动受益：

```
sx(rect) : 先绕中心按边缩放 → 再乘 DPR
sl(len)  : 先按元素缩放 → 再乘 DPR
```

GPU 侧同理：`gsx()` / `gsl()` 里同样两步，顶点数/draw call 不变。

四条配套改动：

| 位置 | 做法 |
|---|---|
| 文本 | 字形按"元素缩放 × DPR"**重新取字号**（`ql_draw2d_device_font(font, font_fx)`），与浏览器一致：`transform: scale()` 会让文字一起变大且清晰。只缩位置不换字号会让字又小又错位 |
| `paint_box` | 放大时按 scale 撑开（缩小时保持原范围），只膨胀不收缩 |
| 命中测试 | 把屏幕坐标**逆缩放**回布局空间（缩放中心要跟着平移量一起算），自身命中时把 box 按 scale 撑开 |
| 通道 | `transform` 通道（`QL_UI_KF_MOVE`）现在同时携带 `tf_x/tf_y/sc`；`QLUIStyle` 加 `sc`（千分比）、`QLUIKeyframe` 32 B、blob version 7 → **8** |

**验收**：`test_scale` 21 项——布局尺寸与 scale 无关、视觉宽度 40→60px、绕中心、
命中测试在放大后的位置、关键帧插值（200ms 时 1250）、**CPU vs GPU 0.00%**。
`test_qlui_errors` 28 项（新增 `scale(1.2, 2)` / `rotate()` / `matrix()` 必须报错）。

##### ⑧ 完成：`scaleX()`/`scaleY()` 假 3D 翻转 —— **已完成**

真 3D 要透视矩阵、深度排序、背面剔除——独立技术路线。而"卡片翻面"只需要
`scaleX: 1 → 0 → 1`。**关键判断：轴对齐矩形在轴对齐缩放下仍是轴对齐矩形**，
所以 CPU 行跨度扫描一行都不用改，只把 `elem_fx` 拆成 `elem_x_fx`/`elem_y_fx`。

代价是三个歧义，全部按 `min(sx, sy)` 近似并在文档里写明：圆角、描边/阴影、字号。
字形**不做横向挤压**——`scaleX(0.7)` 时文字高度也会变成 0.7 倍；翻转动画中途宽度趋 0，
察觉不到；真要逐像素压扁得给字形位图加重采样（MCU 上不可能）。

| 项 | 做法 |
|---|---|
| 样式 | `QLUIStyle.sc` → `sc_x` + `sc_y`（`int16_t`），**112 → 116 字节**，blob version 8 → **9** |
| 关键帧 | `QLUIKeyframe.sc` → `sc_x` + `sc_y`，**32 → 36 字节**（`-1` = 用基础值，**`0` 是合法值**） |
| 绘制后端 | `QLDraw2D.elem_fx` → `elem_x_fx`/`elem_y_fx`，新增 `ql_draw2d_set_elem_scale_xy()`；`sl()` 用 `min` |
| 文本 | 压到 0 宽时**一个字都不画**（否则几十个字形叠成一条墨线） |
| 命中 | 从"`sc > 1000` 就撑大命中盒"的近似，改成**精确逆缩放**（`hx = cx + (x-cx)*1000/sc_x`）；`sc == 0` 直接 `return NULL` |
| `backface-visibility` | **构建期报错**——假翻转没有背面，没有"背面朝后不画"这回事 |
| `animation-delay` | 顺手补上（`QLUIAnimation.delay_ms` + `QLUIAnimRun.phase`）：错开相位才能做出"两张脸" |

**踩到的 bug**：`ql_draw2d_set_elem_scale_xy()` 的钳位写成 `fx > 0`，把合法的
`scaleX(0)` 悄悄变成 `1.0`——翻转动画在中点闪一下满宽。改成 `fx >= 0`。
另一个：延迟判断写成 `phase == 0 && elapsed < delay`，第二天 tick 起 `phase` 已是 1，
直接掉进 `elapsed -= delay` 的**无符号下溢**，延迟中的元素被算成天文数字。

##### M5.5 效果总览窗口 + 一个 GPU 遮罩 bug —— **已完成**

`test/web/flex/showcase.*` + `example_showcase_window`：六个格子把 M5.5 的全部能力

##### ⑬ 字体变体与装饰线（B2）—— **已完成（2026-11-08）**

就只是"高级 `span`"。这一步把变体补上，全部**合成**，不加载第二个字体文件
（MCU 上也不可能）。

| 效果 | CPU | GPU | 备注 |
|---|---|---|---|
| 加粗 | `glyph_blit()` 跑两遍，第二遍右移 1px | 同一个 quad 发两遍，`x+1` | 墨迹约 +60% 面积 |

##### ⑭ 滚动容器（C1）—— **已完成（2026-11-08）**

`overflow: hidden` 之前只裁不滚，等于"能藏不能看"。这一步把 `auto` 补成真的能滚。

**最关键的决策：滚动偏移烘进布局，不在绘制时加。**

```
ql_ui_scroll_by() → node->scroll_y → ql_ui_layout() → translate_subtree(子节点, -scroll)
```

理由：绘制、命中测试、`paint_box`、脏区读的都是 `node->border_box`。坐标对了，
四件事自动一致。不然就要维护"绘制加了偏移、命中忘了加"这类四份不同步的正确性 ——
那是最难查的一类 bug。代价是滚动时重排一次：211 节点 **0.037 ms**，60fps 预算 16.6 ms。

| 能力 | 做法 |
|---|---|
| 滚轮 | 命中 → 往上找最近可滚祖先 → `scroll_by(dx, dy)` |
| 拖滚动条 | 右侧 10px 热区；位移按"可拖动行程 / 可滚动范围"换算；**不算点击** |
| PageUp/PageDown/Home/End | 作用于焦点节点所在的可滚容器 |
| 滚动条 | 覆盖式 4px 滑块（中灰 60% alpha），不占布局；`hidden` 永远不画 |
| 夹紧 | 范围变化时自动夹回 `[0, max]`，不会卡在越界位置 |

**`scroll_to` 不重排、`scroll_by` 重排**：前者是设状态（连设多次只该排一次），
后者是执行一次操作（用户滚一下就该看到）。

坑：拖滚动条若先走 `set_state_chain(ACTIVE)`，整个列表会闪一下 `:active` 样式；
所以 `pointer_down` 必须先判滚动条热区并直接接管。

验收：`test_scroll`（46 项）—— auto/hidden 分工、滚轮方向、夹紧、`scroll_by` 标脏
（顶到头不白重绘）、命中测试跟着滚、横向滚动、拖滚动条不算点击、无溢出时不画滚动条、
嵌套时滚最近的可滚祖先。

例程：`example/09_scroll.c`（播放列表，滚轮/拖滚动条/PageDown）；教程第 9 章。

**已知缺口**：没有滚动惯性（触屏会"硬"）；滚轮滚到底**不传给父级**（浏览器是链式滚动）。

##### ⑱ 图像管线（`<img>`）—— **设计定案（2026-11-09）**

完整设计见 [图像管线设计](./图像管线设计.md)。三条与"调库还是自己写"直接相关的决定：

1. **自有解码器只做 BMP / QOI / PNG**。PNG 的难点只有 DEFLATE 一处，而它是无状态
   纯算法（32KB 固定窗口、输出直接喂反滤波），可完全有界、可 fuzz；JPEG 是"一整套
   色彩管线"，手写的失败模式是**色偏**而不是崩溃 —— 收益/风险完全不划算。
2. **不分平台，只分开关（Linux Kconfig 那套）**：每个能力一个宏、互不互斥、组合都合法。
   `QL_FEAT_IMG_BMP/QOI/PNG` 各自可裁，`QL_FEAT_IMG_PLATFORM`（JPEG/GIF）想编就编、想砍就砍，
   砍掉后遇到该格式明确报 `QL_ERR_UNSUPPORTED`。"PC 配置 / MCU 配置"只是**预设**
   （`full` / `lean` / `raw-only`），起手不同，随时可单品覆盖。
   零解码路径（构建期转出 `RAW`，`px` 直指 `.rodata`、`owned=0`）是任何平台都可选的一档，
   PC 上用它同样划算：换"启动零解码 + 像素完全确定"。
3. **stb_image 不进产线**（7k 行不可裁、整幅 malloc、顺带扩大攻击面），只当测试对拍。

其余要点：`node->text` 复用为资源名（不加节点字段）；`w/h` 存进 doc，所以**布局不依赖
解码**；`object-fit` 在绘制期算、不动布局；`blend` 与现有 `fill_rect(alpha)` 同一套；
MCU 的推荐姿势是 **`RAW` + 指向 Flash**（`owned=0`，RAM 为 0）。

分期：**P3a ✅ 基础设施（3–4 天）** → **P3f ✅ 工具链（1.5–2 天）** → **P3b ✅ BMP/QOI（1 天）** → P3b BMP/QOI（1 天）→
P3d `object-fit`（1 天）→ P3c PNG（3–4 天）→ P3e 热区（0.5 天）→ P3g 平台后端（1 天），
合计 12–15 天。P3a + P3f 就打通"图片文件 → 构建期转码 → 固件里显示"这条**必达路径**。

**P3a（已完成）**：`QLImage` + `QLDraw2D->blit_image`（CPU 最近邻 + **GPU 纹理**，四种像素格式矩阵）+
`<img>` 标签 + doc 图像资源段（blob **v13**，头 72 → 84 字节）+ 布局固有尺寸。

三个实现要点：
1. **`node->text` 存资源名**（不加节点字段），所以所有"按文本测量/绘制"的地方都要走
   `has_shown_text()` —— 漏一处就会把 "logo.png" 当成正文画在图上（**这个 bug 真踩了**）。
2. **布局只看 doc 里的 `w/h`**，不看解码是否成功：图没注册也占对位置。
   CSS 给了宽度、高度 auto 时按宽高比推（整数运算 `h = w*ih/iw`）。
3. **有界校验前置**：`ql_image_validate()` 用"先除后乘"挡溢出，`stride` 必须装得下
   `w*bpp` 且是 uint16，`len == stride*h`；进绘制层之前必过。

**GPU 侧**：图片单独成批（整帧顶点共用一个纹理，图片是另一张），纹理按
`(px,w,h,format)` 缓存；滤波必须与 CPU 一致（默认 `GL_NEAREST`，否则半透明边缘被插成
渐变，比对差 3.4%）。两个坑：① `RGB565` 的内部格式必须是 **`GL_RGB565`**，配
`GL_RGB8` 会 INVALID_OPERATION → 纹理没数据 → **图片整块消失**（不是变色，特别难查）；
② 采样器必须绑东西，否则采样值未定义。验收：`test_gl_vs_cpu` 新增两张图的一页，
CPU vs GPU 逐像素差异 **0.00%**。

开关骨架一起落地：`QL_FEAT_UI_IMAGE` / `QL_FEAT_IMG_BMP|QOI|PNG|INFLATE|PLATFORM` +
CMake `QLGL_IMG_PRESET=full|lean|raw-only`（已验过 `raw-only` 构建）。

**P3b + P3f（已完成）**：BMP / QOI 解码器 + 构建期转码。

- **BMP**：24/32 位真彩、8 位调色板、`BITFIELDS`（565/888）、自上/自下、行长补齐 4 字节；
  **不解** RLE（明确 `UNSUPPORTED`，这是"明确失败"而不是缺功能）。
- **QOI**：六种 op 全实现。踩了个坑：判断"是不是 RUN"写成 `(op & 0xC0) != 0xC0`
  **会把 0xFE/0xFF（RGB/RGBA）整块吞掉** —— 高两位同样是 11。改成先解析 op、
  再按 `run` 计数写像素。
- **工具**：`qltext cc/blob --root`，与 doc 一起产出（一个界面一份 .c / 一份 .qlui）。
  `--pixel-format` 决定产物像素格式（构建期定型，运行时零转换），`--scale N` 面积平均缩小。
  解码复用库里的 `ql_image_decode`，所以**构建期与运行时不可能漂移**。
- **枚举零值坑**：`QLImageFormat` 原来 `RGB565 = 0`，于是
  "`out_format` 没填（memset 成 0）"被当成"要 RGB565"。把 **RGBA8888 挪到 0**，
  "默认 RGBA8888"就成了自然行为。教训：**带"默认值"语义的枚举，0 留给默认项**。

验收：`test_image` 96 项（BMP 两种输出格式、QOI 含截断、doc 资源段编码→加载→出图）；

##### ⑫ 标签集与 UA 默认样式 —— **已完成（2026-11-08）**

标签在这套架构里只影响三件事：UA 默认样式、`tag` 选择器、调试名。布局与绘制只看
编译出来的 `QLUIStyle`，所以加标签的边际成本几乎为零 —— 真正的问题一直是"不够用"。

**10 → 32 个**：容器 11（`header/footer/nav/main/article/aside/figure/figcaption/blockquote`
+ 原有 `div/section`）、标题 6、文本块 `p`、行内 8（`span/b/i/em/strong/u/s/mark`）、
列表 3（`ul/ol/li`）、空元素 2（`hr/br`）、控件 `button`。

| 决策 | 做法 |
|---|---|
| 三张表要同步 | `QLUITag`（qlui.h）/ `k_tags[]`（解析）/ `s_tag_names[]`（查询）顺序必须一致，**只能末尾追加**（`node.tag` 存进 blob） |
| UA 默认值 | 只给"看结构就该知道"的：块/行内、标题字号、列表缩进、`hr` 的 1px 线、`mark` 的高亮。**不追求与 Chrome 逐像素一致** |
| `<br>` | 做成"高度 0 的块"：块级自然结束当前行内行 = 换行。没有生成内容，也不想在文本节点里塞 `\n` |
| `<hr>` | 块级 + `height: 1px` + **显式背景色**（不给就是黑的，这个坑很多库踩） |
| 空元素 | `br/hr` 不压栈；给它们补结束标签（`</br>`）**明确报错** |
| 不画列表符号 | 没有 `::marker`/`::before`，标记自己写字符（文档里写清楚） |
| `em/strong/u/s` 目前与 `span` 等价 | 加粗/斜体/下划线需要字体变体（合成加粗、合成斜体、装饰线），是下一步 |

**顺手修掉一个真 bug（行内空白）**：`<mark>a</mark> <em>b</em>` 渲染成 `ab`。
解析期把所有"只有空白"的文本段一律丢掉，于是行内元素之间的空格没了。
现在按 CSS 的规则分情况：

| 情况 | 做法 |
|---|---|
| 两个**行内**元素之间的空白 | 保留成一个空格 `span` |
| 两个**块级**元素之间的空白 | 丢掉（否则每个缩进都变成一行） |
| 行首/行尾 | 丢掉 |
| flex 容器里只含空白的项 | `ql_ui_build` 时换成一份**共享的隐藏样式**（`display:none`），零额外内存 |

判断用的是标签的**默认** display（级联还没跑），已在文档里注明这个限制。
两个细节：① 不能用 `first_text/last_text` 判"行首行尾"——`<em>a</em> <strong>b</strong>`
里那段空格恰好是最后一个文本段，但它夹在两个元素中间；② 保留空格会让
`ui_demo.html` 多 2 个节点（24 → 26），测试里的节点数断言已更新。

验收：`test_html_tags`（216 项）—— 32 个标签逐个解析并核对 tag 值与名字、标题六级字号递减、

`ul/li` 缩进、行内空白保留 / 块级空白丢弃 / flex 里不产生项、`tag` 选择器、三类报错文案。

##### ⑪ 自动折行 `white-space: normal` —— **已完成（2026-11-08）**

有了 `line-height` 打底，多行文本只剩"按宽度断行 + 行数决定高度"两件事。

| 决策 | 选择 | 理由 |
|---|---|---|
| 默认值 | **`nowrap`**（浏览器是 `normal`） | v0 文本模型是"一段文本一行"，27 页逐像素基准都建立在这上面；默认改成 `normal` 会让已有界面在你没改任何东西时重排。折行显式打开 |
| 断行实现 | `ql_text_wrap()` 一个函数，布局与绘制都调它 | "布局按一行算、绘制画三行"这类 bug 只能靠共用一份断行来杜绝 |
| 宽度的写法 | 空格**照算**宽度，断行后再 trim 尾随空白 | 第一版把空格当零宽，含空格的英文行实际 120px 被判成放得下，折行直接失效 |
| 行数上限 | 绘制时栈上 `QL_CFG_TEXT_MAX_LINES`（64）条记录 | 不 malloc；**行数统计不受此限**，否则长文本高度算少 |
| 结构体 | `uint8_t white_space` 塞进 padding，**仍是 120 字节** | blob v11 不变（旧 blob 该字节为 0 = nowrap，行为与旧版一致） |
| 不支持 | `pre` / `pre-wrap` / `break-spaces` / `text-overflow: ellipsis` | 要保留空白与制表符语义，本库不做；写了报错不降级 |

**顺带修掉一个真 bug（分轴）**：`max_content_main()` 给 flex 项算 max-content 主轴
尺寸时，对文本节点**一律返回文本宽度**。可 `flex-direction: column` 时主轴是竖直，
max-content 应该是高度（行数 × 行高）。后果：46 个汉字的简介在 column 容器里声称
自己 **322px 高**，整页被撑爆、折行高度也算不出来（写 `example/07_player` 时撞上）。
现在按 `row ? 文本宽度 : 行数 × 行高` 分轴，折行时行数用父容器给的可用宽度估。

验收：`test_text_wrap`（59 项）—— 英文按词断且每行不超宽、CJK 随处断、超长单词硬断、
`'\n'` 叠加折行、默认 nowrap 高度 = 1 行、`normal` 高度随行数增长、绘制真的画出多行、
继承、column flex 回归（高度 = 行数 × 行高且等于容器高）、三类非法值报错。

例程：`example/07_player.c` —— 一个真实的播放器界面（渐变封面 / 进度条 / 折行简介 /
`line-height` 居中的按钮），顺带当"这套子集够不够写真实界面"的靶子。

##### ⑩ `line-height` —— **已完成（2026-11-08）**

写 `example/03_layout` 时暴露的真实缺口：`height: 26px; text-align: center` 的按钮，
文字水平居中但**贴着内容盒顶部**。查下来引擎是对的（CSS 块布局本来就这样，
浏览器也一样），错的是**库里根本没有表达"垂直居中"的手段** —— `text-align` 的
竖直 counterpart 就是 `line-height`。

于是补上：`QLUIStyle.line_h`（`int16_t`，0 = `normal`），`QLUIStyle` **116 → 120 字节**，
blob v10 → **v11**。

| 关键点 | 做法 |
|---|---|
| 半行距 | `(line_h - (ascent + descent)) / 2`，第一行基线 = `box.y + 半行距 + ascent` |
| 默认零变化 | `line_h == 0` 时半行距恒为 0，与旧版**逐像素相同**（27 页基准图未动，只有 blob 变了） |
| 三种写法 | `normal` / `<N>px` / 无单位倍数（按 `font-size` 折算成 px） |
| 继承 | 进 `k_inherited`，与 `font-size` 同等待遇 |
| 排版入口 | 只有一个（`ql_draw2d_text_layout`），CPU/GPU 共用，所以 `draw_text` 多了一个 `line_h` 参数 |
| auto 高度 | 文本节点的内容高用 `line_h` 撑开，不再固定用字体行高 |

验收：新增 `test_line_height`（21 项，**按渲染出来的墨迹包围盒**判断，不看结构体）——
`line-height == height` 时墨迹中心与盒中心重合（2 倍值相等）；不给值时墨迹贴顶；
`2` 与 `40px` 在同字号下墨迹中心完全一致；负例（`1.5em` / `0` / `40000px` / `auto`）全部明确报错。

顺带把 4 个例程的按钮/胶囊都补上 `line-height: <box 高度>px` —— 截图里那些
"字浮在上面"的地方一次性对齐。

##### ⑨ 毛玻璃 `backdrop-filter: blur()` —— **已完成**

唯一会"回头读自己画过的东西"的效果。数据侧几乎零成本：`QLUIStyle` 加一个
`uint8_t backdrop_blur`（塞进原 padding，**116 字节不变**，blob v9 → v10）；
`render_node` 里在"画自己的背景之前"插一句调用。

| 后端 | 做法 | 代价（实测） |
|---|---|---|
| CPU | 画布就地模糊：取区域 → **两趟 H/V 滑动窗口盒式卷积**（每像素 O(1)）→ 写回 | 108×56 卡片 **0.159 ms**；300×200 **1.68 ms**（整屏重绘是 0.304 ms） |
| GPU | **中途 flush 一次批次** → `glBlitFramebuffer` 降到半分辨率 → H/V 两趟 9 抽头 → `mode 4` 画回 | 额外 **1 个 draw call**、6 个顶点、两块半分辨率 RGBA8 |

**这一步打破了"单批次"这条性能红线**，所以把提交动作抽成 `flush_batch(g)`：
正常帧仍然只被 `end()` 调一次（行为完全不变），毛玻璃自己先 flush 再继续摞顶点。

GPU 侧三个"错了就整块黑"的坑（都写进 `QLRender阅读指南` §15）：
`u_bg` 采样器没绑东西 = 未定义值；忘了还原 FBO/视口 = 后续全画进半分辨率缓冲；
纹理上下颠倒 = 玻璃里出现倒影。

**两条后端故意不一致**：CPU 全分辨率盒式、GPU 半分辨率高斯近似 →
`test_blur` 不比逐像素，只断言性质：玻璃内出现一长串"中间色"（硬边摊开了）、
玻璃外一个中间色都没有（模糊不外溢）、半透明玻璃自己叠在模糊结果上。
实测 CPU 13 个中间色像素 / GPU 7 个。

`example_showcase_window` 底排加了一条滑动的毛玻璃（12px）压在一排带数字的色块上，
数字被糊开是"糊"最直观的证据。

**顺带修掉两个真 bug**（都是"窗口很卡"排查出来的）：

| bug | 表现 | 修法 |
|---|---|---|
| `ql_font_default()` 的字号缓存只有 **8 个槽**，满了以后"造一个不缓存的新字体" | 缩放动画每帧重载 TTF + 重光栅化：**8.077 ms/帧**（0.567 → 修好后 0.570），并泄漏 | 槽位 8 → 32，满了**轮转淘汰并销毁**最老的一个 |
| `(ql_coord_t)s->tf_x << QL_FX_SHIFT` | `tf_x` 为负时**左移负数是 UB**（UBSan 报 `left shift of negative value -32`） | 改成乘以 `QL_FX_ONE` |

`example_showcase_window` 也改成**每帧整屏重绘 + 60fps 上限**：毛玻璃在脏区模式下
每块脏区都要单独走一遍模糊（一次 blit + 两次全屏 pass），比整屏画还慢且会一顿一顿的。

#### 效果 × 平台 能力矩阵（正式版）

判据不是"GPU 支不支持"，而是三条 MCU/CPU 的真实瓶颈：
**A. 非轴对齐光栅化**（行跨度扫描失效）、**B. 离屏缓冲的 RAM**、**C. 每像素代价**。

| 效果 | PC / 移动 | MCU | 卡在哪 | 备注 |
|---|---|---|---|---|
| 缓动 / 关键帧 / 状态过渡 | ✅ | ✅ | — | 纯数学 |
| 路径动画（平移） | ✅ | ✅ | — | 贝塞尔求值，几十个乘法 |
| 路径动画（沿路径旋转） | ✅ | ⚠️ 降级 | A | 数学能算，旋转后画不出来 → 退化：跟随平移、朝向固定 |
| 圆形 / 圆角揭示 | ✅ | ✅ | — | 行跨度光栅本身就是"按行求交集"，加个随半径变化的 sqrt |
| 交叉淡入淡出 | ✅ | ✅ | — | 两个 quad 动 alpha |
| 任意形状遮罩 | ✅ | ⚠️ 看精度 | B+C | 1bpp 遮罩 320×240 = 9.4KB 可接受；4bpp = 37.5KB 偏重 |
| 线性 / 径向渐变 | ✅ | ✅ | — | 逐行算"起始色 + 每像素增量"，**MCU 上最便宜的效果** |
| 软阴影 / 外发光（实时 SDF） | ✅ | ⚠️ 仅小编码区域 | C | 每像素 sqrt，全屏不可行；一张卡片约 1 万像素可接受 |
| 软阴影（9-slice 预烘焙） | ✅ | ✅ **推荐替代** | — | 64×64 4bpp 贴图 = 2KB，九宫格拉伸 + alpha blit |
| 单元素 3D 翻转（真透视） | ✅ | ❌ | A | 透视后的四边形非轴对齐 |
| 单元素 3D 翻转（假翻转） | ✅ **已实现** | ✅ **推荐替代** | — | `scaleX: 1→0→1`，轴对齐照样走行跨度；无透视缩短但视觉上就是翻转（`test_flip`） |
| 组透明度（父 `opacity`） | ✅（GL 走 FBO 图层） | ❌ | B | 退化：逐元素 alpha（重叠处偏暗） |
| 模糊 / 毛玻璃 | ✅ **已实现**（GL + CPU） | ❌ | B / C | GPU 1/2 降采样 ping-pong；CPU 就地卷积 O(面积)，一张卡 ≈ 半次整屏重绘 |
| 毛玻璃（近似） | — | ⚠️ 视觉近似 | — | 半透明底 + 预烘焙噪点叠层，看着像磨砂，其实没模糊 |
| 多平面 3D 场景 | ❌ | ❌ | A | 需深度缓冲 + z 测试；与画家算法冲突 |
| `backface-visibility` | ❌ 报错 | ❌ 报错 | — | 假翻转没有背面，`scale == 0` 时零面积即"看不见"；换脸用两个元素错开 delay |

**MCU 上真正做不了的只有三件**：真透视 3D、真毛玻璃、组透明度语义。
其余全部可做，其中 **4 项有"几乎无损"的替代做法**（上表"推荐替代"）。

> 不允许在 MCU 阶段换另一套做法**。

#### 三条强制约束

1. **动画必须走脏区，禁止依赖整屏重画**

   | | 320×240 整屏重绘 | 结论 |
   |---|---|---|
   | x86 实测 | 0.196 ms | PC 上随便全画（1080p 全屏 2.37ms，占 16.7ms 预算 14%） |
   | Cortex-M4 估算 | 4~8 ms（含文字/圆角/混合实际 15~25ms） | **MCU 必须脏区**，否则没有帧预算 |

   动画系统从第一版就要**跟踪被动画元素的脏矩形**（旧位置 ∪ 新位置），
   不能"PC 能全画，所以先不做脏区"——那等于把 MCU 路堵死。

2. **`transform` 是绘制期属性，不是布局期属性**
   与 CSS 语义一致（`transform` 不影响布局），所以滑入/缩放动画**零重排**。
   代价是命中测试必须做逆变换。反过来，动画 `width`/`padding` **会**触发每帧重排，
   允许但要在文档里明确劝阻（和浏览器一样）。

3. **亚像素坐标是"顺滑"的分水岭**
   `ql_coord_t` 现在是整数像素：`x` 从 10 动到 20 只有 10 个离散位置，
   60fps / 300ms 的动画只有 18 个台阶，肉眼可辨。
   **`M5` 的定点坐标（26.6）恰好是这件事的基础，所以 M5 必须在 M5.5 之前**
   （PC 端 GPU 路径天然亚像素，CPU 路径最终仍落在整像素上——这是可接受的偏差）。

#### 验收

| 项 | 标准 |
|---|---|
| 微交互 | hover/press 过渡在 GPU 与 CPU 两条路径上均无跳变 |
| 帧率 | 320×320 窗口，10 个元素同时动画，vsync 60fps 不掉帧 ✅（CPU 侧 0.026 ms/帧，窗口实测 59.3 fps） |
| 脏区正确性 | 动画元素的**旧位置**必须被重绘（新增 `test_anim_dirty` 逐像素断言） |
| 语义 | 中断动画从当前插值重基；`animation-fill-mode` 四值正确；`animationend` 可收到 ✅ |
| 3D 翻转 | 单卡片翻面正确，`backface-visibility: hidden` 不显示背面，命中测试在翻转后仍准确 |
| 效果 | 软阴影 / 渐变 / 圆形揭示 / mask 揭示 各有 golden image 测试 |
| 不支持的 | `filter` / `clip-path` / 3D 场景 在构建期**报错**（沿用"不静默降级"红线） |

#### 明确不做

| 特性 | 原因 |
|---|---|
| `filter: blur()` / `backdrop-filter` 的 MCU 实现 | 无离屏缓冲 |
| `clip-path` 任意路径 | 需 stencil 或 shader 采样，收益不抵复杂度 |
| 多平面 3D / `perspective` 场景 | 与画家算法冲突，需深度缓冲 |
| `motion-path` 的多段复合路径 | 极低频；单段贝塞尔够用 |

## 6. 架构红线（写进规范，防止走偏）

| 红线 | 原因 |
|---|---|
| **不做保留式场景图 / render tree** | 那会变成 GTK4 的 GSK，每帧重建节点，性能优势全丢 |
| **不做运行期 CSS 匹配** | 样式在构建期消解，这是性能与体积的根基。M3.5 的运行时解析是"加载时算一次"，**不是**每帧匹配，且解析器可整块摘掉 |
| **不做 DOM API / JS 引擎** | PC 高兼容用系统 WebView，不在本项目范围内 |
| **不与 Qt/GTK 比功能广度** | 只做 UI；可访问性、IME、多媒体不做 |
| **不允许静默降级** | 不支持的 CSS/HTML 必须构建期报错 |
| **稳态零 malloc** | 所有热路径预分配；新增分配要有断言兜底 |
| **外来数据必须有界** | 静态 doc 是编译器常量；`.qlui` 与将来的 HTML/CSS 文本是**外来字节**，所有计数/递归都要有 `QL_CFG_UI_MAX_*` 上限 |
| **明确失败优于半个正确** | 加载失败一律返回 NULL + 带原因的错误，禁止"跳过坏数据继续画" |
| **混用单位是面板** | doc 之间是 `uint16` 下标，跨 doc 引用物理上不存在；不做元素级混合 |
| **动画必须走脏区** | PC 上可以整屏重画（占预算 14%），MCU 上没有这个余量。第一版就做对，否则 MCU 路堵死 |
| **不打破"单批次"除非有里程碑授权** | 毛玻璃是唯一会打破它的特性，且必须作为可选编译开关 |
| **同一份源，两个平台** | 能力差异靠 `qlui --platform` 的**构建期降级报告**表达，不靠 `#ifdef` 满天飞；"不静默降级"依然成立 |

### golden 护栏（M7 前置）—— **已完成（2026-11-08）**

**为什么先做这个**：M3.5 第 3 步（C 版 HTML/CSS 解析器）的验收标准是
"构建期产出的 blob 与提交的基准**逐字节相同**，且拒绝的输入集合不变"。
那是在 C 里复刻一套 Python 语义——没有自动回归，每次改 shorthand 展开或级联顺序
都只能靠肉眼，做不下去。

**两层比对，各自独立咬合**（`test/web/test_golden.c`，27 个用例）：

| 层 | 判据 | 抓什么 | 已验证的咬合度 |
|---|---|---|---|
| `.qlui` blob | **逐字节相同** | 任何数据层变化（色阶、间距、圆角、简写展开顺序…） | 改 `#F0B030` → `#F0B031`、改 `border-radius: 24px` → `25px`：**都红** |
| 基准图 | 单通道差 > 12 的像素 ≤ 0.5% | 版面/几何/绘制回归 | 只坏基准里一个像素 run：**红**（1.77% 超差） |

**顺带扩了 CPU vs GPU 的覆盖面**：从手挑 3 页变成**全部 27 页**，每页一个容差
（绝大多数是 2%，`blur` 6% —— CPU 全分辨率盒式 vs GPU 半分辨率 9 抽头，斜坡本来不同宽）。

**体积与速度**：基准用自带的极简 RLE（`.qlg`）+ 按内容裁剪，**528 KB**（等价 PPM 是 8.2 MB）；
单次运行 **0.19 s**。

**CI 三档**（`.github/workflows/ci.yml`）：Release/ctest、ASan+UBSan/ctest、`-Werror` 构建。
第一跑就抓到一个真 UB（`ql_rectfx_from_rect` 里对负坐标左移，见 §7 风险表下方）。

**用法**

```bash
./build/test_golden                        # 比基准
QLGL_GOLDEN_UPDATE=1 ./build/test_golden    # 重建基准（**先确认画面是对的**）
QLGL_GOLDEN_EXACT=1  ./build/test_golden    # 逐像素严格相等（本机自测）
QLGL_GOLDEN_PPM=1    ./build/test_golden    # 另外写 /tmp/golden_*.ppm 供肉眼查看
```

**顺带修掉一个真 flex bug（有回归测试）**

写 `03_layout` 时发现 `.btn { width: 56px }` 被压成 24px：

> flex 项的 `width: auto` 被当成 block 布局的"撑满包含块"。于是空的
> `flex-grow: 1` 占位块基准尺寸 = 整个容器宽 → `sum_base` 超过容器 →
> 算出一份**负剩余空间** → 触发 shrink → 把旁边固定宽度的兄弟一起压扁
> （实测 `40px`→29px、`56px`→40px）。

修法：新增 `max_content_main()`，在 `measure_flex_items()` 里先把 auto 主轴尺寸
按 **max-content** 落成显式值（空盒子 0 / 只有文本取文本宽 / 有子节点按主轴求
和或取最大）。注意**不能顺手把 `box_sizing` 改成 1** —— 那会把同一项的交叉轴
也算错（带 1px 边框的 20px 格子从 22 变 20，`test_golden` 的 `bench100` 当场红）。

`test/web/test_flex_auto.c`（15 项）钉住这条语义：固定宽不被压、空 auto 项基准为 0、
文本项基准是文本宽、`flex-basis` 显式给了就不用 max-content、content-box 不变。
