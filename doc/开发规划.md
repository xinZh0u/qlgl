# QLGL 开发规划

> 定位：**CSS+HTML 的"GTK"** —— 界面用 HTML/CSS 写，构建期编译成 C；绘制层 CPU/GPU 双后端；
> PC / 移动是第一平台，MCU 是第二平台；性能对标 LVGL，在小屏 CPU 光栅场景结构性轻于 GTK。
>
> 本文是**排期与验收依据**。每完成一个里程碑，必须同时更新 [bench.md](./bench.md) 与相关手册。

---

## 1. 现状快照（已完成并可验证）

| 层 | 能力 | 状态 |
|---|---|---|
| 基础 | 对象/类型/属性/事件池/内存池/QLStr 双策略 | ✅ 6 个测试 |
| 绘制 | `QLCanvas` 原语（填充/圆角/描边/线/alpha/多像素格式） | ✅ |
| 文本 | 内置 4bpp 位图字体（ASCII 32..126）、UTF-8、度量 | ✅ |
| 控件 | `QLWidget` / `QLLabel`（属性 + 自动尺寸 + 对齐） | ✅ |
| HTML/CSS | `tools/qlui`：HTML+CSS → C；block/inline、盒模型、6 种选择器、级联、`box-sizing` | ✅ |
| 绘制接口 | `QLDraw2D`（CPU/GPU 唯一分界） | ✅ |
| GPU | GLES3 + EGL：SDF 圆角、字形图集、**1 draw call/帧** | ✅ |
| 显示 | 内存 / X11 / Wayland（CPU）；GL(X11) 窗口 + 离屏 | ✅ |
| 工具 | `qlgen`（类型 id）、`qlfontgen`（字体）、`qlui`（HTML/CSS） | ✅ |

**规模**：头文件 + 实现 **7,626 行**，测试/示例 19 个文件，13 个 ctest 全绿，
ASan/UBSan 与 `-Werror -Wpedantic -Wconversion` 通过。

### 实测性能（本机，Mesa，单帧 450 顶点）

| 分辨率 | GL 含 GPU 完成 | CPU 光栅 |
|---|---|---|
| 320×240 | 0.111 ms（≈8,900 fps） | 3.68 ms（272 fps） |
| 1280×720 | 0.305 ms（≈3,280 fps） | 23.1 ms（43 fps） |
| 1920×1080 | 0.501 ms（≈2,000 fps） | **44.4 ms（23 fps）** |

窗口 vsync 模式稳定 **59.2 fps**，CPU 侧每帧仅 0.22 ms。

## 4. 里程碑

> 排序原则：**先让"能看见、能点、能写中文"，再谈性能极限，最后铺平台。**
> 每个里程碑独立可演示、可验收，不做"半年后再看效果"的大爆炸式交付。

### M1 · 交互闭环（约 2 周）

**目标**：界面能点、能悬停、能响应键盘。

| 任务 | 说明 |
|---|---|
| 输入抽象 | `QLInputEvent`（pointer down/up/move/wheel、key down/up、字符输入） |
| 后端对接 | X11（鼠标/键盘已有基础）、Wayland（wl_pointer/wl_keyboard）、GL 窗口 |
| 事件路由 | 命中测试 → 目标节点 → 冒泡到根；`stopPropagation` |
| 回调 API | `ql_ui_on(node_id, event, cb)`；节点在生成期拿到稳定 id |
| 状态样式 | `:hover` / `:active` / `:focus` / `:disabled` 编译成"状态 → 样式覆盖表" |
| 验收 | `example_ui_interactive`：按钮按下变色、悬停高亮、Esc 退出；3 个单测 |

**为什么第一优先**：没有输入，所有界面都只是"画出来的图片"，无法验证真实可用性。

---

### M2 · 文本质量（约 3 周）

**目标**：中文能看、缩放下不糊、文本不再是 CPU 瓶颈。

| 任务 | 说明 |
|---|---|
| FreeType 接入 | `QLFontBackend` 抽象；矢量字体光栅化 → 8bpp 位图 |
| 字形缓存 | 每 (font, size, glyph) 缓存位图；LRU + 固定上限（MCU 可关） |
| 动态图集 | GPU 侧字形图集扩容/淘汰（现在只有静态 512×512 两张内置字体） |
| CJK | 默认字体接 Noto Sans CJK 子集；`font-family`/`font-weight` 映射 |
| 排版增强 | 自动换行、行高、字距；HarfBuzz 留到 M2.5（拉丁/中文不需要整形） |
| 验收 | 中文示例页；128 字正确渲染；`font-size: 12/16/24` 三档；文本帧时间 ≤ 2 ms @1080p |

**为什么第二**：**PC 第一平台 + 中文用户 = 必须**. 现在只有 ASCII，任何中文界面都是 `?`。

---

### M3 · 布局表达力（约 4 周）

**目标**：能表达真实页面，不再"只能堆 div + margin"。

| 任务 | 说明 |
|---|---|
| flexbox | `display:flex`、`flex-direction`、`justify-content`、`align-items`、`flex-grow/shrink/basis`、`gap`、`flex-wrap` |
| 定位 | `position: relative/absolute/fixed`、`z-index`、`overflow: hidden/auto` |
| 滚动 | 滚动容器 + CSS 样式化滚动条（`::-webkit-scrollbar` 子集） |
| 混合内容 | 支持 `<p>文字<b>粗</b></p>`（文本节点与元素混排） |
| 布局缓存 | 内容尺寸缓存，供 M4 的增量布局使用 |
| 验收 | 20 个 flex 用例几何差 ≤ 1px；可滚动列表；混合内容示例 |

**为什么第三**：flex 是 Web 布局的事实标准，没有它"迁移"就是空话。

---

### M4 · 性能补齐（约 3 周）

**目标**：把 CPU 路径拉回 LVGL 量级，并让静态界面几乎零开销。

| 任务 | 对应缺口 | 预期收益 |
|---|---|---|
| ~~CPU 行循环 + 格式特化~~ **已完成** | G1 | 1080p 44ms → **1.84ms** ✅ |
| SIMD（SSE2/NEON）blitter | G1 | 再快 2~3× |
| 字形行级裁剪 + 缓存 | G4 | 文本快 3~5× |
| 增量布局（脏子树） | G2 | 静态界面重排 ≈ 0 |
| 渲染脏区剪枝 | G3 | 节点多时线性 → 局部 |
| `style_copy` 改按需分配 | G5 | 每节点省 44 B |
| 控件层接 `QLDraw2D` | E2 | 控件也能用 GPU |
| 验收 | §3.1 全部指标达标，写入 bench.md 并入 CI |

---

### M5 · 逻辑坐标 / 高 DPI（约 1 周，**必须早做**）

**目标**：同一份 CSS 在 1x/1.25x/1.5x/2x/3x 屏上视觉一致。

| 任务 | 说明 |
|---|---|
| 坐标改 26.6 定点 | `ql_coord_t` 语义改为 CSS px（26.6） |
| DPR | 布局在 CSS px，光栅在设备 px；`ql_canvas` 与 GL 均按 DPR 缩放 |
| 后端上报 | X11（Xft.dpi）、Wayland（wl_output.scale）、Win（DPI awareness）、macOS（backingScaleFactor） |
| 验收 | DPR=2 与 DPR=1 的截图缩放到同尺寸后像素差 < 3% |

> 这件事越晚做越贵：rect 已经扩散到 qlui/widget/canvas/GL 四处，必须单独一个里程碑完成。

---

### M6 · 平台扩展（约 6~8 周，可并行）

**目标**：兑现"PC/移动第一平台"。

| 顺序 | 平台 | 需要的后端 |
|---|---|---|
| 1 | Linux Wayland（GPU） | EGL + `wl_egl_window`（当前靠 XWayland） |
| 2 | Windows | Win32 窗口 + **D3D11** 渲染 + DPI |
| 3 | macOS / iOS | AppKit/UIKit + **Metal** 渲染 |
| 4 | Android | ANativeWindow + **GLES3**（复用现有 GL 后端）+ 触摸 |

**约束**：每个新后端必须通过 `test_gl_vs_cpu` 的等价测试（"该后端 vs CPU" 像素一致）。

## 5. 关键路径与依赖

```
M1 输入 ──┐
M2 文本 ──┼─▶ 可演示的产品级界面 ─▶ M6 平台扩展
M3 布局 ──┘            ▲
                        │
M4 性能 ────────────────┘（基线稳定后再铺平台，避免在 5 个平台上重复优化）
M5 DPR ── 必须在 M3 之后、M6 之前（否则每个平台都要返工）
```

**建议节奏**：M1 → M2 → M3 → M4 → M5 → M6，M7 穿插进行。

## 6. 架构红线（写进规范，防止走偏）

| 红线 | 原因 |
|---|---|
| **不做保留式场景图 / render tree** | 那会变成 GTK4 的 GSK，每帧重建节点，性能优势全丢 |
| **不做运行期 CSS 匹配** | 样式在构建期消解，这是性能与体积的根基 |
| **不做 DOM API / JS 引擎** | PC 高兼容用系统 WebView，不在本项目范围内 |
| **不与 Qt/GTK 比功能广度** | 只做 UI；可访问性、IME、多媒体不做 |
| **不允许静默降级** | 不支持的 CSS/HTML 必须构建期报错 |
| **稳态零 malloc** | 所有热路径预分配；新增分配要有断言兜底 |

## 7. 风险登记

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| flexbox 语义细节踩坑（基线对齐、百分比循环依赖） | 高 | M3 超期 | 先做 20 个用例驱动，与浏览器差分测试 |
| FreeType/HarfBuzz 体积膨胀（+1.5~2.5 MB） | 中 | MCU 档不可用 | 分档裁剪：MCU 只保留位图字体 |
| 多平台后端维护成本 | 中 | 人力稀释 | 只做 4 个主力平台；每加一个都要过 golden 测试 |
| GPU 驱动差异/上下文丢失 | 中 | 移动端白屏 | CPU 后端始终可回退；资源重建路径 |
| 需求继续膨胀（又要 JS、又要完美兼容） | 中 | 方向漂移 | 用本文 §6 红线挡住 |

## 8. 立即可开工的三件事（按性价比）

1. **M4-G1：CPU 行循环 + 格式特化**（1~2 天）
   收益最大、风险最低：1080p 从 44 ms 降到 ≈6 ms，同时让 golden 测试跑得更快。
   不依赖任何新决策。

2. **M1：输入系统 + 状态样式**（1~2 周）
   让 qlui 界面第一次"能点"，是产品级演示的前提。

3. **M2：FreeType 接入**（1 周起步）
   解开"中文不可用"这个硬阻塞；先做单字体单字号，再做缓存与图集。
