HTML5 标签覆盖与 MCU 裁剪

这份文档回答两个问题：

  1. HTML5 的标签，本库到底支持到哪一步？ —— 全量清单，一个不漏，逐条给状态。
  2. MCU 上怎么办？ —— 编译期按能力包裁剪，但枚举与 blob 不许跟着变。

一句话承诺：

解析层 114/114（不再有"不认识的标签"）；渲染层按能力包（PC/移动默认全开）； MCU 编译期裁包，裁剪只影响代码路径与错误文案，不影响 QLUITag 枚举值、不影响 blob。

1. 全量清单（114 个）

口径：HTML Living Standard 的元素索引，不含 obsolete 元素（marquee center font big strike tt frame nobr rb xmp 等二十来个），也不含实验中的 portal / fencedframe。obsolete 那批按"明确失败"处理：写了就报错，不做宽容降级。

2. 能力包

一个"包"= 一组标签 + 支撑它们的那部分引擎。包是编译期开关，也是构建期报告的单位。

现状（老实说）：除 QL_FEAT_UI_META、QL_FEAT_UI_IMAGE 与 QL_FEAT_IMG_* 之外，表里的宏目前只有名字、还没进代码（grep 不到）。 它们是"裁剪时的口径"，不是现在能 -D 的东西。已落地的开关见 图像管线设计 §2 与 include/qlgl/qlconfig.h。

CORE 里那 62 个是"不需要任何额外运行期机制、只靠样式+布局就能画"的那批 （含滚动容器）。判据是"要不要专用机制"，不是"有没有状态"：

  • <input> / <select> 是状态最重的两个（光标、选区、覆盖面板），但正因为如此 它们必须能被裁 —— 所以归 CONTROL；
  • <output> / <datalist> 其实零成本（前者等价 span，后者 display:none）， 仍归 CONTROL 是因为用户视角它们是表单控件，一起裁更省心。

3. 一条硬约束：枚举不可条件化

QLUITag 的数值会写进 blob（QLUINode.tag 是 uint16 索引），而且三张表 （QLUITag / k_tags[] / s_tag_names[]，外加 qltext 的 TAG_NAMES[]）必须同序。

所以：

允许 禁止
在末尾追加枚举项 因为"MCU 不用"而删掉/挪动枚举项
用宏裁掉函数体、UA 默认分支、绘制路径 用宏裁掉枚举项本身（值会错位，blob 跨平台就废了）
用宏裁掉报错文案 让同一份 .qlui 在两个平台上解释出不同标签

结论：枚举与名字表永远全量。代价是 .rodata 里多约 1.2 KB 字符串 （114 条名字 + 指针表），换回来的是"一份 blob 到处能读、调试名永远对得上"。

如果某天真的差这 1 KB，再加一个 QL_CFG_UI_TAG_NAMES_MIN（名字表退化成 ql_ui_tag_name() 返回 "?"），那是独立的一步，和裁包无关。

4. 裁包之后会发生什么

现状：机制与第一个包（META）已经落地，开关在 qlconfig.h： QL_FEAT_UI_META（默认 1）与 QL_CFG_UI_LENIENT_TAGS（默认 0）。 其余包（TEXT / TABLE / IMAGE / CONTROL / EMBED）随实现追加， 在那之前它们的标签还不在枚举里，遇到就是"不认识的标签"报错。

解析器先按名字认标签（tag_index()，全量表），再看这个标签所属的包开没开：

模式 行为
strict（默认） 明确报错，文案里点名缺哪个包：
<table>: 这个构建关掉了表格（QL_FEAT_CSS_TABLE=0）
lenient 降级成 div（块级）/ span（行内），并计入 doc->degraded_tags，ql_ui_load_text 之后可查

两条都不静默：strict 失败在编译期（CI 能拦住），lenient 有计数与名单（运行时能打日志）。 这就是本库"明确失败优于半个正确"的落地方式 —— 降级是显式声明的，不是悄悄发生。

lenient 的典型用途：MCU 上贴外部 HTML 片段、只想要"能看就行"。

5. 现在是占位的 13 个（EMBED）✅

5.1 先说清楚"占位"是什么意思

占位是默认档，不是终点。 这一包的原则是：

能接外部 C 库就接，真的接不了才留占位；不同平台接不同的库； PC / 移动默认开，MCU 默认关，但硬要在 MCU 上保留也允许。

所以下面 13 行现在全是 ✅ —— ✅ 的意思是"认识且不炸"（整页 HTML 贴进来能编译过）， 不是"已经做到头了"。每行都标了它属于哪一档：

档 含义 标签
A 自己就能做，不需要外部库，也不动架构前提 iframe embed object canvas track
B 需要外部库，但接进来是加法 svg audio video
C 库存在，但接了要推翻"构建期定型 / 无运行期重排 / 脏区驱动" script slot template
D 没有可用的 C 库，自己写等于重做一个布局引擎 math

全部后端的接口设计、开关结构、工作量与排序见 EMBED 后端设计。 目前代码里这 13 个只有占位实现，一个后端都没接（未排期）。

5.2 现状逐条

标签 档 为什么现在是占位 / 能不能接后端 内容怎么处理 盒子
script C 引擎能接（QuickJS / JerryScript / Duktape），但 el.style.x= / appendChild / rAF 分别要求运行期重算样式、运行期建节点、持续全帧重绘 —— 三条都是反向红线。不做 整段跳过（按 raw text 扫到 </script>，内容里的 < </div> 都是普通字符） display:none
template C 惰性内容，没有 JS 就没有任何东西会去克隆它。可以另做"构建期宏展开"，但那是 QLGL 自己的语言特性，不是 HTML 语义 整段跳过（标签配平扫描） display:none
slot C 没有 shadow DOM 就没有可插的树。同上 解析但隐藏 display:none
svg B 可接，ROI 最高：plutosvg（MIT，自带光栅器）。两条路 —— 构建期转 RAW（MCU 唯一档）或运行期后端（PC/移动），和 JPEG 后端同形 整段跳过（内容不是 HTML：<path>/<circle> 真去解析就报错） 占位盒 120×60 inline-block
audio B 可接：dr_wav/dr_mp3/dr_flac + miniaudio（ALSA/Pulse/CoreAudio/WASAPI/AAudio/OpenSL 一套通吃）。真正的工作量是 <audio controls> 控件，不是解码 解析但隐藏 占位盒 300×32
video B 可接，成本最大：起步用 pl_mpeg（MPEG-1，单文件 MIT，无依赖）；ffmpeg 作 PC 全格式后端，但要接受 5–15 MB 和 LGPL 链接要求。还需要逐帧 blit 的双缓冲 解析但隐藏 占位盒 300×150
iframe A 不需要任何库：构建期把 src 文档编进来，运行期当子视口渲染（裁剪 + 滚动都现成）。唯一新机制是事件坐标路由 解析但隐藏 占位盒 300×150 block
embed object A 纯类型分派器，几十行：src 是图片走 <img> 那条完整路径，是 HTML 走 iframe，其余占位 解析但隐藏 占位盒 300×150 block
canvas A HTML 语义要 JS（永远空白）→ 死路。但换成 C API 渲染回调就完全成立：ql_ui_canvas_bind() 让应用代码在渲染期往盒子里画图表/仪表/波形 解析但隐藏 占位盒 300×150 block
track A 依附 audio/video：WebVTT 解析约 200 行 + 字幕叠画。没有 media 就没有意义 空元素 display:none
math D C 世界没有可用的 MathML 引擎；自己写 ≥ TABLE 包的工作量。旁路：构建期用 TeX/KaTeX 渲染成 SVG/位图，走 svg 或图像管线 整段跳过（<mi>/<mo> 不是 HTML 标签） 占位盒 120×60 inline-block
noscript — 纯语义。既然本库永久无脚本，按规范内容应该显示；现在是隐藏（实用主义），后续改成开关 QL_CFG_UI_NOSCRIPT_SHOW 解析但隐藏 display:none

占位盒长什么样：1px 实线边框 + 居中的标签名（iframe / video / svg…）。 用标签名而不是"未支持"两个字，是因为内建位图字体只有 ASCII（中文会变成 ???）， 而且标签名本身就是排查线索。盒子小于 32×12 时不画字（糊成一团没意义）。 想彻底去掉提示就写 CSS：iframe { border-width: 0; width: 0; height: 0 }。

两处与浏览器不同的取舍（都写在这里，不藏着）：

  1. <noscript> 的内容不显示。 严格按规范，QLGL 没有 JS ⇒ 脚本"总是不可用" ⇒ 应该显示 noscript 的内容。但这类内容在网页上通常是"请开启 JavaScript"式的降级 提示，在 QLGL 里显示出来只会是噪音。要显示就自己写 noscript { display: block }。 后续会把这个取舍变成开关 QL_CFG_UI_NOSCRIPT_SHOW（默认仍是隐藏，见 EMBED 后端设计 §6.8），目前该宏还不存在。
  2. <canvas> / <iframe> / <object> / <video> 的兜底内容不显示。 浏览器在"不支持"时显示它们；这里用占位盒代替，避免一页里出现两套"做不到"的说明。

<svg> 必须跳内容，不能只 display:none —— 这是实现时踩到的坑： <svg> 里的 <path> / <circle> 都不是 HTML 标签，真解析会报"不支持的标签"， 整页编译不过。而"整页 HTML 贴进来能编译"正是这一包存在的全部理由。

顺带修的一条容错：空元素（br / img / input / embed / track …）的 结束标签，浏览器是忽略（规范里叫 parse error 而非语法错误），这里也照做 —— 否则 <embed></embed> 这种看着很正常的写法会让整页编译不过，而错在哪用户看不出来。 非空元素的结束标签不匹配仍然明确报错。

6. 构建期就该知道结果

现状：下面的 --features 参数还没实现（qltext check 现在只报"能否编译"）。 这一节是设计意图 —— 包的名字在这里是用户可见的报错单位，所以名字得起对。

qltext 拿得到目标平台的能力包，所以不用等到跑起来才发现被降级：

$ qltext check --html app.html --css app.css --features core,image
app.html: 42 个节点，使用标签 9 种
  <table>   ×2  需要 QL_FEAT_CSS_TABLE  → 会被降级成 div
  <img>     ×3  ✅
  <ruby>    ×1  需要 QL_FEAT_UI_TEXT   → 会被降级成 span
结论：3 处降级。要么开包，要么改界面。

同一套开关也用在 qltext cc --features ...（生成 C 时直接按目标平台裁）。
