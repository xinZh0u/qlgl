HTML5 标签覆盖与 MCU 裁剪

这份文档回答两个问题：

  1. HTML5 的标签，本库到底支持到哪一步？ —— 全量清单，一个不漏，逐条给状态。
  2. MCU 上怎么办？ —— 编译期按能力包裁剪，但枚举与 blob 不许跟着变。

一句话承诺：

解析层 114/114（不再有"不认识的标签"）；渲染层按能力包（PC/移动默认全开）； MCU 编译期裁包，裁剪只影响代码路径与错误文案，不影响 QLUITag 枚举值、不影响 blob。

1. 全量清单（114 个）

口径：HTML Living Standard 的元素索引，不含 obsolete 元素（marquee center font big strike tt frame nobr rb xmp 等二十来个），也不含实验中的 portal / fencedframe。obsolete 那批按"明确失败"处理：写了就报错，不做宽容降级。

2. 能力包

一个"包"= 一组标签 + 支撑它们的那部分引擎。包是编译期开关，也是构建期报告的单位。

3. 一条硬约束：枚举不可条件化

QLUITag 的数值会写进 blob（QLUINode.tag 是 uint16 索引），而且三张表 （QLUITag / k_tags[] / s_tag_names[]，外加 qltext 的 TAG_NAMES[]）必须同序。

所以：

允许 禁止
在末尾追加枚举项 因为"MCU 不用"而删掉/挪动枚举项
用宏裁掉函数体、UA 默认分支、绘制路径 用宏裁掉枚举项本身（值会错位，blob 跨平台就废了）
用宏裁掉报错文案 让同一份 .qlui 在两个平台上解释出不同标签

结论：枚举与名字表永远全量。代价是 .rodata 里多约 1.2 KB 字符串 （114 条名字 + 指针表），换回来的是"一份 blob 到处能读、调试名永远对得上"。

如果某天真的差这 1 KB，再加一个 QL_CFG_UI_TAG_NAMES_MIN（名字表退化成 ql_ui_tag_name() 返回 "?"），那是独立的一步，和裁包无关。

4. 裁包之后会发生什么

现状：机制与第一个包（META）已经落地，开关在 qlconfig.h： QL_FEAT_UI_META（默认 1）与 QL_CFG_UI_LENIENT_TAGS（默认 0）。 其余包（TEXT / TABLE / IMAGE / WIDGET / EMBED）随实现追加， 在那之前它们的标签还不在枚举里，遇到就是"不认识的标签"报错。

解析器先按名字认标签（tag_index()，全量表），再看这个标签所属的包开没开：

模式 行为
strict（默认） 明确报错，文案里点名缺哪个包：
<table>: 本构建没有启用 QL_FEAT_UI_TABLE（表格布局）
lenient 降级成 div（块级）/ span（行内），并计入 doc->degraded_tags，ql_ui_load_text 之后可查

两条都不静默：strict 失败在编译期（CI 能拦住），lenient 有计数与名单（运行时能打日志）。 这就是本库"明确失败优于半个正确"的落地方式 —— 降级是显式声明的，不是悄悄发生。

lenient 的典型用途：MCU 上贴外部 HTML 片段、只想要"能看就行"。

5. 永远只做占位的 13 个（EMBED）

它们不是"还没做"，是按红线不做真渲染：

标签 为什么不做 占位怎么做
script noscript template slot 与"没有 DOM / 没有 JS"红线冲突 script 的内容整段跳过（不解析、不进文本池）；其余按 display:none
iframe embed object 外来内容无法有界（网络、第三方渲染器） 一个带边框的空盒子 + 文字 未支持
audio video track 要解码器 + 音频输出 + 音视频同步 空盒子（可以画个播放图标字符）
canvas 要 JS 或"C 代码往上画"的新 API 层 空盒子占位；真的想画 → 直接用 QLCanvas，别绕 HTML
svg math 各自需要独立渲染器（等于写第二个 QLGL） 空盒子占位

这就是"HTML5 全支持"的准确含义：114 个标签全能编译通过， 其中 66 个现在真画、48 个按包补齐后真画或占位、0 个报"不认识的标签"。

6. 构建期就该知道结果

qltext 拿得到目标平台的能力包，所以不用等到跑起来才发现被降级：

$ qltext check --html app.html --css app.css --features core,image
app.html: 42 个节点，使用标签 9 种
  <table>   ×2  需要 QL_FEAT_UI_TABLE  → 会被降级成 div
  <img>     ×3  ✅
  <ruby>    ×1  需要 QL_FEAT_UI_TEXT   → 会被降级成 span
结论：3 处降级。要么开包，要么改界面。

同一套开关也用在 qltext cc --features ...（生成 C 时直接按目标平台裁）。
