CSS 覆盖与裁剪（全量清单）

这份文档回答三个问题，口径与 HTML5 标签覆盖与裁剪 一致：

  1. CSS 的每一样东西，本库支持到哪一步？ —— 按模块穷举，一条不漏。
  2. 不支持的为什么不做？ —— 每条给一个原因码（§2），不写"暂不支持"这种废话。
  3. 哪一批先做？ —— 按"收益 / 风险 / 是否动 QLUIStyle"排成五批（§10）。

一句话现状：

布局与绘制的骨架已经齐了（盒模型、flexbox、定位、圆角、阴影、渐变、变换、过渡、动画）； 缺的是真实页面天天用的细节（min/max-*、em/rem、:nth-child、::before、 letter-spacing、text-overflow、border-style、cursor…）。 加这些是"补细节"，不是"补架构"。

0. 已完成 vs 待做（2026-11-09 更新）

已完成（B2 全部 + B1 第一片）：

能力 说明
*、[attr] 系列、:first/last/only-child、:nth-child(an+b)、:*-of-type、:not() 全部构建期求值
::before / ::after + content: "文本" 构建期展开成真节点（内部 tag #pe）
+ / ~ 兄弟组合符 之前直接报错，文档却写着支持 —— 现在真的支持了
min-width/max-width/min-height/max-height（px / %） blob v16；border-box / content-box 各自正确
!important 级联两趟：普通先应用，important 再应用
hsl() / hsla()、#rrggbbaa
currentColor / inherit / initial / unset 颜色位置识别成特殊值

还没做（下表里仍标 ⏳ 的）：em/rem/calc()、margin: auto、 border-radius 四角、letter-spacing / text-overflow（B3）、 border-style: dashed（B4）、align-self / order（B5）、transform: rotate()。

下面各表的 ⏳ 里混着"已做但表还没逐行翻"的可能 —— 以本节为准， 逐行状态在下一次整理时同步。

1. 状态记号

记号 含义
✅ 已支持（解析通过且生效）
⚠️ 支持但语义有偏差，偏差写在该行备注里
⏳ 计划做（§10 有批次编号）
❌ 明确不做（写了就构建期报错，不静默降级）
— 属性存在但本库没有对应概念（如打印相关），写了报错

红线：不支持的东西必须报错并给行号。下面每一个 ⏳/❌ 今天的实际表现都是 ql_ui_text_last_error() 里一句能读懂的话（多数还带替代方案），而不是"忽略这条规则继续渲染"。

2. 原因码

每行的"原因"列用下面的码。一个属性可能同时命中多个，只写主因。

码 含义 典型例子
L 布局必需：没有它写不出真实页面 min-width、margin: auto
R 绘制原语已具备：QLDraw2D 有对应调用，接上就行 border-radius、box-shadow
B 构建期可算：样式在编译期摊平，运行期零成本 所有选择器、简写展开
T 要时间轴 / 持续重绘，与"省电优先"冲突 animation-play-state: paused 之外的场景
O 要离屏图层（组不透明度、混合、滤镜链） 真 opacity、mix-blend-mode
F 要新光栅路径（旋转 / 任意仿射 / 非矩形） transform: rotate()
X 要外部引擎（文本整形、排版算法、打印引擎） text-justify、hyphens
P 与"静态节点 / 构建期定型"冲突（本库最核心的取舍） CSS 变量、@media、content: counter()
M 与 MCU 目标冲突（体积 / 内存 / 代码量） Grid、多栏、border-image
N 收益极低 / 已被取代 / 与 GUI 无关 float、text-emphasis、打印属性

3.5 @ 规则

@ 规则 状态 原因 备注

@layer @container @property @scope @starting-style ❌ P 都是"让样式表更动态"的东西，与本库"样式构建期定型"相反

auto ✅ L

border-width ✅ R 四边统一
border-color ✅ R 四边统一

11. Grid（整块不做）

属性 状态 原因
display: grid / inline-grid ❌ M：实现成本接近 flex 的两倍

12. 变换

属性 状态 原因 备注
transform: translate() ✅ R 加到绘制偏移上，不进布局（零重排）
transform: scale() ✅ R 允许负值（几何压扁 + 镜像）
transform: scaleX() / scaleY() ✅ R 假 3D 翻转就靠它
transform: rotate() ⏳ F 只支持 translate()/scale()/scaleX()/scaleY()；要旋转光栅路径（CPU 逐像素仿射 + GL 顶点变换 + 字形旋转）
transform: skew() ⏳ F 同上（斜体就是按行剪切，机制类似）
transform: matrix() / matrix3d() ❌ F 通用仿射需要完整的 3×3 变换管线
transform: perspective() / rotate3d() 等 3D ❌ M 要真 3D 管线；scaleX 已经能近似"翻面"效果
transform-origin ⏳ R 现在固定绕元素中心
transform-style / backface-visibility ❌ M 3D 专用

13. 过渡与动画

属性 状态 原因 备注
transition（简写） ✅ T 可过渡：background-color opacity color border-color border-radius transform clip-path

20. 三处"看起来简单、其实不简单"

写在这里，免得后面有人当"漏了"顺手补成半成品：

  1. opacity 是"逐图元降透明"，不是严格的组不透明度。真 CSS 把整棵子树先合成到一张 离屏图层再整体混合；本库的做法是把整体 alpha 乘到每一个绘制入口上，并顺着子树 往下乘（QLDraw2D.alpha / ql_draw2d_set_alpha()）。对"子树内部不重叠"的界面两者 逐像素一致；只有子树内部互相覆盖处会略透（每个图元各自降透明，重叠区乘了两次）。 严格版本要在 CPU 与 GL 两端各加一层离屏合成 —— 和 transform: rotate() 同级成本。
  2. margin: auto 是布局概念，不是值解析。块级盒要在有确定可用宽度时分掉剩余空间； flex 里的 auto margin 又是另一套（吸收剩余空间）。改动落在 layout_node() 与 flex 求解器两处。
  3. letter-spacing / word-break / text-overflow 都要动 ql_text_wrap()。 断行只有一份实现，布局（数行算高度）与绘制（逐行发射字形）共用它 —— 这是"布局与绘制对行数有分歧"这类 bug 的唯一防线。改它必须两边同时验。

21. CSS 能力包（编译期裁剪）

与标签完全同构：HTML5 那边一个"包"= 一组标签 + 支撑它们的引擎； CSS 这边一个"包"= 一组属性（含值级别的子特性）+ 支撑它们的绘制/布局代码。

21.1 为什么要包

理由 说明
省 Flash 阴影（SDF）、毛玻璃（独立着色器）、渐变（逐像素/顶点插值）加起来是实打实的几千字节
省 RAM 关掉 CONTROL 就没有输入框池；关掉 ANIM 就没有过渡池与关键帧表
构建期报告的单位 qltext cc 能直接说"这份界面需要 CSS_FLEX + CSS_SHADOW，而你的板子没开 CSS_SHADOW"
确定性 板子上不会出现"PC 上有阴影、板子上没有"这种无法解释的差异 —— 要么全有，要么明确报错

21.3 三个反直觉的判断

  1. CSS_SELECTOR_ADV 是唯一"裁了不省多少"的包。B2 全部在构建期展开 （:nth-child → 内部类、::before → 真节点），运行期零成本。 裁它只省解析器代码（几 KB），不省 RAM、不省每帧开销。 MCU 上更值得的做法是：保留它，因为它让"同一份 HTML"能两端跑， 而省下的那点 Flash 比"改两套 HTML"便宜得多。
  2. CSS_GRADIENT 在 GPU 上几乎免费（顶点颜色插值，不加顶点、不加 draw call）， CPU 侧才是逐像素成本。所以"给 MCU 留渐变、裁掉阴影"是合理组合 —— 包之间是正交的，不搞"要么全有要么全无"。
  3. CSS_ANIM 与省电相关。关掉它不仅是省代码：没有 animation 就没有 "主循环必须一直醒着"的理由。MCU 上关这个包等于强制静止界面，这对电池更实在。

21.4 硬约束（与标签 §3 同一条）

允许 禁止
在 QLUIStyle 末尾追加字段 重排/删除已有字段（style_struct_size 会变，blob 跨平台就废了）
用宏裁掉绘制路径（CSS_SHADOW 关掉后不画阴影） 用宏裁掉解析分支导致同一份 CSS 在两端解释不同
用宏裁掉报错文案 让同一份 .qlui 在两个平台上样式不同

关键点：报错不能因为裁剪而消失。 关掉 CSS_SHADOW 之后写 box-shadow， 必须报"本构建未启用 QL_FEAT_CSS_SHADOW（阴影）"，而不是静默忽略 —— 否则"PC 上看着对、板子上错位"的老问题会从标签那边原样搬过来。

因此每个包在解析期有三态：

模式 行为
启用 正常解析并生效
strict（默认） 明确报错，文案点名缺哪个包
lenient 忽略该声明，计入 doc->degraded_props（与 degraded_tags 并列），ql_ui_load_text() 后可查

21.5 与 blob 的关系

裁剪不影响 blob 的读写。 理由与标签一致：结构体字段永远全量、 枚举永远全量，所以：

  • 全量构建产出的 .qlui，在裁剪构建上能读、能布局、能画 —— 只是被裁掉的效果不生效；
  • 反过来也可以（裁剪构建产出的 blob 在全量构建上读，一切正常）。

这让"PC 上设计、板子上跑"不需要两套产物格式。代价是裁剪构建的 .rodata 里 仍有那些属性名字符串（约 700 字节，k_supported_props[]）。

21.6 预设

与 QLGL_IMG_PRESET（full / lean / raw-only）同形，CSS 侧三档：

预设 开哪些 典型目标
full 全开 PC / 移动
ui-lite BASE + FLEX + RADIUS + POSITION + SELECTOR_ADV；关 SHADOW/GRADIENT/BLUR/CLIP/TRANSFORM/ANIM MPU（嵌入式 Linux，弱 GPU）
micro BASE + POSITION；其余全关 MCU（静止界面，光标 + 文本 + 色块）

预设只是"一堆 -D 的别名"，随时可以用单品开关覆盖 —— 与图像管线完全一致的用法。

21.6.1 与 HTML5 能力包的交叉依赖

两边不是独立的 —— 有几个交叉点必须写进构建期检查（qltext cc 的报错里点出来）：

HTML5 包 需要哪些 CSS 包 说明
CONTROL（input/select/textarea） CSS_BASE 输入框的框体、光标都是 BASE 的绘制原语
IMAGE（<img>） CSS_BASE + 可选 CSS_RADIUS（圆角裁图）/ CSS_IMAGE_FIT（object-fit） 图像管线自己在 QL_FEAT_IMG_*
EMBED 占位盒 CSS_BASE 1px 边框 + 居中文字
任意包 + box-shadow / 渐变 / 模糊 / 动画 对应的 CSS_* 缺一个就报错，不静默丢效果

规则一句话：HTML5 包决定"这个标签能不能用"，CSS 包决定"它能不能被画得好看"， 两者都不满足时，报错信息里要同时点名（例： <dialog>: 需要 QL_FEAT_UI_CONTROL；它的 box-shadow 需要 QL_FEAT_CSS_SHADOW（本构建未启用））。

21.7 每个包的验收

一个新包落地时必须同时满足四条，缺一条就是"半个功能"：

  1. 关掉能编译：-DQL_FEAT_CSS_X=0 全量测试仍 60/60（用 lenient 或不用该特性）；
  2. 关掉会报错：写该属性时错误文案点名包名，且给出替代方案；
  3. 体积真的降：size build/libqlgl.a 前后对比，降幅记在包里；
  4. 两端一致：包开着时 test_gl_vs_cpu 逐像素一致（绘制类包强制）。

22. 五批计划

排序依据：先补"真实页面没它写不出来"的，再补"锦上添花"的；同一批内先做不动 QLUIStyle 的（只动解析期），后做动结构体的（要抬 blob 版本 + 重生成 golden）。

批 内容（对应上面各节） 归属能力包 收益 风险 动 QLUIStyle 验收
B1 值与尺寸（进行中：min/max-*、!important、hsl()、#rrggbbaa、currentColor/inherit/initial、em/rem/vw/vh、margin: auto 已完成；剩 calc()/min()/max()、border-radius 四角、aspect-ratio） min/max-*、em/rem/vw/vh、calc()/min()/max()、margin: auto、inherit/initial/currentColor、!important、border-radius 四角、aspect-ratio、hsl()、#rrggbbaa BASE（少量进 RADIUS） 真实页面的基础语法 中：动级联与宽度求解 是 → blob v16 新 test_css_units + golden
B2 选择器 :first/last/nth-child(an+b)/only-child/of-type、:not()、[attr] 系列、*、::before/::after+content、:disabled/:checked、::placeholder CSS_SELECTOR_ADV 兼容性收益最大（12.5% 声明 + 25% 选择器） 低：全在构建期展开，运行期零成本 否（伪元素在构建期变成真节点） 新 test_selectors + golden
B3 文本细节 letter-spacing、word-spacing、text-indent、text-transform、text-overflow: ellipsis、word-break/overflow-wrap、tab-size、text-decoration-* CSS_TEXT_ADV 列表、标题、长 URL 中：动 ql_text_wrap()（见 §20.3） 是 → blob v16 扩 test_text_wrap / test_white_space / test_textarea
B4 绘制细节 border-style: dashed/dotted、四边独立 border-*、多重/inset 阴影、outline、background-size/position、object-position、text-shadow、image-rendering、scrollbar-* CSS_BORDER_STYLE + CSS_SHADOW / CSS_GRADIENT 视觉还原度 中高：每个都要 CPU + GL 两份，必须过 test_gl_vs_cpu 部分 扩 test_effects + test_gl_vs_cpu
B5 布局与交互 align-self、align-content、order、flex-flow、overflow-x/y、position: sticky、inset、visibility、cursor、pointer-events、user-select、scroll-behavior CSS_FLEX 补全 + CSS_UI 表达力 + 桌面手感 中：动 flex 求解器与命中测试 是 扩 test_flex* / test_scroll

另外两项单独立项（成本与一批相当，但语义是"新子系统"）：

  • transform: rotate() / skew()：要一条旋转光栅路径（CPU 逐像素仿射 + GL 顶点变换 + 字形旋转 + 裁剪盒变换）。做完它，变换才算齐。
  • 真 group opacity：要离屏图层（见 §20.1）。现在的 opacity 是逐图元降透明。

建议顺序：B1 + B2 一起做（一次抬 blob 版本、一次重生成 golden），之后 B3 → B4 → B5， 中间可随时插入 rotate（对动效类页面它比 B5 更实用）。

23. 怎么新增一个 CSS 属性（检查清单）

照着走，漏一步就会留下"能解析但没生效"或"只在一个后端生效"的坑：

  1. 解析：src/ui/qlui_parse.c - 加进 k_supported_props[]（否则报"不支持的属性"）； - 写 parse_xxx()，错误文案要能定位（set_error("%s: ...", where)）； - 若要进关键帧，再加进 k_keyframe_props[]； - 若是简写，在 expand_shorthands() 里展开成长属性（简写本身不落结构体）。
  2. 字段：include/qlgl/qlui.h 的 QLUIStyle - 只在末尾追加；抬 QL_UI_BLOB_VERSION；tools/qltext 的 Python 侧同步。
  3. 生效： - 布局类 → layout_node() / flex 求解器； - 绘制类 → src/ui/qlui.c 的 render_node()，且同时改 src/draw/qldraw2d.c（CPU） 与 src/port/qlgfx_gl.c（GL）。
  4. 测试： - 语义类：新建/扩 test/web/test_*.c，命中与不命中两侧都断言； - 绘制类：扩 test_effects（CPU 像素）+ 跑 test_gl_vs_cpu（两后端逐像素一致）。
  5. golden：test_golden 基准图会变，重生成并逐张看差异（别一把 cp 过去）。
  6. 文档：本文对应行改状态；QLUI阅读指南 补"实现要点/踩坑"；教程给个最小例子。
  7. 裁剪：要能被 MCU 裁掉就加 QL_FEAT_CSS_* 宏，按 §21 的口径裁绘制路径， 并走 §21.7 的四条验收（关掉能编译 / 关掉会报错 / 体积真的降 / 两端一致）。
  8. 归包：把新属性填进 §21.2 的包表。新建包之前先问"它能不能并进已有的包" —— 包太多会让"给板子选开关"变成一件苦差事。
