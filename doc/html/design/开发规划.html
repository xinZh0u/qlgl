QLGL 开发规划

定位：CSS+HTML 的"GTK" —— 界面用 HTML/CSS 写，构建期编译成 C；绘制层 CPU/GPU 双后端； PC / 移动是第一平台，MCU 是第二平台；性能对标 LVGL，在小屏 CPU 光栅场景结构性轻于 GTK。

本文是排期与验收依据。每完成一个里程碑，必须同时更新 bench.md 与相关手册。

实现要点

  • 输入层不认识控件树：后端只 push，主循环 ql_input_dispatch() 统一派发， 因此无窗口也能自动化测试（example_input --demo 注入事件跑完整链路）；
  • 状态位沿父链设置，和 CSS 的 :hover 作用到祖先一致；
  • 按住拖动时事件仍发给按下目标（等价 DOM 隐式指针捕获），拖出控件再松手不会漏 UP；
  • 点击合成：同目标 + 位移 ≤ 4px；
  • 后端不再把 Esc 当关闭键，示例用 ql_win_bind_esc() 自己挂处理器。

顺带修掉的真 bug

  1. ql_object_set_parent 头插 + 渲染正序遍历 → 最后挂上的控件画在最下面， 与"后挂的覆盖先挂的"相反。改为追加到链尾（链表顺序 == 绘制顺序）。
  2. ql_ui_build 用 node_count 给样式下标做越界检查， 样式数一旦超过节点数就静默回落到 styles[0]。QLUIDoc 增加 style_count。

M2 · 文本质量（约 3 周）—— 已完成（2026-11-08）

目标：中文能看、任意字号、文本不再是 CPU 瓶颈。

任务 说明 状态
字体后端抽象 QLFontBackend + 可选的 glyph_bitmaps，静态位图字体与动态字体共用读取接口 ✅
FreeType 接入 ql_font_ft_load(path, face, px)；8bpp 灰度；TTC 自动挑简体字面 ✅
字形缓存 有序数组 + 每字形独立位图；上限 2048，满则拒绝新字形并告警 ✅
动态图集 GPU 侧 1024² R8 货架分配 + glTexSubImage2D 增量上传 + (字体,codepoint) 哈希 ✅
任意字号 ql_font_default(N) + font-size: Npx 全部走字号表 ✅
验收 test_font_ft（40 项）、中文示例页（CPU 与 GPU 输出一致）、example_gl_window 中文渲染 ✅

实现要点

  • 三条绘制路径（画布 / QLDraw2D / GPU 图集）都不区分字体类型， 只通过 ql_font_glyph_row() / ql_font_glyph_alpha() 取像素；
  • 内置位图字体仍在启动时一次性拼进图集（一次 glTexImage2D）， 动态字形才走增量上传 —— 首帧耗时反而从 1230µs 降到 1065µs；
  • MCU 可以直接关掉 QLGL_BUILD_FREETYPE，位图字体路径零依赖不变。

顺带修掉的真 bug

  1. GPU 字形 UV 缓存用字形数组下标做键，而动态字体的缓存表插入后要保持 按 codepoint 有序 —— 插入新字会把后面所有字形挪位，下标不稳定， 症状是"部分文字被画成别的字"。改成按 (字体, codepoint) 做键。
  2. 往 8bpp 图集搬 4bpp 位图时按 box_w 直接 memcpy，奇数宽度时 stride < box_w 会读越界（ASan 报 global-buffer-overflow）。 统一走 fetch_glyph_row()，非 8bpp 逐像素展开。
  3. 生成器把字体字节写成数字数组 { 228, 184, 173 }，-Wconversion 下报错； 改成带八进制转义的字符串字面量。

未纳入 M2（已登记）：自动折行、字距/行高精调、HarfBuzz 整形、 字重/斜体合成、字形 LRU 淘汰。

M3 · 布局表达力（约 4 周）—— 已完成（2026-11-08）

目标：能表达真实页面，不再"只能堆 div + margin"。

任务 说明 状态
flexbox display:flex、flex-direction（含 reverse）、justify-content（6 值）、align-items、flex-grow/shrink/basis、gap、flex-wrap ✅
定位 position: relative/absolute/fixed、top/right/bottom/left、z-index ✅
裁剪 overflow: hidden/auto（裁剪 + 命中测试同步裁剪） ✅
混合内容 <p>文字<b>粗</b>…</p> —— 生成期展开成匿名 inline 节点，运行期零改动 ✅
验收 test_flex（84 项几何断言，12 个用例页）；示例页改为真实 flex 布局；CPU/GPU 均验证 ✅

实现要点

  • flex 是"测量 → 分配 → 定位"三步；测量直接复用 layout_node（哑位置跑一遍）， 保证与 block/inline 路径的尺寸算法完全一致；
  • 全程零分配：信息暂存在子节点的 border_box 里，需要汇总时再遍历链表；
  • 最终尺寸写进 style_copy，复用既有的"运行期改写样式"机制；
  • z-index 在布局末尾对子链表做稳定排序，之后绘制与命中测试自动一致；
  • 混合内容在生成期消解成匿名 <span>，运行期数据模型不变。

顺带修掉的真 bug

  1. box-sizing: border-box 时显式高度被当成内容高使用，导致所有这类元素 被撑大一整个 padding + border（卡片高度 68 → 86）。宽度路径一直是对的， 高度路径漏了换算。
  2. style_copy 从不清除：flex 分配与绝对定位写进去的强制尺寸会带到下一帧， 视口变窄时表现为"尺寸不更新"。改为每次 ql_ui_layout 开头重置。
  3. QLUILength.value 是 uint16_t，top: -6px 变成 65530（badge 飞到 y=65741）。 改成 int16_t。
  4. 同一节点在一次布局里被 layout_node 调用两次（相对定位那段重复调用）， 已合并成一次。
  5. 命中测试原来按"数组下标倒序"扫，z-index 排序后与绘制顺序脱节。 改为与绘制同源的树遍历（子节点优先 + 后者覆盖 + overflow 裁剪）。

未纳入 M3（已登记）：滚动容器与滚动条、自动折行、align-self/align-content、 绝对定位的 "static position" 与完整 shrink-to-fit。

实现过程中真正花时间的五个细节（都写进《QLUIText阅读指南》）：

  1. 样式表身份 = 排序后的 (属性, 值) 字符串集合，不是编译后的结构体。 否则"两个声明不同但编出来一样"的节点会被合并，样式表条数就不同了。
  2. 简写必须在单条规则内展开（animation / transition / flex / gap / background / border）——级联合并后再展开会覆盖后出现的长写。
  3. 空文本池也要占一条：构建期工具用 text_ofs[] = { 0 } 占位，于是 text_count == 1 且池里是空串。
  4. Unicode 空白：Python 的 \s 认 U+3000 等；示例文本里就有一个全角空格， 漏掉它 blob 差 2 字节。
  5. box-shadow 的颜色提取顺序必须是 rgba() → #hex → 第一段字母， 顺序错了会把 1px 里的 px 当颜色。

顺带修掉一个真泄漏：pnode_free 只遍历 items，而 flatten 之后子节点在 first_child 链上——27 页跑完漏 76 KB。

文档：doc/手册/uitext/（阅读指南 + API 手册）；示例：test/uitext/example_load_text.c。

M5.1 的过程与结论（重要，改了这一节的原始设计）

原计划是"ql_coord_t 语义整体改成 26.6"。开工前先量了真实缺陷，结论是要分两步走：

  1. 先修真正的病根：flex / justify 的每一项都是"各自整除"， 余数被直接丢掉。实测 100px 分三个 flex:1 得到 33+33+33 = 99， 右边留 1px 空隙。这不需要定点，只要把分配改成累计推进： num += 总额 × 权重; 份额 = num / 权重和; num %= 权重和; 这样份额之和恒等于总额。改完实测 33+34+33 = 100，space-between 也精确落到行尾。
  2. 再决定要不要 26.6：查下来，"整数输入 + 整数输出"的布局里， 26.6 的额外精度只来自除法，而除法已被第 1 步解决。 其余精度损失来自样式表本身的表示（QLUILength.value 是 int16 整数 px / 整数百分比）， 要让 33.33% 或 margin: 5.5px 可表达就必须改 QLUIStyle → 改 blob 格式， 那是另一件事。 而 border_box 是 QLRect（设备像素整数）， 光栅化的落点本来就是整像素——26.6 在这里体现不出任何视觉差别。

所以 ql_coord_t 全局改 26.6 撤出 M5.1，改到 M5.3 与"边缘覆盖率 AA"一起做： 只有光栅化肯吃小数，定点才有意义。这样也避开了 424 处调用点的无收益风险。

剩下真正受益于 26.6 的地方只有两处，都记在 M5.3： ① 光栅化落点（边缘覆盖率）；② 字形前进宽（FreeType 给的就是 26.6， 现在被 adv_w = (slot->advance.x + 32) >> 6 取整，长行会累计漂移， 居中/右对齐会偏几个像素）。

M5.1 的验收：test_flex 新增第 12 组用例（test/web/flex/frac.*）： 100px÷3 的边界、space-between 的末项贴边、shrink 后无空隙，共 14 项断言。 原有 84 项全部保持通过（说明累计分配只改"除不尽"的情形）。

M5.2 的设计：缩放只在一处发生

单位三层，各管一段：

层 单位 谁负责换算
布局 / qlui / 控件 / 自定义绘制 CSS px 不换算，始终是 CSS px
QLDraw2D 后端入口（CPU 与 GL） 设备像素 唯一的换算点
驱动 flush(area) / 清屏 设备像素 每帧的 ql_ui_render*()

缩放系数是 26.6 定点（QL_SCALE_ONE = 1.0，96 = 1.5），挂在"表面"上： QLDispDriver.scale_fx → QLCanvas.scale_fx → QLDraw2D.scale_fx， GL 侧是 QLGfxGL.scale_fx。上层代码一行都不用改——这就是选这个设计的原因。

两条容易写错的地方：

  1. 矩形必须按"边"缩放（ql_scale_rect 用 ql_rect_right 算同一条边界）， 不能 x*scale + w*scale：相邻矩形各自算宽度会在接缝处裂开或重叠 1px。 （和 M5.1 的累计分配是同一个道理。）
  2. 文本要按设备字号重新取字体（ql_draw2d_device_font）：DPR>1 时 ql_font_default(css_px * scale)，否则字形会被拉伸糊掉。只有动态字体能真正 重取；位图字体在 MCU 上不缩放（固有限制）。

顺手修掉一个 GPU 的真 bug（重要）

写 DPR 测试时发现 GPU 后端和 CPU 差 28%，查下来是：本后端是单批次 （整帧一次 glDrawArrays），注释里写着"顶点已按最终 clip 画好"， 但 emit_quad / emit_quad_gradient / emit_shadow 从来没做这个裁剪， g->clip 只是存着。结果是 overflow:hidden 在 GPU 上完全没生效—— 测试页里那个 120×70 的子节点整块画了出来，正好多出 5422 像素。

修法：发顶点前把四边形范围与 g->clip 求交（clip_quad）， 但形状参数（hx/hy、radius、border、渐变跨度）必须继续用未裁剪的矩形， 否则片元里的 SDF 会算错——被裁掉的只是光栅化范围。 纹理四边形（字形）裁剪后按顶点位置线性插值重算 UV（图集 UV 是轴对齐的，插值精确）。

结果：CPU vs GL 从 28.24% → 0.77%（scale=1）/ 27.87% → 0.40%（scale=2）， 仍是单 draw call。

M5.2 的验收：test/web/test_dpr.c（22 项）： 1. 布局与 DPR 无关（两种 DPR 下 border_box 逐字段相同）； 2. scale=2 渲染后 2×2 盒式降采样 vs scale=1：0.57% 像素超差（门槛 3%）； 3. GPU 与 CPU 在 scale=2 下：0.40%； 4. ql_scale_rect 按边缩放：1.5× 下相邻矩形边界相接、设备→CSS 往返不丢像素。

M5.3 的设计：先把"能画在半个像素上"做出来

动画的"顺滑"本质是矩形边落在非整像素上也能画，所以这一步只加光栅化原语：

typedef struct { ql_coord_t x, y, w, h; } QLRectFx;   /* 设备像素 26.6 */

void ql_canvas_fill_rect_fx(...);        /* 面积覆盖率 AA */
void ql_canvas_fill_round_rect_fx(...);
void ql_canvas_stroke_rect_fx(...);

配一个绘制期平移，这就是动画的落点：

ql_draw2d_set_offset(d2d, x_css_26_6, y_css_26_6);   /* translate(0.5px) → 32 */
  • CPU：把矩形转成 QLRectFx 走覆盖率填充；
  • GPU：直接加进顶点浮点（本来就免费，且是精确的，比 CPU 更准）；
  • 不影响布局（与 CSS transform 语义一致）→ 滑动/缩放动画零重排；
  • 文本与阴影只吃偏移的整数部分（亚像素会让字形糊；阴影本来就软）。

三个关键实现选择，都是为了"不引入跳变"：

  1. 圆角跨度复用整数版 round_row_span，再把整像素跨度平移亚像素余量。 一开始用中心采样（直接算 SDF），结果圆角比整数版大将近 2px—— 动画跨过 0 时拐角会"突然胀一圈"。改用整数跨度后，对齐时逐字节相同。
  2. 整数矩形 = 低 6 位全 0 的 fx 矩形，覆盖率恰好全满 → 与整数路径逐像素相同。 这就是本次改造的安全阀（test_subpx 用 5 种矩形 × 4 种半径 × 3 种 alpha 对照）。
  3. 每行只在两端各多一次 put_px，中间整像素仍走 fill_row 的 SIMD 快路径， 所以亚像素不是"全逐像素"的代价。

缓动曲线能看到几个台阶（12px 的矩形从 0 移到 1px）：

整像素 1 个（直接跳过去）

  2. 进度不进布局：只覆盖 bg_color / bg_color2 / bg_alpha， 于是动画期间零重排，paint_box 不变，脏区就是这个节点自己的盒子。
  3. 隐式关键帧用"基础样式"补齐：@keyframes x { 50% { opacity: 0 } } 的首末帧 标成 QL_UI_KF_BASE，运行期取节点自己的基础样式——与 CSS 语义一致， 不需要为每个元素生成一份帧表。

明确报错（"不静默降级"）：关键帧里只允许 background / background-color / background-image / opacity / animation-timing-function；各帧的属性集合必须一致； animation-play-state: paused / steps() / cubic-bezier() 构建期拒绝 （animation-delay 在 ⑧ 里补上了，见下文）。 新增 test_qlui_errors（Python，16 个用例）守住这条线——它不需要编译，直接跑生成器。

与 transition 的优先级：同一节点两者都有时动画赢，trans_retarget 直接跳过 （动画已经占了颜色通道，再让过渡去改同一个通道只会互相打架）。

⑦ 完成：clip-path: circle() 子树圆形遮罩 —— 已完成

语义：clip-path: circle(<百分比>)，圆心固定在元素中心，百分比是最远角距离的千分比 （0% = 全裁，100% = 完全覆盖）。用千分比而不是 px 是因为揭示动画要走完整个过程—— px 半径会在动画早期就把元素盖满，剩下 90% 的时长"看起来没动"。

关键设计：在像素汇点上做遮罩，而不是为每个原语各写一遍。

后端 做法 为什么这样最省
CPU fill_row 把每行跨度与圆的水平范围求交（每行一次 sqrt），内层仍走 SIMD 快路径，两端各留一个像素给覆盖率；单像素走 put_px，alpha 乘圆覆盖率 fill_row / put_px 是全部图元（填充/圆角/渐变/阴影/字形）的共同汇点，只改 2 个函数就自动全覆盖
GPU 新增顶点属性 a_mask（设备像素的 cx, cy, r），在 emit_vertex（唯一出口）统一填；片元里 cov *= 1 - smoothstep(-0.5,0.5,length(gl_FragCoord-中心)-r) 所有 emit_* 都从 emit_vertex 出去，同样一处改动全覆盖；gl_FragCoord 要按 u_viewport.y 翻一次（GL 原点在左下）

顶点因此从 64 B 涨到 80 B（65536 顶点 ≈ 5.2 MB 静态），换来"遮罩对任何图元成立"。

约定："关闭"必须是 -1，不能是 0。 0 的语义是"遮罩存在但半径 0 = 全裁掉"， 这正是揭示动画的第一帧。这条约定踩了三次坑： 1. memset 出来的 QLCanvas/QLDraw2D 是 0 → 默认变成"全裁" → 整屏全黑； 2. GPU 侧只重置了 g->mask_r 没重置 g->draw.mask_r，render_node 收尾恢复时 用 0 又把遮罩打开了 → 除第一个节点外全部消失； 3. 顶点属性 a_mask 只写了 glDisableVertexAttribArray(6) 却忘了 glVertexAttribPointer(6, ...)，未绑定的属性默认值是 (0,0,0,1) → mr=0 → 全黑。

已知限制（刻意保留并告警）：只支持一层遮罩。嵌套 clip-path 的 CSS 语义是 "取交集"，而两个圆盘的交集不是圆盘，所以运行期保留外层并 QL_LOGW。

验收：test_clip 30 项——0% 零墨迹、100% 完全恢复、50% 圆内/圆外分明、 子元素伸出父盒子的部分被一起裁掉（这是"子树遮罩"与"只裁自己背景"的关键区别）、 遮罩 50% 时 CPU vs GPU 差 0.26%。

  1. 斜体不能用整数像素剪切：9px 高的小字整数剪切只有 1px，分摊到 9 行里每行 要么 0 要么 1，视觉上就是"没斜"。改成 1/16 定点后才像斜体。

⑱ 图像管线（<img>）—— 设计定案（2026-11-09）

完整设计见 图像管线设计。三条与"调库还是自己写"直接相关的决定：

  1. 自有解码器做 BMP / QOI / PNG / GIF（首帧），JPEG 交给平台后端。PNG 的难点只有 DEFLATE 一处，而它是无状态 纯算法（32KB 固定窗口、输出直接喂反滤波），可完全有界、可 fuzz；JPEG 是"一整套 色彩管线"，手写的失败模式是色偏而不是崩溃 —— 收益/风险完全不划算。
  2. 不分平台，只分开关（Linux Kconfig 那套）：每个能力一个宏、互不互斥、组合都合法。 QL_FEAT_IMG_BMP/QOI/PNG 各自可裁，QL_FEAT_IMG_PLATFORM（JPEG/GIF）想编就编、想砍就砍， 砍掉后遇到该格式明确报 QL_ERR_UNSUPPORTED。"PC 配置 / MCU 配置"只是预设 （full / lean / raw-only），起手不同，随时可单品覆盖。 零解码路径（构建期转出 RAW，px 直指 .rodata、owned=0）是任何平台都可选的一档， PC 上用它同样划算：换"启动零解码 + 像素完全确定"。
  3. stb_image 不进产线（7k 行不可裁、整幅 malloc、顺带扩大攻击面），只当测试对拍。

其余要点：node->text 复用为资源名（不加节点字段）；w/h 存进 doc，所以布局不依赖 解码；object-fit 在绘制期算、不动布局；blend 与现有 fill_rect(alpha) 同一套； MCU 的推荐姿势是 RAW + 指向 Flash（owned=0，RAM 为 0）。

分期：P3a ✅ 基础设施（3–4 天） → P3f ✅ 工具链（1.5–2 天） → P3b ✅ BMP/QOI（1 天） → P3d ✅ object-fit + 圆角裁剪（1 天） → P3e ✅ <map>/<area> 热区 + picture/source（0.5 天） → P3c ✅ PNG（3–4 天） → P3g ✅ 平台后端 + GIF 首帧（1 天），合计 12–15 天。 P3a + P3f 就打通"图片文件 → 构建期转码 → 固件里显示"这条必达路径。

P3c 的两条要点：IDAT 是 zlib 流（2 字节头 + Adler-32，不是裸 DEFLATE）， ql_inflate 不分配滑动窗口（输出缓冲本身就是窗口，额外 RAM 为 0），输入走流式回调 所以多个 IDAT 零拷贝；test_png 用现场构造的 stored 块 PNG 覆盖 15 组 (颜色类型, 位深) 与 5 种 filter，test/assets/png 用 PIL 生成的真实压缩流对拍， test_png_fuzz 4700 例随机/变异输入在 ASan 下只允许"返回失败"。

P3g 的两条要点：平台后端接口永远在（几十字节），调度是"自有解码器优先、 返回 UNSUPPORTED 才问后端"，所以后端抢不走原生格式，但能补上原生不做的分支 （隔行 PNG 就是一例）；libjpeg 的 error_exit 必须换成 longjmp —— 默认实现是 exit(1)，一张坏图会带走整个应用，参考实现里还额外把 "数据提前结束"（libjpeg 会把缺的行填灰）判为失败。

GIF 改成了自有实现：静态 GIF 只是"调色板 + LZW + 隔行"，和 QOI 同难度、 无色彩管线（写错的后果是解不出来，不是颜色不对）；giflib 又不像 libjpeg 那样到处都有。动画仍然不做，只取首帧 —— 初稿把它推给平台后端的理由就是动画。

P3e 的两条要点：热区几何在构建期定型（usemap ↔ <map name> 在解析末尾配对， 存下 <img> 节点序号），运行期只做一次"屏幕点 → 图片像素"的整数换算； blob 升到 v14（areas / area_coords 两段，不需要热区时 0 字节）。

⑩ line-height —— 已完成（2026-11-08）

继承 进 k_inherited，与 font-size 同等待遇
排版入口 只有一个（ql_draw2d_text_layout），CPU/GPU 共用，所以 draw_text 多了一个 line_h 参数

⑨ 毛玻璃 backdrop-filter: blur() —— 已完成

唯一会"回头读自己画过的东西"的效果。数据侧几乎零成本：QLUIStyle 加一个 uint8_t backdrop_blur（塞进原 padding，116 字节不变，blob v9 → v10）； render_node 里在"画自己的背景之前"插一句调用。

后端 做法 代价（实测）
CPU 画布就地模糊：取区域 → 两趟 H/V 滑动窗口盒式卷积（每像素 O(1)）→ 写回 108×56 卡片 0.159 ms；300×200 1.68 ms（整屏重绘是 0.304 ms）
GPU 中途 flush 一次批次 → glBlitFramebuffer 降到半分辨率 → H/V 两趟 9 抽头 → mode 4 画回 额外 1 个 draw call、6 个顶点、两块半分辨率 RGBA8

这一步打破了"单批次"这条性能红线，所以把提交动作抽成 flush_batch(g)： 正常帧仍然只被 end() 调一次（行为完全不变），毛玻璃自己先 flush 再继续摞顶点。

GPU 侧三个"错了就整块黑"的坑（都写进 QLRender阅读指南 §15）： u_bg 采样器没绑东西 = 未定义值；忘了还原 FBO/视口 = 后续全画进半分辨率缓冲； 纹理上下颠倒 = 玻璃里出现倒影。

两条后端故意不一致：CPU 全分辨率盒式、GPU 半分辨率高斯近似 → test_blur 不比逐像素，只断言性质：玻璃内出现一长串"中间色"（硬边摊开了）、 玻璃外一个中间色都没有（模糊不外溢）、半透明玻璃自己叠在模糊结果上。 实测 CPU 13 个中间色像素 / GPU 7 个。

6. 架构红线（写进规范，防止走偏）

红线 原因
不做保留式场景图 / render tree 那会变成 GTK4 的 GSK，每帧重建节点，性能优势全丢
不做运行期 CSS 匹配 样式在构建期消解，这是性能与体积的根基。M3.5 的运行时解析是"加载时算一次"，不是每帧匹配，且解析器可整块摘掉
不做 DOM API / JS 引擎 任何平台都不做，也不嵌 WebView —— 全平台同一套自绘（Web兼容设计 §6/§7.3）
不与 Qt/GTK 比功能广度 只做 UI；可访问性、IME、多媒体不做
不允许静默降级 不支持的 CSS/HTML 必须构建期报错
稳态零 malloc 所有热路径预分配；新增分配要有断言兜底
外来数据必须有界 静态 doc 是编译器常量；.qlui 与将来的 HTML/CSS 文本是外来字节，所有计数/递归都要有 QL_CFG_UI_MAX_* 上限
明确失败优于半个正确 加载失败一律返回 NULL + 带原因的错误，禁止"跳过坏数据继续画"
混用单位是面板 doc 之间是 uint16 下标，跨 doc 引用物理上不存在；不做元素级混合
动画必须走脏区 PC 上可以整屏重画（占预算 14%），MCU 上没有这个余量。第一版就做对，否则 MCU 路堵死
不打破"单批次"除非有里程碑授权 毛玻璃是唯一会打破它的特性，且必须作为可选编译开关
同一份源，两个平台 能力差异靠 qlui --platform 的构建期降级报告表达，不靠 #ifdef 满天飞；"不静默降级"依然成立

顺带修掉一个真 flex bug（有回归测试）

写 03_layout 时发现 .btn { width: 56px } 被压成 24px：

flex 项的 width: auto 被当成 block 布局的"撑满包含块"。于是空的 flex-grow: 1 占位块基准尺寸 = 整个容器宽 → sum_base 超过容器 → 算出一份负剩余空间 → 触发 shrink → 把旁边固定宽度的兄弟一起压扁 （实测 40px→29px、56px→40px）。

修法：新增 max_content_main()，在 measure_flex_items() 里先把 auto 主轴尺寸 按 max-content 落成显式值（空盒子 0 / 只有文本取文本宽 / 有子节点按主轴求 和或取最大）。注意不能顺手把 box_sizing 改成 1 —— 那会把同一项的交叉轴 也算错（带 1px 边框的 20px 格子从 22 变 20，test_golden 的 bench100 当场红）。

test/web/test_flex_auto.c（15 项）钉住这条语义：固定宽不被压、空 auto 项基准为 0、 文本项基准是文本宽、flex-basis 显式给了就不用 max-content、content-box 不变。
