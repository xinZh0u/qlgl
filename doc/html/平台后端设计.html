设计文档

平台后端设计（QLPlatform）

目标：应用只写 qlglinit() + qlwindow，平台差异（X11 / Wayland / MCU 板级） 全部收在一张回调表里。QLWindow 不知道底下是什么，只调 QLPlatform。

应用
 └─ QLWindow（主循环、输入汇、IME/剪贴板、脏区重绘）
     └─ QLPlatform（窗口/显示、事件泵、绘制呈现）
         ├─ 桌面：X11/Wayland + GL 或 CPU 光栅
         └─ MCU ：板级显示 flush + 按键/触摸 + tick

1. 回调表

typedef struct QLPlatform {
    const char *name;

    QLPlatformWindow *(*window_open)(const char *title, ql_coord_t w, ql_coord_t h,
                                     int backend);
    void (*window_close)(QLPlatformWindow *pw);

    int  (*poll)(QLPlatformWindow *pw);          /* 1 = 继续，0 = 已关 */
    int  (*wait)(QLPlatformWindow *pw, int timeout_ms);
    /* 每窗口输入实例（多窗口）；不实现 = 退回进程默认队列（单窗口） */
    void (*set_input)(QLPlatformWindow *pw, QLInput *in);
    void (*size)(QLPlatformWindow *pw, ql_coord_t *w, ql_coord_t *h);
    int  (*resize_pending)(QLPlatformWindow *pw);

    int  (*begin)(QLPlatformWindow *pw, ql_color_t bg, const QLRect *dirty, int n);
    QLDraw2D *(*draw)(QLPlatformWindow *pw);
    void (*end)(QLPlatformWindow *pw);

    void (*set_vsync)(QLPlatformWindow *pw, int on);
    int  (*dump_ppm)(QLPlatformWindow *pw, QLUIRoot *ui, ql_color_t bg,
                     const char *path);

    void (*attach_clipboard)(QLPlatformWindow *pw, QLUIRoot *ui);
    void (*attach_ime)(QLPlatformWindow *pw, QLUIRoot *ui);
    void (*set_ime_spot)(QLPlatformWindow *pw, ql_coord_t x, ql_coord_t y,
                         ql_coord_t h);
    void *(*native)(QLPlatformWindow *pw, const char *what);   /* "gl" */
    uint32_t (*frame_us)(QLPlatformWindow *pw);
    uint32_t (*swap_us)(QLPlatformWindow *pw);
} QLPlatform;

begin(..., dirty, n)：n == 0 表示整屏；返回 1 表示后端要求整屏重画。 CPU 后端在 begin 里清脏区、end 里把脏区 flush 给显示驱动即可。

set_input 是可选能力：实现了它的后端（桌面 X11 / Wayland / GL）会为每个 QLWindow 创建一条独立的 QLInput，事件只进自己窗口的队列；没实现的后端 （假平台、MCU 板级）退回进程默认队列，行为与单窗口时完全一致。 多窗口要求后端必须实现 set_input，并且绘制前要切回自己的 GL 上下文 （qlgfx_gl 用 eglMakeCurrent 做这件事）。

2. 选择后端

  1. 应用在 qlgl_init() 之前调 qlgl_set_platform(&my_platform)（测试/模拟器/多后端）；
  2. 否则用 qlgl_platform_default()（弱符号）： - 桌面构建：ql_platform_desktop()（X11 → Wayland → 内存离屏；GL 或 CPU）； - MCU：板级文件定义同名强符号，覆盖弱符号：
/* port/myboard/qlplatform_board.c —— 链接进来即可，应用层不用改 */
const QLPlatform *qlgl_platform_default(void) { return &board_platform; }

QLWindow 通过 qlgl_platform() 取当前后端；桌面默认后端已包含 GL 与 CPU 两套。

3. MCU 板级实现（已跑通）

仓库里有一份可编译、可运行的完整实现： test/mcu/qlplatform_board.c。它不是文档示例，而是 test/mcu/build.sh window 真正链接进去的后端（QEMU mps2-an386 / Cortex-M4，无 OS、无文件系统）。

typedef struct {
    QLDispDriver disp;       /* ql_disp_init_fb：静态 RGB565 帧缓冲 */
    QLCanvas     canvas;
    QLDraw2D     d2d;
    QLRect       flush;
    int          full;
} BoardWindow;

static BoardWindow s_win;              /* 单屏：静态对象，零分配 */

static QLPlatformWindow *board_open(const char *title, ql_coord_t w, ql_coord_t h,
                                    int backend)
{
    (void)title; (void)backend;
    if (s_open) return NULL;           /* 一进程一屏（输入汇是单例） */

    BoardWindow *b = &s_win;
    if (ql_disp_init_fb(&b->disp, s_fb, QL_BOARD_W * 2u, w, h,
                        QL_COLOR_RGB565, board_flush) != QL_OK)
        return NULL;
    ql_canvas_from_disp(&b->canvas, &b->disp);
    ql_draw2d_canvas_init(&b->d2d, &b->canvas);

    ql_anim_set_time_source(ql_board_now_ms);   /* 裸机没有 clock_gettime */
    board_clock_init();                         /* SysTick 1ms */
    s_open = 1;
    return (QLPlatformWindow *)b;
}

三件板级专属的事：

事情 做法 为什么
时间 SysTick 1ms 中断累加 s_ms，ql_anim_set_time_source() 指过去 裸机没有 clock_gettime；QLWindow 的 --seconds/帧统计会自动退回毫秒时间源
输入 中断只入环形队列，poll() 里搬进 ql_input_push_* ISR 里不能分配、不能和主循环抢队列
空闲 wait() 里 WFI SysTick 每 1ms 一次中断，静止时省电且零轮询

begin/draw/end 与桌面 CPU 后端同构：清脏区 → ql_ui_render* → flush(area)； flush 在真板子上是 SPI/DMA，测试里是拷进另一块内存（模拟"屏幕上现在显示的内容"）。

两个容易踩的坑（这次都踩了）：

  1. 向量表下标：SysTick 是异常 15 → 表里第 16 项（索引 15）。 少写一项会让 SysTick 跳到 0 地址 → HardFault → 默认 handler 的 wfi 死循环， 现象是"程序卡住、没有输出"。test/mcu/startup.c 里有完整注释。
  2. QLWindow 的统计缓冲：--stats 的采样数组现在按需分配（1024 帧 × 3 组 ≈ 12KB）， 否则 48KB 的 MCU 堆在 ql_window_create() 里就没了。

另一个与平台无关但影响 MCU 链接的点：qlui.c 里保留了运行期解析入口， 会引用 qlui_parse.c 的符号。MCU 构建必须开 -ffunction-sections -fdata-sections + -Wl,--gc-sections，让没被引用的 ql_ui_load_html* 整段丢掉（test/mcu/build.sh 已经默认打开）。

4. 桌面 CPU 光栅

QLPlatform 的默认桌面实现里 window_open(..., QL_WINDOW_CPU) 走：

  • ql_disp_x11_create()（X11）或 ql_disp_wayland_create()（Wayland）；
  • ql_canvas_from_disp() + ql_draw2d_canvas_init()；
  • begin 清脏区、end 调驱动 flush() / flush_done()；
  • 窗口缩放：resize_pending 里重建画布，QLWindow 重新布局；
  • resize()：X11 用 XResizeWindow（异步），Wayland 返回 QL_ERR_UNSUPPORTED；
  • 剪贴板：Wayland 与 X11 都接到 QLUIClipboard（X11 走 qlclipboard_x11.h）； 状态是每窗口一份（QLClipX11 / QLWlWindow），多窗口时各用各的 Display/Window，不会互相覆盖。

调试：QLGL_WINDOW_CPU=1 ./example_00_hello 强制走 CPU 路径，用来和 GL 对照。

5. 测试

test/web/test_window_fake.c 用假平台（内存显示 + 脚本输入）验证桌面侧行为：

  • qlgl_set_platform(&fake) 后 ql_window_create() 走假后端；
  • ql_window_poll() 把输入队列派发到界面层并触发点击回调；
  • ql_window_dump_ppm() 写出非空 PPM；
  • ql_window_set_ui() 换界面、ql_window_quit() 退出；
  • ql_window_resize() → 后端重建画布 → resize_pending → 重新布局。

MCU 侧是 test/mcu/window.c，在 QEMU 里跑同一套 QLWindow：

./test/mcu/build.sh window        # 编译 + 在 QEMU 里跑，PASS/FAIL 看输出
./test/mcu/build.sh window --no-run   # 只看 ROM/RAM

它验证的是"无 OS 也能用高层 API"：
