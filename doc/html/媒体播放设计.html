设计文档

媒体播放设计（<audio> / <video> / <track>）

这份文档定四件事：播放引擎怎么分层、时钟和线程谁说了算、 帧怎么落到 CPU/GL 两个后端、<track> 和容器字幕分别归谁。 和图像管线一样，红线是外来数据必须有界：媒体文件是典型的"不可信、可畸形、 可能很大"的输入，任何一条路径都不许 OOM、越界或死循环。

状态：设计草案（2026-11-15）。目标读者：要实现媒体后端、音视频输出、 字幕轨与 <video> 布局/绘制的人。 相关：平台后端设计（回调表套路）、 图像管线设计（外来数据必须有界、blit_image）、 HTML5 标签覆盖与裁剪（现状：三个标签都还是占位）。

0. 结论摘要

问题 决定
用什么解码 FFmpeg（libavformat / libavcodec / libavutil / libswscale / libswresample），默认后端，运行期可选
自己写吗 不写。容器解析 + 编解码器 + 重采样都不是这个库该做的事
分层 QLMedia（状态机/时钟/队列）+ QLMediaBackend（解码接缝）+ QLAudioSink（音频设备接缝），与 QLPlatform 同一套路（弱符号 + ql_*_set_backend()）
线程 每个 QLMedia 一个工作线程（demux + 解码 + 预填充），UI 线程只取"最新一帧"和"已解码 PCM"
A/V 同步 音频设备时钟为主；没有音频/没开声音时用 CLOCK_MONOTONIC；视频迟到超过 ~80ms 直接丢
视频呈现 CPU 后端：sws_scale 到画布格式；GL 后端：三平面纹理 + BT.601/709 矩阵 shader（不落 CPU）
音频输出 一期 ALSA；PulseAudio / WASAPI / AAudio 作为后端补充；回调里只做环形缓冲拷贝
<track> 和 FFmpeg 无关：WebVTT 解析 + 按时间取 cue + 由 QLUI 画 overlay
容器内嵌字幕 FFmpeg 的 subtitle stream，走同一条 overlay 通道（与 <track> 并列，优先级：用户选的轨 > 容器默认）
现状兼容 没有媒体能力/没有后端时，<video>/<audio> 仍退回现有"占位盒"，页面不炸
MCU QL_FEAT_MEDIA=0（默认）。将来可以是"只解 MJPEG + PCM"的极简后端，不链 FFmpeg
许可 FFmpeg 默认 LGPL-2.1+；不要开 --enable-gpl，否则整库变 GPL

1. 目标与非目标

目标

  1. <video src> 能播本地文件，画面进 QLUI 的盒子（object-fit / 圆角 / 裁剪复用现有路径）， 有声音、有进度、能暂停/拖动/循环，卡顿时丢帧而不是越拖越晚。
  2. <audio src> 只出声、不占布局（与浏览器一致：<audio> 无 controls 时没有盒子）。
  3. <track kind=subtitles src=x.vtt> 能按时间显示字幕，样式走最小子集（颜色/字号/底）。
  4. 解码在后台线程，UI 线程永不阻塞；静止（暂停）时零解码、零唤醒。
  5. 外来输入有界：尺寸、时长、码率、队列深度都有上限；畸形文件只报错，不崩。

非目标（明确不做）

  • controls 原生控件（播放条）。本库的哲学是"界面用 HTML/CSS 写"， 播放条就是一个 <div> + 几个按钮；一期只提供事件和 API，不画控件。
  • HLS / DASH / DRM。一期只做"一个 URL/路径 = 一个文件"。
  • 录制、摄像头（getUserMedia）、屏幕捕获。
  • 视频编码。只解不编。
  • 多路视频同屏（画中画/分屏）。一期限制 QL_CFG_MEDIA_MAX_STREAMS（默认 2：1 视频 + 1 音频）， 多实例留接口但不保证。
  • requestVideoFrameCallback、MediaSource、Web Audio API。
  • 硬件解码一期不做（接口留 hw 字段；VAAPI/VideoToolbox 二期）。
  • 动画 GIF/APNG（图像管线已有结论：只取首帧）。

2. HTML 语义与元素模型

2.1 三个标签的现状与目标

标签 现在 目标
<video> QL_UI_TAG_VIDEO，占位盒，子内容不渲染 替换型元素：固有尺寸来自媒体（默认 300×150），有画面、有事件
<audio> QL_UI_TAG_AUDIO，矮占位盒 零盒子（display:none 语义），只出声；controls 也由应用自己写
<track> QL_UI_TAG_TRACK，display:none 保持 display:none；但构建期要把它挂到父 <video>/<audio> 的轨道表上

迁移注意：<audio> 从"矮占位盒"改成"无盒"会改变现有页面的布局。 关闭媒体能力（QL_FEAT_UI_MEDIA=0）时保留旧行为（占位盒）， 打开时按浏览器语义走。

2.2 属性（一期认这些，其余忽略）

元素 属性 语义
<video> / <audio> src 本地路径或 file://；构建期原样存进文本池，运行期由 QLMedia 打开
poster 视频首帧出来前显示的图（资源名，复用 <img> 的资源表）
width / height 覆盖固有尺寸（CSS width/height 仍然优先，走盒模型）
muted / volume 音量
loop 播完回 0
autoplay 允许自动播放；桌面默认尊重该属性，移动端由应用决定
preload none / metadata / auto（默认 metadata：只读头，不解码）
playsinline 认下来但无操作（没有全屏概念）
<track> kind subtitles / captions / descriptions / chapters / metadata；一期只渲染 subtitles/captions
src WebVTT 文件（.vtt）
srclang / label / default 轨道选择
<source> src / type 多个候选源：一期只取第一个能打开的（按顺序尝试）

没有 JS：所以没有 video.play()。控制走 C API（§9）， 页面里的按钮通过 ql_ui_set_click_cb 回调到应用，应用再调 ql_media_play()。 这也是"HTML 写界面、C 写逻辑"的分工，和现有事件/输入模型一致。

2.3 资源从哪来

  • 不在构建期转码：视频动辄几十 MB，塞进 C 数组不现实。 qltext 只把 src 当字符串存下来（和 <img> 的资源名同一个文本池）。
  • 小音频（提示音）可以走 <img> 那套"构建期嵌入"：qltext --embed-media name=file， 产物是字节数组，运行期 ql_media_open_mem()。一期先只做路径，嵌入二期。
  • 找不到文件 = QL_ERR_IO + 明确日志 + 占位盒（不崩、不猜）。

3. 能力开关与预设

沿用"能力正交、各自可裁、组合都合法"的规则（与图像管线一致）。

能力 宏 默认 关掉的后果
<video>/<audio> 标签 QL_FEAT_UI_MEDIA 1（桌面）/ 0（MCU 预设） 三个标签回到占位盒/display:none
播放引擎核心 QL_FEAT_MEDIA = QL_FEAT_UI_MEDIA 没有 QLMedia，标签永远占位
FFmpeg 后端 QL_FEAT_MEDIA_FFMPEG 构建期找到 FFmpeg 才 1 只能用注册进来的其他后端（或没有）
视频通路 QL_FEAT_MEDIA_VIDEO = QL_FEAT_MEDIA <video> 只出声/只显示 poster
音频通路 QL_FEAT_MEDIA_AUDIO = QL_FEAT_MEDIA 静音播放（时钟退回系统单调钟）
WebVTT 字幕 QL_FEAT_MEDIA_WEBVTT = QL_FEAT_UI_MEDIA 无 <track> 渲染，容器字幕也不显示
网络流 QL_FEAT_MEDIA_NET 0 只允许本地路径
硬件解码 QL_FEAT_MEDIA_HW 0（二期） 恒软解

容量与队列（qlconfig.h）：

宏 默认 含义
QL_CFG_MEDIA_MAX_STREAMS 2 每实例最多几路流（1 视频 + 1 音频）
QL_CFG_MEDIA_FRAME_POOL 4 视频帧池大小（同时存活的帧数）
QL_CFG_MEDIA_VIDEO_QUEUE 3 解码完成待呈现的帧数上限
QL_CFG_MEDIA_AUDIO_QUEUE 8 已解码 PCM 块数上限
QL_CFG_MEDIA_MAX_DIM 8192 单边像素上限（防"4K 视频"变炸弹）
QL_CFG_MEDIA_MAX_PIXELS 4096×2160 总像素上限（解码前用容器信息挡）

4. 分层与接缝

QLUI（<video>/<audio>/<track> 三个元素、布局、overlay）
  └─ QLMedia（一个媒体实例：状态机、时钟、队列、事件）
       ├─ QLMediaBackend  ← 解码接缝（ffmpeg 默认；MCU 可换 MJPEG）
       │     · open/close/seek/read_video/read_audio
       │     · 输出 QLMediaVideoFrame（YUV 平面 + pts）与 PCM 块
       ├─ QLAudioSink     ← 设备接缝（ALSA 默认；Pulse/WASAPI/AAudio）
       └─ 时钟：音频设备时钟 / 系统单调钟

和 QLPlatform 完全同构：

/* 应用/板级覆盖；不设置就用默认（桌面 = ffmpeg + ALSA） */
void ql_media_set_backend(const QLMediaBackend *backend);
const QLMediaBackend *ql_media_backend(void);

/* 弱符号：MCU 板级文件定义同名强符号即可覆盖 */
const QLMediaBackend *ql_media_backend_default(void);
const QLAudioSink    *ql_audio_sink_default(void);

为什么要有接缝：FFmpeg 在 MCU 上完全不成立（体积、浮点、文件系统）。 把"解码"和"出声"关在 vtable 后面，QLMedia 的时钟/队列/状态机就能被 一个假后端完整测掉（见 §12），将来换 MJPEG/ADPCM 也不用动 UI 层。

5. 一次播放的数据流

ql_media_open(path)
   │  读容器头（不解码）：时长、流数、尺寸、帧率、采样率
   ▼
ql_media_play()
   │
   ├─ 工作线程 loop：
   │    av_read_frame → 视频包队列 / 音频包队列（有界，满了就阻塞）
   │    视频解码 → 帧池取一块 → 解码进 YUV 平面 → pts 入"待呈现"
   │    音频解码 → swr_convert → 16bit 立体声 → SPSC 环形缓冲（给设备回调）
   │
   ├─ 音频设备回调（独立线程）：
   │    从环形缓冲取 N 帧 → 写设备；欠载补静音并记一次 underrun
   │
   └─ UI 线程（每帧）：
        ql_media_acquire_frame() → 拿到"该显示了"的最新帧（或 NULL）
        → CPU: sws_scale → canvas blit / GL: 上传三平面 + shader
        → 释放帧（还池）

边界规则

  • 队列全部有界：包队列 8、视频帧 3、音频块 8。满了让工作线程阻塞，而不是吃内存。
  • 帧池固定 QL_CFG_MEDIA_FRAME_POOL 个，acquire_frame() 不阻塞； 没有新帧就返回 NULL（上一帧继续显示）。
  • 音频回调里不分配、不加锁：只用无锁 SPSC 环形缓冲（读写下标原子推进）。
  • UI 线程不做 av_* 调用，也不做 sws_scale（GL 后端连转换都不做）。

6. 时钟与 A/V 同步

6.1 主时钟

场景 主时钟
有音频且没静音 音频设备时钟：pts_played = 写入设备的字节数 / 每秒字节数 - 设备缓冲延迟（ALSA 用 snd_pcm_delay()）
无音频 / muted / 音频后端打开失败 CLOCK_MONOTONIC，从 play() 起算，暂停时冻结
暂停 时钟停走；恢复时把基准点后移暂停时长

对外暴露：

int64_t ql_media_clock_us(const QLMedia *m);   /* 当前播放位置（微秒） */

6.2 视频呈现策略

pts <= clock + 5ms        → 立刻呈现
clock + 5ms < pts < +80ms → 等（UI 层把下一帧时间告诉主循环，别空转）
pts < clock - 80ms        → 丢帧（跳过，不呈现），并记一次 late_drop
  • 连续丢帧超过 ~500ms：重新对齐（把时钟基准挪到该帧 pts），避免"永远追不上"。
  • 60fps 视频要求主循环能 16ms 醒一次：QLWindow 现在的空闲等待固定 32ms， 需要新增"下一个截止时间"查询（动画 + 媒体共用）：
/* QLUI 侧汇总：动画 / 媒体 / 光标闪烁，谁最近就返回谁；没有返回 -1 */
int ql_ui_next_deadline_ms(const QLUIRoot *ui);

ql_window_poll() 的 wait(timeout) 取 min(32, deadline)。

6.3 拖动（seek）

ql_media_seek(ms)

工作线程收到命令后：avformat_seek_file(...) → avcodec_flush_buffers() → 清空包/帧队列 → 重置音频环形缓冲 → 时钟基准改到目标 pts。 seek 期间 UI 继续显示旧帧（不清屏），直到新帧到达。

7. 视频呈现：两个后端

7.1 帧的表示

typedef struct QLMediaVideoFrame {
    int32_t  w, h;
    int64_t  pts_us;
    uint8_t  format;        /* QL_MEDIA_FMT_YUV420P / NV12 / RGB565 / RGBA8888 */
    uint8_t  planes;        /* 1~3 */
    uint8_t *data[3];
    int32_t  stride[3];
    int      refs;          /* 帧池引用计数 */
    void    *pool;          /* 归还用 */
} QLMediaVideoFrame;

永远是"借用"：ql_media_acquire_frame() 返回带引用的帧，画完必须 ql_media_frame_release(frame)，否则帧池耗尽、解码线程阻塞（这是设计上的背压）。

7.2 CPU 后端

  • sws_scale 到画布的 QLColorFormat（RGB565/RGB888/ARGB8888）。
  • 尺寸不匹配时同时做缩放（SWS_BILINEAR）；object-fit 的裁剪在 QLUI 层做。
  • 代价：1080p @60 每帧约 2~5ms（桌面 x86），720p 约 1~2ms。 MCU 档不提供该路径（QL_FEAT_MEDIA=0）。
  • 目标矩形每一帧都要标脏：视频盒子的 QLRect 入脏区，走现有局部重绘。

7.3 GL 后端

  • 三个平面各上传一张 GL_LUMINANCE（GLES3 用 GL_R8）纹理， 只在 pts 变化时上传（同一帧重复绘制不重复传）。
  • 片元着色器做 BT.601/709 矩阵 + object-fit 的 UV 变换； 色彩范围（limited/full）从容器/解码器元数据取，取不到按 limited。
  • 圆角/裁剪复用现有的 SDF + mask，不做第二套。
  • 与"保留式脏区"的交互：视频区域每帧必然脏，因此含视频的窗口实际是每帧重绘该矩形； 静止（暂停）时回到零重绘。

7.4 poster 与首帧

  • poster 有值：解码前显示图片（复用图像资源表）。
  • 没有 poster：显示空白（透明）而不是黑块——黑块会让人以为"加载失败"。

8. 音频输出

8.1 接口

typedef struct QLAudioSink {
    const char *name;
    int  (*open)(void **out, int rate, int channels, int format, int period_frames);
    void (*close)(void *ctx);
    int  (*start)(void *ctx);            /* 回调开始拉数据 */
    void (*pause)(void *ctx, int paused);
    /* 设备回调：buf 里填 frames 帧，返回实际写入帧数；欠载返回 0 */
    int  (*write)(void *ctx, const void *buf, int frames);
    int  (*delay_frames)(void *ctx);     /* 设备里还剩多少帧没播（做时钟用） */
    void (*set_volume)(void *ctx, int percent);
    /* 内部：由 QLMedia 注册的"要数据"回调 */
    void (*set_pull)(void *ctx, int (*pull)(void *, void *, int), void *user);
} QLAudioSink;
  • 一期实现：ALSA（snd_pcm_*），SND_PCM_FORMAT_S16_LE、立体声、 48kHz 优先（设备不支持就 swr 转）。
  • 设备打不开：QL_FEAT_MEDIA_AUDIO 仍在，但实例退化成"静音 + 系统时钟"， 打一条 QL_LOGW（不是错误——蓝牙耳机没连上也应该能播视频）。
  • 音量在 swr 之后乘（S16 乘法带饱和），或交给 ALSA 的 softvol；一期用前者， 保证所有后端行为一致。

8.2 欠载与漂移

  • 欠载（underrun）：补静音，累计计数；连续欠载说明解码跟不上 → 日志一次。
  • 时钟漂移：音频时钟与系统时钟的偏差不主动纠正；视频追音频。
  • 设备热插拔：一期不管（ALSA 默认设备重开）；二期加 snd_pcm_recover + 重建。

ql_err_t ql_media_set_volume(QLMedia *m, int percent);   /* 0~100 */
void     ql_media_set_muted(QLMedia *m, int muted);
void     ql_media_set_loop(QLMedia *m, int loop);

/* ---------- 状态（UI 每帧读，都是常量时间） ---------- */
int64_t ql_media_duration_ms(const QLMedia *m);
int64_t ql_media_position_ms(const QLMedia *m);
int     ql_media_state(const QLMedia *m);   /* QL_MEDIA_IDLE/OPENING/READY/PLAYING/PAUSED/ENDED/ERROR */
int     ql_media_has_video(const QLMedia *m);
int     ql_media_has_audio(const QLMedia *m);

/* ---------- 视频帧 ---------- */
QLMediaVideoFrame *ql_media_acquire_frame(QLMedia *m);   /* 不阻塞；无新帧 NULL */
void ql_media_frame_release(QLMediaVideoFrame *f);
int  ql_media_frame_wait_ms(const QLMedia *m);           /* 下一帧还有多久（喂 wait） */

/* ---------- 字幕 ---------- */
int  ql_media_track_count(const QLMedia *m);
int  ql_media_set_track(QLMedia *m, int index);          /* -1 = 关 */
/* 观众要的文字（含容器字幕与选中的 <track>），UI 每帧取一次 */
const char *ql_media_subtitle_text(const QLMedia *m);

/* ---------- 事件 ---------- */
typedef enum {
    QL_MEDIA_EV_READY,       /* 元数据就绪（尺寸/时长可读） */
    QL_MEDIA_EV_STATE,       /* 状态变了 */
    QL_MEDIA_EV_ENDED,
    QL_MEDIA_EV_ERROR,
    QL_MEDIA_EV_BUFFERING,   /* 二期：网络流 */
} QLMediaEventType;
typedef void (*ql_media_event_fn)(QLMedia *m, QLMediaEventType ev, void *user);
void ql_media_set_event_cb(QLMedia *m, ql_media_event_fn cb, void *user);

约定：

  • 所有 API 都可以在 UI 线程调用；内部只投递命令，不阻塞等解码。
  • ql_media_position_ms() 在 PLAYING 时读时钟，其它状态读"最后已知位置"。
  • 错误码：QL_ERR_INVAL（参数/路径）、QL_ERR_IO（打不开）、 QL_ERR_UNSUPPORTED（没有后端/编解码器）、QL_ERR_NOMEM。

9.1 与 QLUI 的绑定

/* 构建期：<video id=v src="a.mp4"> 的节点绑定一个媒体实例 */
ql_err_t ql_ui_bind_media(QLUIRoot *ui, const char *node_id, QLMedia *m);
/* 或者按节点指针（构建路径没有 id 时） */
ql_err_t ql_ui_bind_media_node(QLUIRoot *ui, QLUINodeRT *node, QLMedia *m);

绑定之后：布局用媒体的固有尺寸（还没读到就用 width/height 或 300×150）， 绘制时 QLUI 调 ql_media_acquire_frame()，有帧就画、没帧就画 poster/空。

10. <track> 与 WebVTT

10.1 归谁

来源 谁解析 谁绘制
<track src=x.vtt> 本库自己的 WebVTT 解析器（纯文本，几十 KB） QLUI overlay
容器内嵌字幕（MKV/MP4 的 subtitle stream） FFmpeg 同上（文本走 ql_media_subtitle_text()）
硬字幕（压进画面的） 不需处理（已经在像素里） —

<track> 不使用 FFmpeg：VTT 解析不需要任何编解码库，也因此 QL_FEAT_MEDIA_WEBVTT=1 而 QL_FEAT_MEDIA_FFMPEG=0 是合法组合（静态字幕页）。

10.2 解析与模型

typedef struct {
    int64_t start_ms, end_ms;
    uint16_t text;        /* 文本池下标（构建期）或堆字符串（运行期） */
    uint8_t  line;        /* 0~100，默认 90（底部） */
    uint8_t  align;       /* start/center/end */
} QLVTTCue;
  • 文件格式：WEBVTT 头 + 可选 NOTE/STYLE（STYLE 一期忽略）+ cue 块。
  • 文本内联标签：<b> <i> <u> <c.class> <v Speaker> → 一期只保留纯文本 + <b>/<i> 两个开关位（不建富文本树，避免第二个排版器）。
  • 时间轴：cue 按 start_ms 排序，ql_media_position_ms() 二分查当前 cue。
  • 构建期可选：qltext 把 .vtt 预解析成 C 表（和 HTML 一样），运行期零解析； 运行期路径保留给"外部字幕文件"。

10.3 绘制

  • overlay 是 QLUI 的一个合成层，画在视频帧之上、控件之下。
  • 默认样式（可被 CSS 覆盖一部分）： css video::cue { color: #fff; font-size: 5%; text-shadow: 0 1px 2px #000; } 一期不支持 ::cue 选择器（等于给解析器加伪元素），改为内置默认样式 + 三个可配项：ql_ui_media_set_cue_style(fg, bg_alpha, size_pct)。
  • 多行：按视频盒子宽度折行（复用现有文本折行）。
  • 描边：CPU 后端用"四向偏移 + 底色半透明条"两种之一；GL 后端用 SDF 描边（二期）。

11. 构建、依赖与许可

11.1 CMake

option(QLGL_BUILD_MEDIA "构建 <audio>/<video>/<track> 与 QLMedia" ON)

if(QLGL_BUILD_MEDIA)
    find_package(PkgConfig QUIET)
    if(PkgConfig_FOUND)
        pkg_check_modules(FFMPEG QUIET
            libavformat>=60 libavcodec>=60 libavutil>=58
            libswscale>=7 libswresample>=4)
    endif()
    if(FFMPEG_FOUND)
        target_sources(qlgl PRIVATE src/media/qlmedia.c src/media/qlmedia_ffmpeg.c
                                  src/media/qlaudio_alsa.c src/media/qlwebvtt.c)
        target_include_directories(qlgl PRIVATE ${FFMPEG_INCLUDE_DIRS})
        target_link_libraries(qlgl PRIVATE ${FFMPEG_LIBRARIES})
        target_compile_definitions(qlgl PUBLIC QL_FEAT_MEDIA_FFMPEG=1)
        message(STATUS "QLGL: FFmpeg 媒体后端已启用")
    else()
        target_compile_definitions(qlgl PUBLIC QL_FEAT_MEDIA_FFMPEG=0)
        message(STATUS "QLGL: 未找到 FFmpeg，<video> 只能用注册进来的后端")
    endif()
endif()
  • FFmpeg 动态链接（pkg-config 默认就是 -lavformat 等）。
  • 版本下限按 FFmpeg 6.0（avformat >= 60）。Qt 6.5 自带的是 FFmpeg 7.1， 两者 API 差异集中在 AVCodecParameters/ch_layout，用 #if LIBAVUTIL_VERSION_MAJOR 分隔即可。
  • QLGL_BUILD_MEDIA=OFF 时整个 src/media/ 不参与编译，头文件里的 声明保留（返回 QL_ERR_UNSUPPORTED 的桩），与 TEXT_PARSER=OFF 的教训一致： 要么在配置期挡，要么给桩，不能让用户撞链接错误。

11.2 许可（必须写进发布说明）

选择 后果
默认 FFmpeg（LGPL-2.1+，动态链接） 本库仍可用 MIT/BSD 发布；分发时要带上 FFmpeg 的版权与源码获取方式
--enable-gpl（libx264、libx265、某些滤镜） 整条链接链变 GPL，闭源产品不能用
--enable-nonfree（如 fdk-aac） 不可再分发
静态链接 FFmpeg LGPL 要求提供可重新链接的目标文件，工程上更麻烦；优先动态

建议：仓库里不 vendored FFmpeg，只写"系统装 libavformat-dev 等"； 发布包按发行版方式依赖。示例/测试如果需要一个"自带样本"，用 ffmpeg 现场生成（见 §12），不把二进制塞进仓库。

11.3 ALSA

  • find_package(ALSA) 或 pkg_check_modules(ALSA alsa)；没有就 QL_FEAT_MEDIA_AUDIO=0 或退化成"空音频后端"（静音 + 系统时钟）。
  • 只链 libasound，不用 Pulse 的 native API 一期（PipeWire 的 ALSA 兼容层够用）。

12. 测试计划

媒体最容易变成"只能手测"的模块。这里刻意把能被确定性测试的部分和 只能手测的部分分开。

12.1 确定性测试（进 ctest）

测什么 怎么测
时钟 / 丢帧策略 假后端：按脚本产出 pts 序列，假"音频时钟"按固定步长推进；断言呈现/丢弃的帧号序列
队列与背压 假后端快速产帧，UI 故意不取；断言队列封顶、工作线程阻塞而不是吃内存
帧池生命周期 acquire/release 配平；ASan 下泄漏检查；close() 时未归还的帧被回收
seek 状态机 脚本化命令序列（play → seek → pause → play），断言 flush/时钟基准/队列清空
事件顺序 READY → STATE(PLAYING) → ENDED，且不重复
WebVTT 解析 正常/跨行/带标签/坏时间戳/CRLF/BOM；golden 文本
cue 查找 边界（cue 结束时刻、相邻 cue 相接、空档）
音频环形缓冲 单元测试：单生产者单消费者、绕回、欠载补零、采样计数
重采样 swr 的配置生成（48k→44.1k、5.1→立体声）用固定输入断言输出长度误差 < 1 帧
有界性 伪造"时长/尺寸/码率"超限的容器头，断言在解码前就被拒

假后端（test/media/fake_backend.c）就是 PC 上的"MCU 版"： 不依赖 FFmpeg/ALSA，产出合成 YUV（例如渐变色块 + 帧号）和 PCM（正弦波）。 QL_FEAT_MEDIA_FFMPEG=0 的构建里也能跑完整测试。

12.2 需要真实解码器的测试

  • 构建期用系统 ffmpeg 生成 1 秒样本（testsrc2 8 帧 + sine）， 没有 ffmpeg 就 SKIP（不把二进制塞仓库）。
  • 断言：能打开、能解出 ≥ N 帧、帧尺寸正确、pts 单调、能 seek 到中间、 能播完触发 ENDED。
  • 像素正确性：解码出的第一帧做 hash（只比"是否稳定"，不比跨版本一致）。

12.3 只能手测（写进验收清单，不进 CI）

  • 声音是否连续（欠载计数应为 0）、音画是否同步（口型偏移 < 80ms）；
  • 4K 视频 CPU/GL 两条路径的帧率与 CPU 占用；
  • 蓝牙/HDMI 切换、设备独占时的降级；
  • 拖动进度条时的观感（seek 后首帧延迟）。

13. 分阶段计划

阶段 内容 验收
M1（音频） QLMedia 核心（状态机/时钟/队列）+ FFmpeg 音频解码 + ALSA 输出 + <audio> 无盒语义 本地 mp3/wav 连续播放 5 分钟，欠载 0；暂停/恢复/seek 正确；假后端测试全绿
M2（视频，CPU） 视频解码 + 帧池 + sws_scale + <video> 布局（固有尺寸/object-fit）+ 脏区 720p@30 播放流畅、音画同步；暂停零重绘；窗口缩放正确
M3（视频，GL + 字幕） YUV 三平面纹理 + shader 矩阵；<track> WebVTT 解析 + overlay 绘制；容器字幕文本 1080p@60 GL 路径 CPU 占用显著低于 CPU 路径；字幕时间轴准确
M4（打磨） 循环/音量/多源 <source>/poster/事件完善；QL_FEAT_MEDIA_NET（http）；VAAPI 硬解 断网/坏文件/超限输入不崩；硬解开关可回退软解

每个阶段都保持"关掉能力 = 回到占位盒"，不允许出现"半开半关"的中间态。

14. 与 Qt 的对照（抄什么、不抄什么）

维度 Qt 6 本库
后端 FFmpeg 默认 + 平台原生（QT_MEDIA_BACKEND） FFmpeg 默认 + QLMediaBackend 弱符号（MCU 可换）
帧接口 QVideoSink（最新一帧，可丢弃） ql_media_acquire_frame()（同一语义，引用计数）
渲染 QVideoWidget/VideoOutput，可零拷贝 RHI 纹理 QLUI 的替换型元素；GL 走 YUV shader，CPU 走 sws_scale
音频 QAudioSink + 平台设备 QLAudioSink，一期 ALSA
时钟 音频为主，播放器内部管理 同左，暴露 ql_media_clock_us()
线程 播放器 + 每流线程 + 事件循环 一个工作线程 + UI 线程，模型更小
字幕 容器轨 + subtitleText；不解析 WebVTT 文件 容器轨 + 自己的 WebVTT 解析（HTML 语义要求）
控制 QMediaPlayer 富 API + QML 控件 最小 C API + 用户自己写 HTML 控件
许可 Qt 商业/LGPL + FFmpeg LGPL 库自身许可不变 + FFmpeg LGPL（动态）

值得抄的：帧 sink 的"只留最新一帧 + 可丢"、音频主时钟、后端可替换。 不要抄的：QMediaPlayer 那种大而全的对象、每流线程 + 信号槽跨线程、 把控件也做进框架。

15. 风险与备选

风险 影响 应对
FFmpeg 体积（动态库 ~几十 MB） 桌面包变大 只链需要的 5 个库；不 vendored；文档说明
LGPL 合规 分发受限 动态链接 + 随包附许可与源码获取说明；禁 GPL 组件
解码线程与 UI 竞争 卡顿/掉帧 有界队列 + 帧池 + UI 只取最新帧；--stats 观察
4K 软解跟不上 花屏/音画不同步 丢帧策略 + 明确日志；二期硬解
ALSA 设备五花八门 没声音 打不开就静音降级；QL_LOGW；文档给排查命令
畸形媒体 崩溃/越界 容器信息先验（尺寸/时长上限）+ 解码 API 的返回值全检查 + ASan/fuzz
WebVTT 需求膨胀（::cue、区域） 变成第二个排版器 一期只做纯文本 + 两个内联标签 + 固定默认样式
平台差异（Windows/macOS） 后端要各写一份 先 Linux；QLMediaBackend/QLAudioSink 已经留好位置

备选方案（评估过，不采用）：

  • 平台原生播放器（GStreamer/Media Foundation/AVFoundation）： 每个平台一套，行为不一致，且和"单线程自绘"的架构冲突。作为二期可选后端可以。
  • 自带解码器：视频编解码（H.264/VP9/AV1）不是这个库的战场，体积和正确性都不划算。
  • 只做 <audio> 不做 <video>：可以做，但 <video> 是 HTML 的"第一屏需求"， 留到二期的代价是接口要重设计。

16. 开放问题（实现前要定）

  1. <audio> 从"矮占位盒"改成"无盒"是否接受一个可见的布局变化？ （建议接受；关掉媒体能力时保留旧行为。）
  2. 一个页面允许多少个 QLMedia 实例？（建议一期 1 个视频 + 1 个音频， 超出在 ql_ui_bind_media() 返回 QL_ERR_UNSUPPORTED。）
  3. poster 的尺寸语义：按视频盒子拉伸还是 object-fit？（建议与 <img> 一致。）
  4. 字幕文本进不进文本池？（构建期进池省内存；运行期外部 VTT 只能堆分配。）
  5. QLWindow 的 32ms 等待是否改成"由 UI 给截止时间"？（建议改，动画也受益。）
  6. 是否需要"无声视频不打开音频设备"的显式开关？（muted 已能表达，建议不需要。）
  7. 测试样本的许可：用 ffmpeg 现场生成（推荐），还是提交 20KB 的公有领域样本？
