# 跨端一致性：一份代码多端可跑的边界

> 状态：**规划文档**。回答两个问题：
> ① 用 Vue/React 在 qlgl 上写的程序，能否一份代码跑 PC / Android / iOS / Linux / 网页？
> ② 网页端与 qlgl 端的**效果一致性**到什么程度、怎么验收？
>
> 前置阅读：[JS宿主与框架支持](./JS宿主与框架支持.md)（能力从哪来）、
> [10_vs_web](tutorial/10_vs_web.md)（单端差异清单）、[开发规划](./开发规划.md) M6（平台后端）。

---

## 1. 结论

**能共享的是“组件与逻辑”，不能共享的是“像素”。**

| 层 | 一份代码？ | 依据 |
|---|---|---|
| 业务逻辑 / 状态 / 组件树 | ✅ **100%** | React/Vue 运行时是纯 JS，与宿主无关 |
| 组件库 API（Button/List/Input…） | ✅ 共享 | 但**不能直接用 antd / element-plus**：它们假设 DOM，必须自建 `@qlgl/kit` 一层 |
| 布局与样式 | ⚠️ **共享子集** | 只写两端都实现的 CSS；qlgl 侧构建期报错（见 §6） |
| 视觉像素 | ❌ **不可能** | 文本度量、抗锯齿、模糊语义、滚动惯性不同（见 §5） |
| 特效 | ⚠️ 两套实现 | `refract()` 无 CSS 对应物，web 侧用 SVG `feDisplacementMap` 复刻 |

一句话：**这是 React Native / uni-app 的定位，不是“一次编写，处处一样”**。
一致性要落在**设计系统 + 验收阈值**上，而不是逐像素。

---

## 2. “网页”这个目标要拆成两种

| 方案 | 做法 | 适用 | 评价 |
|---|---|---|---|
| **(a) 同一份源码，两个 host renderer** | web 端 `react-dom` / Vue DOM renderer；qlgl 端自定义 renderer | 主路径 | ✅ 生态、SEO、无障碍、原生滚动全部保留 |
| **(b) qlgl 编成 WASM + canvas 自绘** | `ql_disp_mem` / WebGL 输出到 `<canvas>` | 仅“必须逐像素一致”时 | 失去 SEO / 无障碍 / 文本选择 / 原生滚动；体积与性能都不如 DOM |

**建议**：默认走 (a)；(b) 只作为“同一视觉基线”的辅助手段（例如做视觉回归对照）。

## 3. 平台矩阵

| 平台 | 现状 | 需要补 | 难度 | 主要风险 |
|---|---|---|---|---|
| **Linux 桌面** | ✅ X11 / Wayland（CPU + GL） | Wayland GPU（`wl_egl_window`） | 低 | — |
| **Windows** | ❌ | Win32 窗口 + D3D11（或 ANGLE/GL）+ DPI | 中 | IME 候选窗、字体渲染差异 |
| **macOS** | ❌ | AppKit + **Metal**（GL 已弃用）+ Retina | 中 | 字体 hinting 与 Linux 不同 |
| **Android** | ❌ | ANativeWindow + GLES3（复用现有 GL 后端）+ 触摸（已有） | 中高 | **InputConnection（IME）**、surface 丢失与生命周期、无障碍服务 |
| **iOS** | ❌ | UIKit + **Metal** + 生命周期 | 高 | **IME 必须走 UIKit**；**无障碍是上架与可用性硬伤**；JS 只能用系统 JavaScriptCore（无 JIT，UI 够用） |
| **Web（自绘）** | ❌ | WASM + canvas 后端 | 中 | 语义/无障碍/滚动全部自绘 |
| **MCU** | 规划中 | 只保留构建期 HTML/CSS，**无 JS** | — | 与 JS 宿主档互斥 |

> ⚠️ 提醒：**“跑遍 Android/iOS”真正的门槛不是渲染后端，而是 IME + 无障碍 + 生命周期。**
> D3D/Metal 决定“能不能画出来”，IME 决定“能不能写中文”，无障碍决定“能不能上架”。
> [开发规划 §6](./开发规划.md) 里“可访问性不做”这条非目标，在移动端需要重新评估。

## 4. 一致性模型与验收口径

分三层验收，**每层有自己的判据**（都不追求逐像素）。

### 4.1 结构一致性（最强承诺）

同一份 HTML/CSS，两端产出的**盒模型**应当可比：

- 节点数量、层次、`display` 类别一致；
- 每个节点的 `x/y/w/h` 逐项比较，**容差 ±2px**（见 §4.2）；
- 文本节点的**行数**一致（不断言精确字体度量，但断行数不同就是问题）。

### 4.2 布局一致性（±1~3px 量级）

差异主要来自取整与文本度量，属**可接受**范围，但必须有阈值：

| 指标 | 阈值 |
|---|---|
| 元素位置/尺寸偏差 | ≤ 2px（单层），≤ 4px（嵌套 ≥5 层） |
| 整页累计漂移 | ≤ 8px |
| 文本行数 | 必须相同 |

### 4.3 像素一致性（阈值化，不逐像素）

| 指标 | 阈值 |
|---|---|
| 区域（切 16×16 网格）内像素差 > 8/255 的比例 | 每格 ≤ 5% |
| 整页平均绝对误差（MAE） | ≤ 3/255 |
| 允许“白名单区域”（见 §5 的不可消除项） | 记录但不判失败 |

> 与现有 `test_golden` 的关系：**golden 是“同端逐字节”**（改一个色阶就红），
> 跨端 parity 是“**跨端阈值**”。两套并存，不要拿 golden 的标准去做跨端比较。

## 5. 差异来源清单（按影响排序）

| # | 来源 | 影响量级 | 缓解 | 能消除？ |
|---|---|---|---|---|
| 1 | **文本度量与断行**（FreeType vs 浏览器 HarfBuzz+hinting） | 可能整行不同 → 布局连锁 | 两端**自带同一字体**（web 用 `@font-face`）、固定 `line-height` / `letter-spacing`、避免系统字体栈 | ❌ 不能完全 |
| 2 | **取整与亚像素**（qlgl 定点/整数，web subpixel） | 1~3px | 尺寸尽量用整数 px；避免 0.5px | ⚠️ 大体可 |
| 3 | **圆角/描边抗锯齿**（SDF 覆盖率 vs Skia 光栅） | 边缘 1px 观感 | 可接受；截图对比时容忍 | ❌ |
| 4 | **模糊/毛玻璃**（`sigma` ↔ CSS `blur()` 换算近似，采样范围不同） | 半径大时肉眼可辨 | 半径 ≤ 8px；把玻璃当成“风格”而非“精度” | ⚠️ 部分 |
| 5 | **`refract()` 无 CSS 对应物** | 视觉差异明显 | web 侧用 SVG `feDisplacementMap` 复刻（参考稿做法）；分级为 `enhance` | ⚠️ 做到“接近” |
| 6 | **滚动**（自绘 vs 原生；无惯性 vs 有惯性） | 手感 | qlgl 侧可加惯性（需排期）；或用分页代替长滚动 | ⚠️ |
| 7 | **表单控件 / IME 候选窗 / 文本选择** | 交互观感 | 系统实现 vs 自绘，只能“各自符合平台习惯” | ❌ |
| 8 | **色彩管理 / 渐变抖动** | 大面积渐变细微色带 | 已有抖动修色带；web 侧避免极端窄色带渐变 | ⚠️ |
| 9 | **`margin` 折叠**（qlgl 不折叠 vs web 折叠） | 间距差 | **禁止依赖折叠**：块间距用 `padding` 或父级 `gap` | ✅ 可（靠规范） |

## 6. 跨端样式子集（写代码时按这三档）

### ✅ 推荐（两端语义最接近，可放心用）

- 布局：`flex`（row/column/wrap）、`position: absolute/relative`、`padding/margin`（px 与 %）、`gap`、`box-sizing`
- 尺寸：`px`、`%`、`max/min-width`
- 视觉：`background-color`、线性/径向渐变、`border-radius`（含 `%`）、`box-shadow`（≤2 层，含 inset/spread）、`outline`
- 变换：`transform: translate/scale/rotate/skew`（2D）
- 动效：`transition`（delay/easing/`steps()`/`cubic-bezier()`）、`@keyframes`
- 主题：CSS 变量、`@media`（**只用固定 px 断点**）
- 文本：`font-size/weight/color/text-align/line-height/white-space/word-break`

### ⚠️ 可用但必须过验收

| 属性 | 注意 |
|---|---|
| `grid` | qlgl 是子集实现，复杂模板先在两端各跑一遍 |
| `display: table` / 多列 `columns` | 语义子集，慎用复杂场景 |
| `position: sticky` | 边界行为需实测 |
| `backdrop-filter: blur()` | 半径 ≤8px；`saturate` 两端算法不同 |
| `filter` 家族 | 模糊/阴影数值换算近似 |
| `clip-path`（circle/ellipse/inset/polygon） | 4 种形状可用，复杂 `path()` 不支持 |
| `vw/vh` | 两端“视口”定义受滚动条影响不同，优先用 `%` + 断点 |

### ⛔ 禁止（qlgl 构建期会报错，或语义差异不可接受）

`float` / `clear`、3D transform（`rotate3d`/`perspective`）、`:has()` / `:is()` / `:where()`、
`@supports` / `@layer` / `@container`、`ch` / `ex` / `lh` 单位、`margin` 折叠依赖、
`::selection` 样式、自定义滚动条样式、`position: fixed` 之外的高级层叠上下文技巧。

> 这些在 [10_vs_web](tutorial/10_vs_web.md) 里逐条有原因说明。

## 7. 工程约束（做“一份代码多端”的七条硬规矩）

1. **只依赖 `@qlgl/kit`**：业务组件不直接写裸 `div`，底座自己维护（web 端用同一层 API 实现在 DOM 上）。
2. **自带字体**：不写系统字体栈；`line-height` 显式给出。
3. **布局只用 flex**；`grid/table/columns/sticky` 要有验收用例才允许进主流程。
4. **断点用固定 px**；不用视口单位做布局主尺寸。
5. **设计 token 统一**（颜色/间距/字号/圆角/阴影）：禁止散落魔法值，token 一处改、多端生效。
6. **特效分级**：`core`（两端都有）/ `enhance`（各自实现，允许不同，默认可在低端关掉）。
7. **两份基线**：`test/golden`（同端逐字节）+ `test/parity`（跨端阈值，见 §4）。

## 8. `qlui --platform` 跨端报告（草案）

现有机制是“对目标平台不支持的效果给出构建期降级报告”。扩成**跨端**：

```text
$ qlui --platform web,desktop-js --cross-check index.html style.css

cross-check: 3 条警告，0 条错误
  style.css:42  [warn] float 不被 qlgl 支持，web 端可用 → 跨端不一致
  style.css:88  [warn] backdrop-filter: blur(24px) 半径 > 8px，两端观感可能明显不同
  index.html:17 [warn] 使用系统字体栈（未声明 @font-face），文本断行可能不同
  建议：见 doc/跨端一致性.md §6
```

分级：

| 级别 | 含义 | 行为 |
|---|---|---|
| `error` | qlgl 构建期不支持（`float`、`:has()` 等） | 直接失败 |
| `warn` | 两端都支持但语义/观感有差异（模糊半径、vh、grid 复杂模板） | 打印报告，可在 CI 里按白名单豁免 |
| `info` | 提示性（建议自带字体、建议 token 化） | 仅打印 |

## 9. 落地顺序

| 阶段 | 内容 | 验收 |
|---|---|---|
| **A** | Linux 桌面 + Web：同一份 React 代码、两个 renderer，跑通构建/样式子集校验/组件层 | 同一页面两端结构快照一致；布局偏差 ≤2px |
| **B** | `test/parity` 工具 + 两份基线（golden / parity） | CI 里能复现“某次改动导致跨端偏差超标” |
| **C** | `qlui --platform` 跨端报告 | 示例工程零 error、warn 有白名单 |
| **D** | Android（GLES3 复用 + IME/生命周期/无障碍最小集） | 真机跑通输入中文 |
| **E** | iOS（Metal + UIKit IME + 无障碍） | 真机跑通；重新评估“可访问性不做”这条非目标 |
| **F**（可选） | WASM/canvas 自绘，用于“像素基线对照” | 与 GL 端像素差 ≤ 现有 `test_gl_vs_cpu` 口径 |

## 10. 风险

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 把“一份代码”理解成“像素一致”，验收永远不通过 | 高 | 项目失去焦点 | 本文 §1/§4 的**分层承诺**写进对外说明 |
| 组件库生态不能复用（antd/element-plus 无 DOM 不可用） | 高 | 初期开发慢 | 先做 `@qlgl/kit` 最小集（10~15 个组件） |
| 移动端 IME/无障碍工作量被低估 | 高 | 排期翻倍 | Android/iOS 单独排期，不与桌面合并 |
| `grid`/`table` 子集在真实页面被用爆 | 中 | 两端不一致 | §6 的 ⚠️ 档强制验收用例 |
| 跨端 parity 基线数量爆炸（平台 × 页面 × DPR） | 中 | CI 慢 | 只对“设计系统样板页”做 parity，业务页不做 |
