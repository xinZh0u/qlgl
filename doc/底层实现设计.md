# QLGL 底层实现设计（v0.1 草案）

> 本文档只描述**底层**：内存、类型、属性、事件、字符串、绘制、样式、编译期二进制格式与工具链。
> 上层控件（按钮、列表、滚动容器）不在本文范围。
> 约束来源：[代码规范.txt](./代码规范.txt)（C11、中文注释、LVGL 风格、枚举全大写、结构体 `QL` 开头驼峰、禁用 32/64 位不等长类型、属性区预留大余量）。

## 1. 设计总纲

### 1.1 分层

```
┌───────────────────────────────────────────────┐
│ 界面层  ql_ui（HTML/CSS 编译出来的节点树）      │  [QLUI 阅读指南](手册/ui/QLUI阅读指南.md)
├───────────────────────────────────────────────┤
│ 布局层  ql_layout   （盒模型、两趟测量/排布）    │  §8
├───────────────────────────────────────────────┤
│ 样式层  ql_style    （级联结果、继承白名单）     │  §9
├───────────────────────────────────────────────┤
│ 绘制层  ql_draw2d / qlcanvas（字形 blit、脏区） │  §7
├───────────────────────────────────────────────┤
│ 对象层  ql_object / ql_class / ql_prop / ql_event│  §2~§6
├───────────────────────────────────────────────┤
│ 平台层  ql_disp / ql_input / ql_mem / ql_log     │  §2.5
└───────────────────────────────────────────────┘
        ▲ 编译期（PC 端工具 qcssc）        │ 运行期（目标板）
        │ HTML+CSS → IR → 二进制 v1        │ loader / 直接读 .rodata
```

### 1.2 三条铁律

1. **编译期能做的不留到运行期**：选择器匹配、级联、单位换算、文本分段全在 `qcssc` 里做完；运行时只做"按 id 取已算好的值"。
2. **运行期不隐式分配**：控件创建/事件/绘制路径上禁止 `malloc`（可在 `qlgl_init` 里一次性预分配池）。所有"可能失败"的 API 返回 `ql_err_t`。
3. **id 由构建期生成**：类型 id、属性 id、事件 id 全部来自 `src/generated/*.h`，由脚本扫描源码生成，保证目标板与 PC 工具看到同一套 id。

### 1.3 配置裁剪

所有功能由 `qlconfig.h` 单点开关，默认值面向 MPU；MCU 通过 `qlconfig_mcu.h` 覆盖：

```c
/* 计划路径: /src/qlconfig.h */
#ifndef QLCONFIG_H
#define QLCONFIG_H

#define QL_CFG_MAX_CLASS            64      /* 类表容量，ROM 静态数组 */
#define QL_CFG_MAX_INHERIT_DEPTH    8       /* 继承链上限，超过注册即失败 */
#define QL_CFG_EVENT_ARG_MAX        4       /* 事件参数上限 */
#define QL_CFG_EVENT_CONN_POOL      256     /* 全局连接池，0 = 每对象内联 2 个 */
#define QL_CFG_DIRTY_RECT_MAX       16
#define QL_CFG_ANTIALIAS            1
#define QL_CFG_TEXT_UTF8            1
#define QL_CFG_BINARY_LOADER        1       /* 0 = 只允许编译进 .rodata */
#define QL_CFG_HTML_RUNTIME         0       /* 0 = 纯二进制，1 = 运行时解析 */
#define QL_CFG_PROPERTY_NAME        1       /* 0 = 裁掉属性名字符串 */
#define QL_CFG_LOG_LEVEL            2

#endif
```

裁掉 `QL_CFG_PROPERTY_NAME` / `QL_CFG_BINARY_LOADER` / `QL_CFG_HTML_RUNTIME` 可省掉绝大部分字符串与解析代码（⚠️ 体积收益待实测）。

## 2. 对象与内存布局

### 2.1 现状问题（❗阻塞）

| 现状 | 缺陷 |
|---|---|
| [src/qlobject.c](../src/qlobject.c) `ql_object_new` | 私有区总量 = 各层 `private_size()` 的**前缀和之和**，5 层继承时是需求的 3 倍 |
| 同文件 `ql_object_unref` | `free(self)`，`self` 是块内偏移指针 → ASan 报 `free on address which was not malloc()-ed` ✅已验证 |
| 私有区访问 | `ql_xxx_get_private()` 是宏生成的**非 static 函数**，未声明进头文件，且每次调用走一次减法+一次虚调用 |
| `ql_object_init` | 把**栈上局部** `QLObjectClass` 存进 `class_table[0]` → 悬垂 |

### 2.2 目标布局 ✅已验证

**条件**：`class_table[0]` 为根类，且要求"父类先于子类注册"（见 §3.2）。

```
            malloc 块
  +---------------------------+  mem
  | 根类私有区   priv_offset=0 |
  +---------------------------+  +0
  | 父类私有区                |
  +---------------------------+
  | 本类私有区                |
  +---------------------------+  mem + priv_total
  | QLObject 实例（含继承结构） |  ← self，instance_size 为最终派生类大小
  +---------------------------+
```

分配量 = `self->klass->instance_size + self->klass->priv_total`，其中
`priv_total = Σ 每层 own_private_size`（**不再是前缀和**）。

原型实测（5 层、每层 16 字节私有区）：`priv_total = 80`，恰好等于需求，无重叠、无浪费，`unref` 在 ASan 下通过 ✅。当前实现同样场景为 240 字节。

### 2.3 核心 API

```c
/* 计划路径: /src/core/qlclass.h */

struct QLObjectClass {
    QLType   type;              /* 构建期生成，见 §3 */
    uint16_t instance_size;     /* 该类结构体大小（含父类字段） */
    uint16_t own_private_size;  /* 本类自己的私有区大小 */
    uint16_t priv_offset;       /* 私有区相对块首偏移，注册时算好 */
    uint16_t priv_total;        /* 整条链私有区总和，注册时算好 */

    const char *name;           /* QL_CFG_PROPERTY_NAME=0 时可为 NULL */

    ql_property_t property_start;   /* 含 */
    ql_property_t property_end;     /* 含 */

    const QLPropertyDesc *props;    /* 可选，供脚本/工具使用 */
    uint16_t prop_count;

    const QLEventDesc *events;      /* 事件描述表，静态 */
    uint16_t event_count;

    QLObjectClass *parent;

    /* 虚函数 */
    void (*init)(QLObject *self);
    void (*deinit)(QLObject *self);
    void (*class_init)(QLObjectClass *klass);
    void (*set_property)(QLObject *self, ql_property_t p, QLValue v);
    QLValue (*get_property)(QLObject *self, ql_property_t p);
    void (*event)(QLObject *self, const QLEventArgs *args);  /* 默认事件处理，用于冒泡 */
};
/* O(1) 私有区访问；内联，无虚调用 */
static inline void *ql_priv(QLObject *self, QLObjectClass *k)
{
    return (char *)self - self->klass->priv_total + k->priv_offset;
}
```

`QLObject` 精简为：

```c
struct QLObject {
    QLObjectClass *klass;
    QLObject   *parent;
    QLObject   *first_child;
    QLObject   *next_sibling;
    int32_t     ref_count;
    uint32_t    conn_head;   /* 连接池链表头，0xFFFFFFFF = 空 */
    uint16_t    flags;       /* DIRTY_SIZE / DIRTY_STYLE / HIDDEN ... */
    uint8_t     state;       /* 构造中/存活/析构中 */
    uint8_t     reserved;    /* ABI 预留 */
};
```

> 刻意**不用位域**：位域布局由实现定义，与"ABI 稳定"目标冲突（❗当前 [src/qlobject.h](../src/qlobject.h) 有 `uint8_t emitting : 1`）。

### 2.4 生命周期

```c
QLObject *ql_object_new(QLType type);

/* 引用计数为 0 时：先调 deinit（子→父），再释放连接，再 free(块首) */
void ql_object_unref(QLObject *self);

/* 父子关系：父持有强引用，删除父自动 unref 全部子 */
void ql_object_set_parent(QLObject *self, QLObject *parent);
```

销毁顺序固定：`deinit`（派生→根）→ 断开事件连接 → 移出父链 → `ql_mem_free(mem)`。`mem` 指针由 `(char*)self - self->klass->priv_total` 反算，**绝不 free(self)**。

### 2.5 分配器钩子

```c
/* 计划路径: /src/core/qlmem.h */
typedef struct {
    void *(*alloc)(size_t size);
    void *(*realloc)(void *p, size_t size);
    void  (*free)(void *p);
} QLAllocator;

void ql_mem_set_allocator(const QLAllocator *a);   /* qlgl_init 之前调用 */
```

- 默认走 `malloc/realloc/free`；
- MCU 可挂静态块分配器（约定"只分配不回收"或 TLSF 风格）；
- 所有分配失败返回 `NULL`，调用方必须处理并返回 `QL_ERR_NOMEM`（❗当前 `ql_object_new` 未检查 `calloc` 返回值）。

### 2.6 错误码与公共符号

```c
/* 计划路径: /src/core/qlgl.h */
typedef enum {
    QL_OK           = 0,
    QL_ERR_NOMEM    = -1,
    QL_ERR_INVAL    = -2,   /* 参数非法 / id 越界 */
    QL_ERR_NOT_INIT = -3,   /* qlgl_init 未调用或父类未注册 */
    QL_ERR_OVERFLOW = -4,   /* 私有区/继承深度超限 */
    QL_ERR_EXISTS   = -5,   /* 重复注册 */
    QL_ERR_VER      = -6,   /* 二进制版本不兼容 */
} ql_err_t;

#define QL_ARRAY_SIZE(a)    (sizeof(a) / sizeof((a)[0]))
#define QL_CONN_NONE        0xFFFFFFFFu

QLObjectClass *ql_class_get(QLType type);   /* 越界返回 NULL */
QLObjectClass *ql_object_class_get(QLObject *self);
```

`ql_err_t` 为负值，便于 `if (err < 0)` 统一判断；`qlgl_init()` 返回 `ql_err_t` 而非 `int`（❗现状 `int qlgl_init()` 用 `return 1` 表示成功，语义反直觉）。

## 3. 类型系统

### 3.1 现状问题（❗阻塞）

- `QLType` 定义为 `unsigned long` → 32 位机 4 字节、64 位机 8 字节，**直接违反自家规范**。
- 类 id 由 `.init_array` 构造函数按**链接顺序**自增分配 → 每次改文件/改链接顺序 id 就变，二进制格式与语言绑定全部失效。
- 根类没走统一注册，`class_table[0]` 是悬垂指针。
- 继承链遍历用 `class_table[i]`（下标）而非栈内容 → ✅实测对 `QLButton` 调用了无关类 `QLExtra` 的 `init`（类型混淆）。

### 3.2 目标方案

**`QLType = uint32_t`**，id 来自构建期生成的枚举：

```c
/* 计划路径: /src/generated/qltype_gen.h  —— 由 tools/qlgen 生成，勿手改 */
typedef enum {
    QL_TYPE_OBJECT = 0,
    /* 其它类追加到这里（当前只有根类） */
    /* 新类追加到末尾，禁止插入或重排 */
    QL_TYPE_COUNT
} QLTypeBuiltin;
```

生成规则：`tools/qlgen` 扫描所有 `QL_DEFINE_WITH_PRIVATE(NAME, Name, name, Inherit)`，按首次出现顺序编号；CI 里跑 `qlgen --check`，与已提交版本不一致即失败（防止手滑重排导致 ABI 破坏）。

**注册不再依赖构造函数**，改为显式、按依赖顺序：

```c
/* 计划路径: /src/generated/qlclass_gen.c */
typedef struct {
    QLType         type;
    QLType         parent_type;   /* 由 qlgen 从 QL_DEFINE_WITH_PRIVATE 的第 4 个参数解析 */
    QLObjectClass *klass;
} QLClassReg;

static const QLClassReg ql_class_reg_table[] = {
    { QL_TYPE_OBJECT, QL_TYPE_OBJECT, &ql_object_class },
    { QL_TYPE_FOO,    QL_TYPE_OBJECT, &ql_foo_class },
    /* 其它类追加到这里 */
};

ql_err_t ql_class_init_all(void)      /* qlgl_init() 内部调用，顺序即枚举顺序 */
{
    for (size_t i = 0; i < QL_ARRAY_SIZE(ql_class_reg_table); i++) {
        QLObjectClass *k = ql_class_reg_table[i].klass;
        QLType pt = ql_class_reg_table[i].parent_type;

        k->type   = ql_class_reg_table[i].type;
        k->parent = (pt == QL_TYPE_OBJECT) ? NULL : ql_class_get(pt);

        /* 父类必须先注册，否则说明生成的表顺序错了 */
        if (pt != QL_TYPE_OBJECT && k->parent == NULL) return QL_ERR_NOT_INIT;

        k->priv_offset = k->parent ? (k->parent->priv_offset + k->parent->own_private_size) : 0;
        k->priv_total  = (k->parent ? k->parent->priv_total : 0) + k->own_private_size;

        if (k->priv_total > UINT16_MAX) return QL_ERR_OVERFLOW;

        class_table[k->type] = k;
        if (k->class_init) k->class_init(k);
    }
    return QL_OK;
}
```

> 父/子关系由**生成的表**给出（`parent_type`），不引入 `parent_type()` 虚函数——少一次间接调用，也避免"类对象尚未注册就去问它父类是谁"的顺序问题。

好处：无 `.init_array`（裸机友好）、id 确定、父类必然先注册、错误可上报。

### 3.3 对象创建中的继承链遍历（修正版）

```c
QLObject *ql_object_new(QLType type)
{
    QLObjectClass *k = ql_class_get(type);
    if (!k || !k->instance_size) return NULL;

    size_t total = (size_t)k->instance_size + k->priv_total;
    char  *mem   = ql_mem_alloc(total);
    if (!mem) return NULL;

    QLObject *self = (QLObject *)(mem + k->priv_total);
    self->klass = k;
    self->ref_count = 1;
    self->conn_head = QL_CONN_NONE;

    /* 父 → 子，逐层 init；链由 klass->parent 走出，不碰数组下标 */
    QLObjectClass *stack[QL_CFG_MAX_INHERIT_DEPTH];
    int depth = 0;
    for (QLObjectClass *c = k; c && depth < QL_CFG_MAX_INHERIT_DEPTH; c = c->parent)
        stack[depth++] = c;

    for (int i = depth - 1; i >= 0; i--)
        if (stack[i]->init) stack[i]->init(self);

    return self;
}
```

> 深度检查缺失是 ❗现状问题（`ql_object_new` 对 `QL_OBJECT_MAX_INHERIT_NUM` 无边界判断，超出即栈溢出）。

## 4. 属性系统

### 4.1 区间语义（修正）

现状用 `property > start && property < end`，导致 `*_PROPERTY_START` 本身不可用。目标改为**闭区间**：

```c
#define QL_PROPERTY_ENUM_START(NAME, Name, INHERIT)                     \
    typedef enum Name##Property Name##Property;                         \
    enum Name##Property {                                               \
        NAME##_PROPERTY_START = INHERIT##_PROPERTY_SPACE_END + 1,       \
        NAME##_PROPERTY_FIRST = NAME##_PROPERTY_START,

#define QL_PROPERTY_ENUM_END(NAME, capacity)                            \
        NAME##_PROPERTY_END = NAME##_PROPERTY_START + (capacity) - 1,   \
        NAME##_PROPERTY_SPACE_END = NAME##_PROPERTY_END,                \
    };
```

同时把 `start = object 的 SPACE_END + 1`，保证相邻类区间不重叠：
根类 `OBJECT` 占 `[1, 100]`，第一个子类占 `[101, 200]`，依此类推 ……

### 4.2 派发

```c
/* 计划路径: /src/core/qlprop.c */
void ql_object_set_property(QLObject *self, ql_property_t p, QLValue v)
{
    for (QLObjectClass *k = self->klass; k; k = k->parent) {
        if (p >= k->property_start && p <= k->property_end) {
            if (k->set_property) k->set_property(self, p, v);
            return;
        }
    }
}
```

复杂度 O(继承深度)，深度 ≤ 8 → 可接受；不做哈希表（ROM 代价大于收益）。

### 4.3 属性描述表（可选，供工具与绑定）

```c
typedef struct {
    ql_property_t id;
    uint8_t  type;    /* QLValueType */
    uint8_t  flags;   /* QL_PROP_READ / WRITE / REDRAW / RELAYOUT / INHERIT */
    uint16_t reserved;
    const char *name; /* QL_CFG_PROPERTY_NAME=0 时不存在 */
} QLPropertyDesc;
```

`REDRAW` / `RELAYOUT` 标志让 setter 自动打脏标记，避免每个控件手写：set 之后由框架统一置 `QL_OBJ_FLAG_DIRTY_*`，构建设计上把"通知"与"赋值"解耦。

### 4.4 值类型

```c
typedef struct {
    uint8_t  type;
    uint8_t  flags;     /* 例如 QL_VAL_OWN_STR */
    uint16_t aux;
    union {
        int32_t    i;
        uint32_t   u;
        ql_fixed_t f;   /* Q16.16 定点，禁止直接用 float 存属性 */
        void      *p;
        QLObject  *o;
    };
} QLValue;
```

- `QLType` 用 `int32_t/uint32_t`，**不用 `long`**；浮点统一 `Q16.16`（`ql_fixed_t = int32_t`）以满足"32/64 位等长"；
- `QLValue` 含指针，仅在内存中传递，**绝不直接落盘**（落盘用 §11 的 wire 编码）。

## 5. 事件系统

### 5.1 现状问题

| 现状 | 缺陷 |
|---|---|
| ❗`QL_EMIT(obj, code)` 0 参数 | `QL_VALUE_NULL` 未定义，**无法编译** ✅已验证 |
| ❗参数宏 | 实际按逗号 token 数派发，只覆盖偶数 token（2/4/…/20），注释写的 0/1/4/6 与实现不符 |
| ❗`ql_value_ptr(&_p)` | 把**栈上临时结构体**地址塞进事件，回调若缓存即悬垂；也无法被语言绑定表达 |
| ❗无 parent 指针 | `QL_EVENT_BUBBLE` 已定义但根本无法实现 |
| ❗`ql_disconnect` 只置 `removed` | 既不回收槽位也无压缩，长跑场景池会耗尽 |
| ❗`ql_event_new` 在 `class_init` 里 `strdup` | 除了 `strdup` 不可移植外，事件名在 MCU 上纯属浪费 |

### 5.2 参数打包（替换裸指针）

```c
typedef struct {
    uint8_t count;
    uint8_t type[QL_CFG_EVENT_ARG_MAX];
    QLValue arg[QL_CFG_EVENT_ARG_MAX];
} QLEventArgs;
```

宏改为"逐个塞进结构体数组"，不再取临时结构体地址：

```c
/* 计划路径: /src/core/qlevent.h */
#define QL_EMIT_2(obj, code, t1, a1)                        \
    do {                                                    \
        QLEventArgs _a = { .count = 1 };                    \
        _a.type[0] = (t1); _a.arg[0].type = (t1);           \
        _a.arg[0].i = (int32_t)(a1);                       \
        ql_emit((obj), (code), &_a);                        \
    } while (0)
```

约定：**只允许带类型的整型/定点/对象/指针**（`QL_EVENT_ARG_INT/FIXED/PTR/OBJ`），字符串走 `QLStr` 指针，禁止任意结构体。这样 JS/Py 绑定与二进制事件表都能表达。

> 派发改为按参数个数显式选择 `QL_EMIT_N(obj, ev, ...)`（N=0..4），不再靠 token 计数魔法宏——token 计数在 0 参数和奇数参数时必错。

### 5.3 事件 id

```c
#define QL_EVENT_ENUM_START(NAME, Name, INHERIT)                  \
    typedef enum Name##Event Name##Event;                          \
    enum Name##Event {                                             \
        NAME##_EVENT_START = INHERIT##_EVENT_SPACE_END + 1,        \
        NAME##_EVENT_FIRST = NAME##_EVENT_START,

#define QL_EVENT_ENUM_END(NAME, capacity)                          \
        NAME##_EVENT_END = NAME##_EVENT_START + (capacity) - 1,    \
        NAME##_EVENT_SPACE_END = NAME##_EVENT_END,                 \
    };
```

> ❗现状 [src/qlevent.h](../src/qlevent.h) 里 `enum Name##Property` 是笔误，且 `NAME##_EVENT_END` 从未定义，事件枚举体系实际不可用；`main.c` 里直接用魔法数字 `1`。

### 5.4 连接池（运行期零 malloc）

```c
typedef struct {
    QLObject     *obj;
    ql_event_cb_t cb;
    void         *user_data;
    ql_event_t    event;
    uint32_t      conn_id;   /* 单调递增，不复用，避免 ABA */
    uint16_t      next;      /* 同对象连接链表 */
    uint8_t       removed : 1;
    uint8_t       in_use  : 1;
} QLEventConn;
```

- `QL_CFG_EVENT_CONN_POOL` 个槽位静态预分配；对象头只存 `conn_head`；
- `ql_disconnect` 置 `removed`，**首尾的 removed 节点立即回收**，中间的等 `emit_depth == 0` 时压缩；
- `conn_id` 用 `uint32_t` 单调递增（4G 次后回绕可接受，或 64 位 PC 端用 64 位）。

### 5.5 传播

```c
int ql_emit(QLObject *obj, ql_event_t event, const QLEventArgs *args);
```

流程：捕获阶段（若 flag 有 `CAPTURE`，从根到目标）→ 目标回调 → 冒泡（`BUBBLE` 时沿 `parent` 上溯）→ 回调内 `ql_event_stop_propagation()` 置 `stop` 标志、`ql_event_stop_default()` 跳过 `klass->event`。全程一个 `emit_depth` 计数，深度 > 8 直接丢弃（防父子环）。

## 6. 字符串与资源

### 6.1 QLStr

```c
typedef struct {
    char    *data;
    uint32_t len;       /* strlen 缓存，UTF-8 字节数 */
    uint32_t capacity;  /* data 可写容量；0 = 只读（静态/外部） */
    uint8_t  own  : 1;  /* 是否由 ql_mem 分配 */
    uint8_t  dyn  : 1;  /* 是否启用容量倍增策略 */
} QLStr;
```

### 6.2 两种策略（对应规范第 4 条）

| 策略 | 行为 | 适用 |
|---|---|---|
| `QL_STR_COMPACT` | 每次写入按精确长度分配，容量 = 长度 | MCU 端高频文本刷新（内存紧张） |
| `QL_STR_AMORTIZED` | 容量按 2 倍增长，删除不缩容 | MPU/PC 端（避免反复分配） |

策略是**每对象可切换**（`ql_str_set_policy()`），不是编译期二选一，这样同一固件里 label 可以用 compact、日志面板可以用 amortized。

### 6.3 资源

字体/图片/矢量路径全部走"资源 id → 段内偏移"，运行期不出现文件路径：

```c
typedef struct {
    uint32_t id;
    uint32_t offset;   /* 相对资源段 */
    uint32_t size;
    uint8_t  kind;     /* FONT / IMG / PATH */
    uint8_t  reserved[3];
} QLResourceEntry;
```

## 8. 布局（盒模型）

对齐 CSS2.1 的盒子模型，但只实现 **content + padding + border + margin**，不支持 `float`/`position:fixed`。

```c
typedef struct {
    int16_t x, y;          /* 内容区左上（相对父内容区） */
    int16_t w, h;          /* 内容区尺寸 */
    int16_t pad[4];        /* 上右下左 */
    int16_t border[4];
    int16_t margin[4];
    uint8_t box_sizing;    /* CONTENT_BOX / BORDER_BOX */
} QLBox;
```

两趟算法（LVGL 同思路）：

1. **测尺寸**：自底向上 `measure(self, avail_w, avail_h) -> (w,h)`，`width:auto` 时取子节点最大外沿；
2. **排位置**：自顶向下 `arrange(self, x, y, w, h)`，按 `display: block | flex-row | flex-col`（v0.1 只做这三种）依次分配主轴空间。

约束：数值单位在编译期已归一化为**像素整数**（`%` 转成本次可用空间的定点比例，`em` 按字体尺寸换算），运行期不做单位运算。

## 9. 样式系统

### 9.1 计算样式结构体（运行期唯一关心的东西）

```c
typedef struct {
    ql_color_t bg_color;
    ql_color_t fg_color;
    int16_t    border_width;
    uint8_t    border_radius;
    int16_t    font_size;      /* 已换算为像素 */
    uint16_t   font_id;        /* 资源段里的字体索引 */
    uint8_t    align;          /* 文本对齐 */
    uint8_t    opacity;        /* 0..255 */
    uint8_t    display;        /* BLOCK / FLEX_ROW / FLEX_COL / NONE */
    uint8_t    overflow;       /* VISIBLE / HIDDEN / SCROLL */
    /* 追加字段只能加在末尾；结构体带 size 字段供 loader 校验 */
    uint16_t   struct_size;
} QLStyle;
```

### 9.2 编译期级联

`qcssc` 做完整级联，产物是"每个节点一份 `QLStyle` + 一份差异化属性集合"。

层叠顺序（低 → 高）：UA 默认样式 → 标签选择器 → 类选择器 → ID 选择器 → 行内 `style` → `!important`。

**继承白名单**（只有这些属性会向下继承，其余一律重置）：`color`、`font-size`、`font-id`、`text-align`、`visibility`。白名单写死在 `qcssc` 里，避免运行期做继承遍历。

### 9.3 不支持项必须构建期报错

```css
/* qcssc 遇到即报错并指出文件:行:列 */
position: fixed;      /* 不支持 */
float: left;          /* 不支持 */
@media ...            /* 不支持（v0.1） */
```

> 这条是硬要求：静默降级会让"PC 上看起来对、板子上错位"成为常态，排查成本远高于构建失败。

## 11. 二进制格式 v1

### 11.1 总则

- 小端（跨端序时构建期整体翻转，标志位记录）；
- 所有段 8 字节对齐；
- 所有偏移相对**本段起点**；
- 只增不改：新增字段追加在结构体末尾，`struct_size` 字段自描述；破坏性变更升 major。

### 11.2 文件头（32 字节）

```c
typedef struct {
    uint32_t magic;        /* 'QLGL' = 0x4C47514C */
    uint16_t version_major;
    uint16_t version_minor;
    uint16_t header_size;  /* = 32，加载器只读这部分做兼容判断 */
    uint16_t section_count;
    uint32_t file_size;
    uint32_t crc32;        /* 0 = 未启用 */
    uint32_t type_count;
    uint32_t flags;        /* bit0: 小端  bit1: 含字体  bit2: 含图片 */
    uint32_t reserved;
} QLBinHeader;
```

### 11.3 段表项与段 tag

```c
typedef struct {
    uint32_t tag;    /* 'META' 'STRT' 'TYPE' 'PROP' 'EVNT' 'TREE' 'STYL' 'FONT' 'IMGS' */
    uint32_t offset;
    uint32_t size;
    uint32_t item_count;
} QLBinSection;
```

| tag | 内容 |
|---|---|
| `META` | 源文件路径、构建时间、qcssc 版本（可裁剪） |
| `STRT` | 字符串池：`u32 count` + `u32 offsets[]` + UTF-8 数据（去重） |
| `TYPE` | 用到的类 id 列表（与 `qltype_gen.h` 交叉校验） |
| `PROP` | 属性值扁平池：`tag(u8) + payload`，wire 编码见下 |
| `EVNT` | 事件绑定：节点索引 + 事件 id + 处理函数名（字符串池索引，绑定层解析） |
| `TREE` | 节点数组（定长，见下） |
| `STYL` | 每个节点的基础样式 + 状态覆盖表 |
| `FONT` | 字形表：bitmap 或矢量路径 |
| `IMGS` | 图片：格式字节 + w/h + 像素数据（可选 RLE） |

### 11.4 节点记录（定长 24 字节）

```c
typedef struct {
    uint32_t type_id;       /* QLType，与运行时一致 */
    uint16_t parent;        /* 0xFFFF = 根 */
    uint16_t first_child;
    uint16_t next_sibling;
    uint16_t style_index;   /* STYL 段下标 */
    uint16_t event_index;   /* EVNT 段下标，0xFFFF = 无 */
    uint16_t prop_count;
    uint32_t prop_off;      /* PROP 段字节偏移 */
    uint32_t text_off;      /* STRT 段偏移；0xFFFFFFFF = 无文本 */
} QLBinNode;
```

### 11.5 wire 值编码

```c
typedef enum {
    QL_WIRE_INT8   = 0,
    QL_WIRE_INT16  = 1,
    QL_WIRE_INT32  = 2,
    QL_WIRE_FIXED  = 3,   /* Q16.16 */
    QL_WIRE_COLOR  = 4,   /* RGB565 / RGB888 由头部 flags 决定 */
    QL_WIRE_STR    = 5,   /* u32 STRT 偏移 */
    QL_WIRE_BOOL   = 6,
} QLWireTag;
```

统一 `u8 tag` + 变长 payload（`INT8` 省 3 字节，MCU 上重要）。

### 11.6 加载器

```c
/* 计划路径: /src/html/qlbin.c */
ql_err_t ql_bin_load(const void *data, size_t size, QLObject **out_root);
```

校验顺序：`magic` → `header_size >= 32` → `version_major == QLGL_BIN_MAJOR` → `crc32`（若启用）→ `type_count` 与本地 `QL_TYPE_COUNT` 交叉验证（**不匹配直接拒绝**，避免属性错位的静默错乱）。

零拷贝原则：字符串、字体位图、图片**直接指向文件缓冲**，不复制（因此缓冲生命周期必须长于对象树，用 `ql_bin_attach()` 记录所有权）。

### 11.7 纯文本 / MCU 直读

| 模式 | 编译开关 | 体积 | 启动开销 |
|---|---|---|---|
| 纯二进制 + 运行时 loader | `QL_CFG_BINARY_LOADER=1` | 最小数据 + loader 代码 | 解析段表（≈ 微秒级） |
| 二进制转 C 数组（`emit_c`） | `QL_CFG_BINARY_LOADER=0` | 数据略大（C 语法） | 0（直接遍历数组） |
| 运行时解析 HTML/CSS | `QL_CFG_HTML_RUNTIME=1` | 需要 2~3 倍代码 | 高（不推荐在 MCU 用） |

## 12. 语言绑定 ABI

对外只暴露 C ABI，三条规则：

1. **结构体只增不改**，每个对外结构体首部带 `uint16_t struct_size`；
2. **属性/事件 id 永久稳定**（§3.2 生成器保证），名字 → id 的映射表随库发布；
3. **回调签名固定为 `void (*)(QLObject *, const QLEventArgs *)`**，参数打包（§5.2）保证可被 JS/Py 反射成数组。

```c
/* 绑定层只需要这三个入口 */
QLValue ql_object_get_property(QLObject *o, ql_property_t p);
void    ql_object_set_property(QLObject *o, ql_property_t p, QLValue v);
int     ql_connect(QLObject *o, ql_event_t e, ql_event_cb_t cb, void *user_data);
```

字符串转换只在绑定层做（`QLStr` ↔ `JSString`），核心库永不 `strdup`。

## 14. 性能预算与验证方法

目标硬件基线：120~200 MHz Cortex-M4（无 FPU 假设）+ 320×240 RGB565 单缓冲；PC 端 x86-64 作对照。

| 操作 | 预算（M4@168MHz） | 验证方式 |
|---|---|---|
| `ql_object_new` + `unref` | ≤ 1.5 µs | 循环 10 万次计时 |
| `set_property`（深 3 层） | ≤ 120 ns | 同上 |
| `ql_emit`（1 个连接，无冒泡） | ≤ 200 ns | 同上 |
| 全屏 `fill_rect` 320×240 | ≤ 4 ms | 单帧计时 |
| 100 个文本节点重绘 | ≤ 16 ms（60fps 边界） | 冻结帧计时 |
| `.text` + `.rodata`（最小配置） | ≤ 48 KB ⚠️ | `size` |

验证规则：**没有基准数据就不许在文档里写"略高于 LVGL"**——这一条建议直接写进规范的下一次修订。

## 15. 当前缺陷 → 目标实现对照表（P0）

| # | 缺陷 | 精确修复 | 验证 |
|---|---|---|---|
| 1 | 构建失败（`include/` 不存在、`src/draw` 未编译） | 见 §13 CMake 片段 | `cmake -B build && cmake --build build` |

| 9 | 继承深度无边界检查 | `QL_CFG_MAX_INHERIT_DEPTH`，注册期拒绝超深类 | 构造 9 层类断言注册失败 |

## 17. 需要你拍板的 5 个决策

1. **事件参数上限**：定为 4 个（本文默认）还是 8 个？影响每对象内存与绑定复杂度。
2. **`float` 是否允许出现在属性值里**：本文统一 `Q16.16` 定点；若目标板有 FPU 可放宽（但会破坏 32/64 位一致性）。
3. **字体格式**：只做位图（体积小、无依赖）还是同时支持矢量路径（美观、CPU 高）？
4. **`QL_CFG_*` 的默认目标**：默认面向 MPU（功能全开）还是 MCU（最省）？影响第一次基准的基线。
5. **是否接受"不支持项构建期报错"**：这会限制 `qcssc` 的宽容度，但能避免静默错位。

## 附录 B：P0 落地后与 v0.1 设计的差异

对象系统已经按本文实现并全部通过测试，落地过程中有 8 处与上文草案不同，后续以本附录为准：

| # | 上文草案 | 实际实现 | 原因 |
|---|---|---|---|
| 1 | §5.2 `QL_EMIT_2(obj, ev, t1, a1, t2, a2)` 用类型 token | 改为"参数构造器 + 显式个数"：`QL_EMIT_2(obj, ev, ql_args_int, 1, ql_args_string, "hi")` | 类型 token 无法表达复合类型，且 0 参数与奇数参数时 token 计数必错 |
| 2 | §4.2 `void ql_object_set_property` | `ql_err_t ql_object_set_property` | 调用方需要知道"id 越界/类型不符/无人处理"，返回 void 只能靠日志 |
| 3 | §2.4 只有 `ql_object_set_parent` | 增加 `ql_object_add_child(parent, child)` | 父对象持有子引用，调用方还要自己 unref 一次，极易漏；便捷函数把两步合一 |
| 4 | §4.1 `*_PROPERTY_START` 即第一个属性 | `START`/`END` 是区间哨兵，第一个自定义属性是 `START + 1` | 枚举首项带显式初值后，后续项必然 +1；保留哨兵让"零属性类"也能占位 |
| 5 | §3.2 生成文件只有 `src/generated/qlclass_gen.c` | 同时生成 `include/qlgl/qltype_gen.h`（公开 id 枚举） | id 是公开契约，使用者需要 `QL_TYPE_LABEL` 这类常量 |
| 6 | §3.2 `ql_class_register(k, parent)` 只用于内置类 | 内置类由生成表注册，公开 API 同时支持动态注册（id 从 `QL_TYPE_COUNT` 起） | 测试与插件需要在不改源码的前提下定义类 |
| 7 | §5.5 默认处理未明确范围 | 默认处理**只在事件目标节点**、且事件带 `QL_EVENT_FLAG_DEFAULT` 时调用 | 否则一次冒泡会在每个祖先节点都跑默认逻辑 |
| 8 | 日志文本未约定语言 | 日志**一律英文**，注释与文档中文 | 便于 grep 与不同终端/环境的编码兼容 |

另外两处实现细节，写在这里避免再次踩坑：

- `QL_DECLARE` / `QL_DEFINE_WITH_PRIVATE` **自带分号**，调用处不要加分号；
- 宏参数 `name` 会替换掉结构体字段 `.name` 这个 token，所以宏里用 `QL_CLASS_FIELD_NAME` 间接展开。

## 附录 D：Linux 窗口后端（v0.1）

`src/port/qldisp_x11.c` 实现了第一个真实平台后端，与 §7 草案的差异：

| # | 草案 | 实际实现 | 原因 |
|---|---|---|---|
| 1 | 抽象"平台层 `qldisp.h`" | 平台后端放在 `src/port/`，接口在 `include/qlgl/qldisp_x11.h`，由 CMake 的 `QLGL_BUILD_X11` 控制 | 后端可能依赖第三方头文件，不能污染主头文件 |
| 2 | 未约定帧缓冲归属 | X11 后端让 **XImage 的 `data` 指向渲染器帧缓冲** | 绘制与上屏零拷贝；销毁时必须先把 `image->data` 置 NULL 再 `XDestroyImage` |

### 落地时发现并对对象系统做的修正

派生类的私有区只算自己那一份（3 层继承时 `priv_total` 不再翻倍），
导致 `self = mem + priv_total` 落在 4 字节边界上 —— UBSan 报
`member access within misaligned address for type 'struct QLObject'`。

修正：`ql_class_register` 把每层的 `own_private_size` **向上对齐到 `_Alignof(max_align_t)`**，
再累加成 `priv_total`。`test_object_inherit.c` 现在对实例与各层私有区都做了对齐断言。

| # | 话题 | 实现 | 原因 |
|---|---|---|---|
| 1 | 协议来源 | `src/port/protocols/xdg-shell.xml` 随仓库提供，构建期用 `wayland-scanner` 生成 | 系统可能没装 wayland-protocols，但 `wayland-scanner` 通常随 wayland 一起装 |
