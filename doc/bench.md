# 性能基线（bench.md）

> 规则：**没有数字的优化不算优化**。每次改动后重跑本文命令，超标即视为回归。
> 机器：Linux / Mesa / x86-64；会话 Wayland（GL 走 XWayland）。

## 复现命令

```bash
cmake -B build && cmake --build build -j
./build/example_bench_fps 300          # 多分辨率 × GL/CPU
./build/example_gl_window --bench 600  # 窗口无 vsync 上限
./build/example_gl_window --frames 180 # 窗口 vsync 模式
```

## 单帧开销（450 顶点，1 draw call）

| 分辨率 | GL CPU 提交 | GL 含 GPU 完成 | CPU 光栅（优化前） | CPU 光栅（现在） | 提速 |
|---|---|---|---|---|---|
| 320×240 | 0.023 ms | 0.112 ms | 3.68 ms | **0.196 ms** | 18.8× |
| 800×480 | 0.024 ms | 0.196 ms | 11.7 ms | **0.487 ms** | 24.0× |
| 1280×720 | 0.029 ms | 0.338 ms | 23.1 ms | **0.939 ms** | 24.6× |
| 1920×1080 | 0.027 ms | 0.491 ms | 44.4 ms | **1.951 ms** | 22.8× |

> 2026-11-07 优化（M4-G1）：CPU 光栅改为"一次算裁剪 → 按行逐格式写入"，
> 去掉每像素的函数调用/裁剪比较/格式 switch；RGB888 用 4 像素 3 次 32 位写；
> 圆角/描边按行求跨度；字形按行取位图。

## 关于 MCU

上表全部是 x86-64（AVX2/SSE4.2、DDR）实测。**不能直接外推到 Cortex-M**：

- 纯填充是 cache/内存带宽密集，M4 @180MHz 的 SRAM 写带宽约是桌面 DDR 的 1/50~1/100；
- M7 上叠了 ATCM/DTCM 与 ART 加速器，实际比 M4 快 3~5 倍；
- 一致的部分是**算法复杂度**：行跨度扫描 + 格式特化仍然是 MCU 上的正确做法，
  但绝对数值必须单独实测。M6 里程碑会在真板子上跑同一份 `example_bench_fps`。
