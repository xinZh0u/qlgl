# benchmark 命令行未知参数和缺失值被静默忽略

> **核对 2026-11-15**：✅ 已修 —— `benchmark/bench_common.h:149-164` 缺值/未知参数 → usage + `exit(2)`

## 问题

`bench_opts_parse()` 对每个选项的分支都要求参数存在；若参数缺失，条件不成立后循环会直接进入下一项。对于完全未知的参数也没有错误分支，因此两者都会被静默忽略。

例如 `--seconds` 会按默认 3 秒运行，`--seocnds 0.1` 也会以默认时长运行，而非提示拼写错误。

## 影响

benchmark 可能在错误的时长、尺寸、场景或后端配置下运行，最终报告仍看起来正常，导致性能结果与操作者输入不一致。

## 依据

- `benchmark/bench_common.h` 的 `bench_opts_parse()` 仅处理已匹配且有后续值的条件。
- 循环没有最终 `else` 用于拒绝未知参数，也没有检测已知选项缺少参数的分支。

## 验证状态

静态追踪确认未匹配参数不会报错或改变退出状态；未执行专门的 CLI 错误测试。
