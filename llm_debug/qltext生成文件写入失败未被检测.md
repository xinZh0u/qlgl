# qltext 生成文件写入失败未被检测

## 问题

`qltext cc` 通过 `open_out()` 创建生成文件后，多个写出函数连续调用 `fprintf()`，并在结尾直接 `fclose()`；既不检查写调用返回值，也不检查 `fclose()` 的结果。文件创建成功后若磁盘空间耗尽、配额不足或发生 I/O 错误，工具仍可能打印成功并返回 0，但生成的 `.c`、`.h` 或 `_blob.c` 文件不完整。

## 影响

构建期工具把生成失败伪装成成功，后续编译才以不明确的语法/截断错误失败；若只依赖工具退出码判断生成成功，则会留下损坏产物。

## 依据

- `tools/qltext/qltext.c` 的 `open_out()` 只检查 `fopen()`。
- `write_source()`、`write_header()`、`write_blob_helper()` 的输出调用没有检查写入状态，结束时直接 `fclose(f)`。
- `main()` 在这些写函数返回后无条件打印生成成功信息。

## 验证状态

静态追踪确认输出错误未传播；未通过受限磁盘或故障注入进行动态复现。
