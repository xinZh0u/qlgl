# CPU 图层合成 RGBA 分配失败时内容被静默丢弃

> **核对 2026-11-15**：🟡 部分修复（已确认可观测）—— `src/draw/qldraw2d.c:1201-1210` 现在明确 `QL_LOGE`，但两遍哑光已画完时没有可回退的原画布内容，图层仍会整块消失。彻底修需要条带合成（blur 的垂直半径跨条带，改动大），暂列为已知降级

## 问题

CPU 图层第二遍绘制结束后，`cpu_layer_end()` 需要为重建后的 RGBA 图层分配 `w*h*4` 字节缓冲区。若 `ql_mem_alloc()` 失败，函数跳过重建、滤镜和合成，却仍释放两块 matte 缓冲并结束图层；该图层的内容因此完全不绘制，也没有向调用方报告失败或触发普通绘制回退。

## 影响

在内存紧张或图层较大时，带滤镜、变换、遮罩、混合模式或组透明度的节点可能整块消失；调用方无法区分成功合成与分配失败。

## 依据

- `src/draw/qldraw2d.c` 的 `cpu_layer_end()` 在 `rgba == NULL` 时不进入合成分支，但无条件释放 matte 并结束图层。
- 图层缓冲分配成功并完成两遍绘制后才会发生该分配失败，此时已没有保留的普通画布内容可供直接回退。

## 验证状态

静态检查确认该失败路径；本次未注入分配失败进行动态复现。现有 `test_effects` 未覆盖图层 RGBA 分配失败。
