# 字体家族字号缓存节点分配失败时字体泄漏

## 问题

`ql_font_family_font()` 成功创建动态字体后，尝试分配 `QLFTCache` 节点以登记其所有权。如果节点分配失败，函数仍返回该字体，但没有把它加入任何可由 `ql_font_family_reset()` 释放的列表。

此 API 返回的是注册表缓存字体（头文件说明按字号缓存），调用方没有被告知需自行销毁返回值；因此该分配失败路径会留下无法回收的字体、FreeType face 和字体数据，之后再次取相同字号还会重新加载一份。

## 影响

内存压力下缓存节点分配失败会造成动态字体资源泄漏，并在重复请求时不断加载未登记的字体。

## 依据

- `src/text/qlfont_ft.c` 的 `ql_font_family_font()` 在 `font` 非空后分配缓存节点。
- 当 `ql_mem_calloc()` 返回 `NULL` 时，代码仍直接返回 `font`，未销毁字体或登记到其他所有权结构中。
- `include/qlgl/qlfont_ft.h` 将该接口描述为内部按字号缓存的字体，并未要求调用方释放。

## 验证状态

静态追踪确认缓存节点分配失败路径未释放也未登记字体；本次未通过分配器故障注入复现。
