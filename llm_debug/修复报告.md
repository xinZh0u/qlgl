# 修复报告：安装后的两条消费路径

> 对应本目录下两份问题报告。两个问题都已**独立复现 → 修复 → 端到端验证**。
> 报告里的复现命令原样跑过，确认修复前失败、修复后通过。

---

## 摘要

| # | 问题 | 根因 | 修法 | 状态 |
|---|---|---|---|---|
| 1 | `find_package(qlgl)` 找不到头文件 | `include(GNUInstallDirs)` 晚于 `target_include_directories`，`$<INSTALL_INTERFACE:${CMAKE_INSTALL_INCLUDEDIR}>` 展开成空串 | `include(GNUInstallDirs)` 提到 `project()` 之后；加"展开为空就 FATAL_ERROR"守卫 | ✅ 已修 |
| 2 | pkg-config 消费者缺能力宏 | `qlgl.pc` 的 `Cflags` 只有 `-I`，没带 `target_compile_definitions(PUBLIC)` 的宏 | 生成 `.pc` 时从 `INTERFACE_COMPILE_DEFINITIONS` 读取写入 `Cflags`（与 CMake 导出口同源）；并把 `QL_FEAT_IMG_*` 并入 target 接口 | ✅ 已修 |

**一处认知修正**：仓库原注释写"能力开关**不随包导出**"——这句是错的，而且正是问题 2 的源头。
实际是：

- CMake 路径**一直**在导出（`INTERFACE_COMPILE_DEFINITIONS`）→ 只踩问题 1（include 目录丢失）；
- pkg-config 路径**从来没导出** → 只踩问题 2（`#error`）。

"两条路各坏一半"正是这么来的。现在两条路都从**同一个 target 属性**取值。

## 问题 1：安装包丢失 `INTERFACE_INCLUDE_DIRECTORIES`

### 复现（修复前）

```bash
rm -rf /tmp/qb /tmp/qprefix
cmake -S . -B /tmp/qb -DCMAKE_BUILD_TYPE=Release -DCMAKE_INSTALL_PREFIX=/tmp/qprefix \
      -DQLGL_BUILD_TESTS=OFF -DQLGL_BUILD_EXAMPLES=OFF -DQLGL_BUILD_BENCHMARK=OFF
cmake --build /tmp/qb -j && cmake --install /tmp/qb
grep INTERFACE_INCLUDE_DIRECTORIES /tmp/qprefix/lib/cmake/qlgl/qlglTargets.cmake
```

修复前输出（**没有** `${_IMPORT_PREFIX}/include`）：

```
INTERFACE_INCLUDE_DIRECTORIES "/usr/include;/usr/include/freetype2"
```

消费者按报告步骤编译：`fatal error: qlgl/qlgl.h: 没有那个文件或目录`。

### 为什么这个 bug 会"自己藏起来"（报告未提到，但很关键）

`include(GNUInstallDirs)` 用 `set(... CACHE PATH ...)` 写缓存。**同一个 build 目录**
第二次 configure 时，`CMAKE_INSTALL_INCLUDEDIR` 已从缓存读到 `include`，第 22 行的
展开就正常了。

→ 只有**全新配置**才复现。这解释了为什么之前用存量 build 目录安装出的 SDK 是好的，
而报告用全新目录能稳定复现（**双方都没错，是时序问题**）。也正因如此，这个坑在
本仓内部构建里永远看不到。

### 修法

```cmake
project(qlgl LANGUAGES C VERSION 0.1.0)

# 必须在 add_library / target_include_directories 之前：
# 那里的 $<INSTALL_INTERFACE:${CMAKE_INSTALL_INCLUDEDIR}> 是配置期字符串展开。
include(GNUInstallDirs)
```

并删掉原来第 518 行那句（重复 include 无害，但会误导后人以为"晚点 include 也行"）。

**额外加守卫**，防止以后有人把顺序改回去：

```cmake
if(NOT CMAKE_INSTALL_INCLUDEDIR)
    message(FATAL_ERROR "QLGL: CMAKE_INSTALL_INCLUDEDIR 为空 —— "
                        "include(GNUInstallDirs) 必须在本行之前")
endif()
```

在 **configure 期**就失败，而不是等别人的工程编译才发现。

### 验证（修复后，同样全新目录）

```
INTERFACE_INCLUDE_DIRECTORIES "${_IMPORT_PREFIX}/include;/usr/include;/usr/include/freetype2"
```

消费者工程（完全按报告给的 CMakeLists）：

```bash
cmake -S . -B build -DCMAKE_PREFIX_PATH=/tmp/qprefix
cmake --build build && ./build/hello
# → QLUIStyle=420 QLUIDoc=264 blobv=38
```

不加任何 `-I`、不加 `CMAKE_C_FLAGS`。

## 问题 2：`qlgl.pc` 的 `Cflags` 不含能力宏

### 复现（修复前）

```
$ pkg-config --cflags qlgl
-I/tmp/qprefix/include                     ← 一个 -D 都没有

$ gcc -std=c11 $(pkg-config --cflags qlgl) main.c $(pkg-config --libs qlgl)
include/qlgl/qlfont_ft.h:26:2: error: #error "QL_FEAT_CSS_FONT_STACK=1 需要 QLGL_ENABLE_FREETYPE=1"
```

### 修法（采用报告建议的方案 1，未做方案 2）

**① 单一来源**：图像能力宏原来只走本仓全局 `add_compile_definitions`，现在同时挂到
target 接口上，使 `INTERFACE_COMPILE_DEFINITIONS` 包含**全部**开关：

```cmake
set(QL_IMG_DEFS
    QL_FEAT_IMG_BMP=${QL_FEAT_IMG_BMP}
    QL_FEAT_IMG_QOI=${QL_FEAT_IMG_QOI}
    QL_FEAT_IMG_PNG=${QL_FEAT_IMG_PNG}
    QL_FEAT_IMG_GIF=${QL_FEAT_IMG_GIF}
    QL_FEAT_IMG_PLATFORM=${QL_FEAT_IMG_PLATFORM})
add_compile_definitions(${QL_IMG_DEFS})                 # 本仓所有目标
target_compile_definitions(qlgl PUBLIC ${QL_IMG_DEFS})  # 消费方 + 导出口
```

**② `.pc` 从 target 属性生成，不重抄**：

```cmake
get_target_property(_ql_pc_iface_defs qlgl INTERFACE_COMPILE_DEFINITIONS)
foreach(_d IN LISTS _ql_pc_iface_defs)
    string(APPEND QL_PC_DEFS " -D${_d}")
endforeach()
...
Cflags: -I${includedir}${QL_PC_DEFS}
```

以后**新增任何开关都不用改两处**，两条消费路径不可能漂移。

**为什么不做方案 2（把 `#error` 改软）**：方案 1 已让"库关 FreeType"这一侧正确导出
`QL_FEAT_CSS_FONT_STACK=0`（见下方反向验证）。把守卫改软会削弱"不静默降级"红线——
真正的错误配置（库没编文本栈、消费者却按有来写）应**立刻报错**而不是 warning。
报告提到的"报错信息对消费者不友好"，现在通过导出宏直接消解。

### 验证

修复后：

```
-I/tmp/qprefix/include -DQL_FEAT_IMG_BMP=1 -DQL_FEAT_IMG_QOI=1 -DQL_FEAT_IMG_PNG=1 \
-DQL_FEAT_IMG_GIF=1 -DQL_FEAT_IMG_PLATFORM=1 -DQL_FEAT_IMG_LIBJPEG=1 \
-DQLGL_ENABLE_FREETYPE=1 -DQLGL_ENABLE_GL=1 -DQLGL_ENABLE_WAYLAND=1 \
-DQLGL_HAVE_WAYLAND_EGL=1 -DQLGL_ENABLE_X11=1
```

与 `qlglTargets.cmake` 的 `INTERFACE_COMPILE_DEFINITIONS` **逐项相同**。

**反向组合也验了**（报告提到的"库关 FreeType"）：

```bash
cmake -S . -B /tmp/qb2 ... -DQLGL_BUILD_FREETYPE=OFF -DQLGL_BUILD_JPEG=OFF
cmake --build /tmp/qb2 -j && cmake --install /tmp/qb2
grep Cflags /tmp/qp2/lib/pkgconfig/qlgl.pc
# → ... -DQL_FEAT_IMG_LIBJPEG=0 -DQL_FEAT_CSS_FONT_STACK=0 ...
gcc -std=c11 $(pkg-config --cflags qlgl) main.c $(pkg-config --libs qlgl) -o x && ./x
# → QLUIStyle=420 QLUIDoc=264 blobv=38   不再 #error
```

## 端到端验证矩阵

| 场景 | find_package | pkg-config |
|---|---|---|
| 全新 configure → 安装 → 消费方编译 | ✅ | ✅ |
| 结构体尺寸一致（ABI 校验） | ✅ `QLUIStyle=420 QLUIDoc=264` | ✅ 同左 |
| 带 FreeType 构建 | ✅ | ✅ |
| 不带 FreeType 构建 | ✅ | ✅（导出 `QL_FEAT_CSS_FONT_STACK=0`） |
| 真实程序渲染 | ✅ | ✅ |

**真实程序交叉比对**（`test/helloworld`，同一个 `main.c`）：

```bash
# A. find_package 构建
cd test/helloworld
cmake -S . -B build_v -DCMAKE_PREFIX_PATH=/tmp/qprefix
cmake --build build_v && ./build_v/helloworld --dump /tmp/hw_cm.ppm

# B. pkg-config 构建（手工一行）
gcc -std=c11 -O2 -D_POSIX_C_SOURCE=200809L -DQL_HELLO_DIR=... \
    $(pkg-config --cflags qlgl) main.c $(pkg-config --libs qlgl) -o hw_pc
./hw_pc --dump /tmp/hw_pc.ppm

cmp /tmp/hw_pc.ppm /tmp/hw_cm.ppm      # → 逐字节相同
```

两路径产出的帧**逐字节一致**，说明布局 / 解析 / 绘制全一致（ABI 未错位）。
